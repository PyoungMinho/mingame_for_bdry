## 0. 한 장 요약

1. **시각 언어 = "어느 회사 PC에나 있는 회색 크롬 + 흰 격자 + 잉크 파랑 한 가지".** 강조색은 `#2F5E8E` 하나. 녹색 계열은 어떤 용도로도 쓰지 않는다(경고 삼각형·체크·성공 표시 포함).
2. **움직임 0, 그림자 거의 0, 모서리 0~4px, 손 모양 커서 없음.** 시트 앱은 눌러도 아무것도 번쩍이지 않고 커서도 화살표다. 이 둘이 "게임 앱스러움"을 가장 크게 지운다.
3. **글꼴은 OS 기본 UI 글꼴을 이름으로 지정**(맥 SF + Apple SD Gothic Neo / 윈도우 Segoe UI + 맑은 고딕). 웹폰트 0개, 루트가 불러오는 Pretendard는 쓰지 않는다.
4. **다크 모드는 만들지 않는다**(`color-scheme: light` 고정). 이유는 §1-6.
5. **셀 상태 7종은 색 + 글자 + 모양으로 이중 인코딩**: 빗나감 `0`, 명중 `1`, 침몰 = 짧은 이름 + 안쪽 테두리 + 모서리 삼각형, 내 배 = 짧은 이름 + 노랑. 흑백으로 인쇄해도 읽힌다.
6. **게임 레이어와 숨기기 레이어는 같은 셸 안에서 격자 영역만 바뀐다.** 상단바~수식 입력줄, 시트 탭, 상태줄은 1px도 움직이지 않는다(§3-4 불변 표).
7. **공유 파일에서 새는 스타일 6가지**는 `.mc-root` 범위 안에서 덮어쓴다(§6). 가장 위험한 것은 Tab을 누르면 켜지는 주황 포커스 링이다.
8. 이 문서와 방향서가 다르면 방향서가 우선이다. UI가 스스로 바꾼 점은 §11에 모았다.

## 1. 디자인 토큰

### 1-1. 범위 이름 (프론트와 맞출 것)

방향서에 `.mc-root`(§8-2)와 `.mc-shell`(§5, 프론트 검토)이 둘 다 나온다. UI는 **두 층으로 정리**했다. [요청: 프론트팀장 확인, §12 Q3]

| 클래스 | 붙는 곳 | 역할 |
|---|---|---|
| `.mc-root` | `layout.tsx`의 최상위 래퍼 (홈·연습·방 모두) | 토큰 정의, 누수 덮어쓰기(§6), 글꼴·색·커서·스크롤바 |
| `.mc-shell` | 시트 셸(연습·방) 컴포넌트 | 레이아웃 치수, `data-view="game|disguise"`, 분할 창 |
| 접두사 | 모든 클래스·변수 | `mc-` / `--mc-` 만 쓴다. 루트가 쓰는 `mf-`, `moira-` 와 겹치지 않는다 [확인: globals.css] |

### 1-3. 글꼴·글자 크기

```css
--mc-font: -apple-system, BlinkMacSystemFont, "Segoe UI", "Malgun Gothic", "맑은 고딕",
           "Apple SD Gothic Neo", "Noto Sans KR", "Noto Sans CJK KR", system-ui, sans-serif;
```
- 라틴·숫자는 각 OS의 UI 글꼴(맥 SF, 윈도우 Segoe UI), 한글은 맑은 고딕 / Apple SD Gothic Neo가 맡는다. Office 전용 글꼴(Calibri·Aptos·Cambria)과 웹폰트는 지정하지 않는다. [결정]
- 숫자는 항상 `font-variant-numeric: tabular-nums`(루트 body가 이미 켜 두었지만 `.mc-root`에서 다시 지정).
- **굵기는 400과 600 두 가지만.** 윈도우 맑은 고딕은 600을 700으로 렌더하므로 굵게 쓰는 곳을 최소화한다(머리 행, 합계 행, 제목, 선택된 탭).
- 글자색 `--mc-text`, 안티앨리어싱은 OS 기본(`auto`)으로 되돌린다(루트 `antialiased`가 가늘게 만든다, §6 #5).

### 1-4. 치수 (셸 고정 높이 합 232px)

| 토큰 | 값 | 비고 |

| `--mc-menubar-h` | 28px | 텍스트 메뉴줄(장식) |
| `--mc-toolbar-h` | 36px | 한 줄 아이콘 도구줄 |
| `--mc-formula-h` | 28px | 이름 상자 + 수식 입력줄 |
| `--mc-pane-head-h` | 24px | 창 머리 띠 (§3-3) |
| `--mc-colhead-h` | 24px | 열 머리글 |
| `--mc-rowhead-w` | 40px | 행 머리글 (두 자리 행 번호 12px 기준) |
| `--mc-cell-w` | 64px (>=1200) / 56px (1024~1199) | 격자선 1px 포함 (box-sizing: border-box) |
| `--mc-cell-h` | 24px | 격자선 1px 포함, 글자 줄 높이 22px |
| `--mc-split-w` | 5px | 분할 창 경계 |
| `--mc-tabbar-h` | 28px | 시트 탭 |
| `--mc-statusbar-h` | 24px | 상태줄 |

- 위 높이 합(40+28+36+28+24+24+28+24) = **232px**. 창 안쪽 높이 640px이면 격자는 408px = 17행, 600px이면 15행, 방향서가 요구한 "1~14행이 스크롤 없이 보임"은 **높이 570px 이상**에서 충족된다.
- `@media (max-height: 599px)`이면 메뉴줄(28px)을 접어 격자 행을 되찾는다(진짜 시트 앱의 "메뉴 숨기기"와 같은 동작이라 어색하지 않음).
- 창 너비별 분할: `(1280-5)/2 = 637px` → 행 머리글 40 + 열 9개(576) = 616px로 A~I열이 보이고 J열이 21px 걸친다. 1024px에서는 `(1024-5)/2 = 509px` ≥ 40 + 8x56 = 488px로 A~H가 온전히 보인다.
- **칸 폭과 한글 글자 수**(13px 한글 약 13px, 숫자 약 7.5px, 좌우 여백 4px씩): 문구 검사 테스트의 기준 [결정]

| 열 폭 | 한글 최대 | 쓰는 곳 |
|---|---|---|
| 56px | 3자 | 판 셀 짧은 이름 (1024~1199 화면) |
| 64px | 4자 (안전선 3자) | 판 셀 짧은 이름 (문구 상한 2~3자는 이 안전선 기준) |
| 병합 3칸 192px (56px 칸이면 168px) | 12자 (11자) | 항목 표 이름 상한 8자는 여유 있게 들어감 |
| 병합 4칸 | 16자 이상 | 검산 표 라벨 상한 24자는 **병합 5칸(320px) 이상** 필요 → 오른쪽 창 10~14행 검산 표는 라벨 칸을 5칸 병합 [요청: UX 와이어프레임에 반영] |
| 숨기기 시트 열 | 아래 §4 표 | 열별 최대 글자 수 |

### 1-5. 간격·테두리·그림자·층

- **간격 단위 4px**: `--mc-s-0: 2px; --mc-s-1: 4px; --mc-s-2: 8px; --mc-s-3: 12px; --mc-s-4: 16px; --mc-s-6: 24px`. 셀 안 좌우 여백 4px(숫자 칸은 오른쪽 6px).
- 테두리 1px 실선만. 두께 2px는 **선택 셀 테두리**와 **입력 포커스**에만 쓴다. 이중선(`3px double`)은 숨기기 시트 합계 행 아래에만.
- 모서리: 셀·머리글·탭 위쪽 0, 버튼·입력·팝오버·대화상자·토스트·메모 4px(`--mc-r: 4px`), 단축키 칩 3px, 편집자 원 50%.
- 그림자: 메모 `0 2px 6px rgba(0,0,0,.12)` · 팝오버 `0 4px 12px rgba(0,0,0,.14)` · 대화상자 `0 8px 24px rgba(0,0,0,.20)` · 토스트 `0 2px 8px rgba(0,0,0,.24)`. **그 외 그림자 금지.** 또한 포커스를 받는 요소에는 `box-shadow`로 상태를 표현하지 않는다(전역 포커스 규칙이 덮어쓸 수 있음, §6 #1).
- 층(z-index): 격자 0 · 고정 머리글 3 · 선택 테두리·범위 오버레이 4 · 분할 경계 5 · 메모 30 · 팝오버·드롭다운 40 · 토스트 50 · 화면 덮개 60 · 대화상자 61. **모두 `.mc-shell` 안 DOM이며 `body` 포털은 쓰지 않는다**(방향서 §8-2 #11).

### 1-6. 다크 모드를 만들지 않는다 [결정]

- 실제 회사 PC의 스프레드시트는 거의 전부 흰 격자다. 다크 격자는 눈에 띄는 쪽이다. 위장이 제품 약속이므로 다크가 오히려 "이상한 화면"이다.
- `.mc-root { color-scheme: light }` + `viewport.colorScheme = 'light'`로 브라우저·OS 다크 설정에서 입력칸·스크롤바가 어두워지는 것을 막는다. 안드로이드 Chrome "강제 다크"는 `<meta name="color-scheme" content="light">`로 끈다.
- 비용: 야간에 집에서 하는 사용자에게는 밝다. 감수한다(베타 단계, 지표로 불만이 나오면 P1 재검토).
- 토큰을 `--mc-*` 변수로만 쓰므로 나중에 다크를 넣어야 하면 `.mc-root[data-theme="dark"]`로 값만 바꾸면 된다.

### 1-7. 움직임·커서·선택

- `.mc-root *, ::before, ::after { transition: none !important; animation: none !important; scroll-behavior: auto !important; }` 등장·퇴장·hover 모두 즉시. 데이터 막대·막대 차트도 정적.
- **커서**: 셀 격자 위 선택 가능 영역 `cell`(흰 십자, 시트 앱 관례), 입력칸 `text`, 그 외 모든 곳 `default`. **손 모양(`pointer`) 금지**. 힌트 범위 고르기 중 열 머리글 `s-resize`, 행 머리글 `e-resize`.
- `user-select: none`은 크롬·격자·머리글에, 입력칸·결과 문서 본문·메모 본문은 `text`(복사 가능). 모바일은 `-webkit-touch-callout: none; touch-action: manipulation; -webkit-tap-highlight-color: transparent`(두 번 탭이 확대로 해석되지 않게).

### 2-4. 분할 창

```
┌ 창 머리 띠 24px ─────────┬┬ 창 머리 띠 24px ────────┐
│ 열 머리글 24px            ││ 열 머리글 24px           │
│ [40][A][B]…               ││ [40][A][B]…              │
│ 행·격자 (세로 스크롤)       ││ 행·격자                   │
└──────────────────────────┴┴─────────────────────────┘
                       경계 5px
```
- 경계 5px: 바탕 `--mc-grid`, 좌우 1px `--mc-line`. 시트 앱의 "창 나누기" 막대와 같은 모양. 드래그 불가이므로 커서는 `default`.
- 두 창은 같은 폭(50%)이며 각자 세로·가로 스크롤을 가진다. 세로 스크롤은 항상 표시(`overflow: scroll`)해서 레이어가 바뀌어도 스크롤바 폭이 변하지 않게 한다(§3-4).
- 판 바깥 빈 셀은 DOM이 아니라 배경으로 그린다:

```css
.mc-grid-bg {
  background-color: var(--mc-bg);
  background-image:
    linear-gradient(to left,   var(--mc-grid) 1px, transparent 1px),
    linear-gradient(to top,    var(--mc-grid) 1px, transparent 1px);
  background-size: var(--mc-cell-w) var(--mc-cell-h);   /* 정수 px일 것 */
}
```
  선을 타일의 오른쪽·아래에 두므로 실제 셀(오른쪽·아래 1px 테두리, border-box)과 어긋나지 않는다. `--mc-cell-w/h`는 정수여야 한다(소수 px는 선이 흐려짐).

### 2-5. 선택·편집 규칙의 시각

- 선택 셀 = 2px 테두리(위 표). 편집(검산 칸, 이름 상자)은 같은 2px 테두리 안에 흰 바탕 입력.
- 쏘기 대기(선택됨, Enter 전)는 선택과 같다. Enter 후 서버 대기("계산 중...")는 선택 테두리를 `--mc-select-ro`로 바꾸고 그 사이 클릭을 막는다.
- 읽기 전용 창에서도 방향키 이동은 되므로(탐색) 테두리가 움직인다. 색만 회색이다.

## 3. 레이어 구조와 전환

### 3-1. DOM 구조

```
.mc-root                     토큰·누수 덮어쓰기 (홈은 여기까지만)
 └ .mc-shell[data-view]      치수·레이아웃
    ├ .mc-topbar / .mc-menubar / .mc-toolbar / .mc-formula        (불변 크롬)
    ├ .mc-body                                                    (격자 영역, flex:1, min-height:0, overflow:hidden)
    │   ├ .mc-layer.mc-layer--game       게임 레이어: 분할 창 2개 + 오버레이(메모·토스트·검산·대화상자)
    │   └ .mc-layer.mc-layer--disguise   숨기기 레이어: 창 1개 + 차트
    ├ .mc-tabs                                                    (불변 크롬)
    └ .mc-status                                                  (불변 크롬)
```
```css
.mc-shell[data-view="game"]     .mc-layer--disguise { display: none; }
.mc-shell[data-view="disguise"] .mc-layer--game     { display: none; }
```
`display: none` 외 방법(투명도, 좌표 이동, `visibility`)을 쓰지 않는다. 두 레이어 모두 미리 마운트하고, 속성 하나만 바꾼다.

### 3-2. 두 레이어는 같은 틀에 들어간다

- `.mc-body`의 크기는 레이어와 무관하게 `flex: 1`로 고정된다. 레이어를 바꿔도 부모 박스는 한 번도 리플로우되지 않는다.
- 두 레이어 모두 `position: absolute; inset: 0;`. 각 창은 `overflow: scroll`로 **스크롤바 공간이 항상 있다**(윈도우 12px). 맥 오버레이 스크롤바는 원래 공간을 차지하지 않는다.
- 헤더 행(열 머리글)과 행 머리글은 두 레이어에서 같은 위치(좌표 x=0, y=0 기준 40px / 24px)에서 시작한다.

### 3-3. 창 머리 띠 24px — 두 레이어에서 모두 존재 [결정]

- 게임 레이어: 창마다 "내 시트 · B님이 검토 중" / "상대 시트 · 편집 가능" (12px `--mc-text-sub`, 왼쪽 정렬 여백 8px, 바탕 `--mc-chrome`, 아래 1px `--mc-line`).
- 숨기기 레이어: **같은 24px 띠를 "필터 줄"로 쓴다.** 바탕·글자 같음. 안에 왼쪽부터 "보기: 기본" "필터: 없음" "단위: 천원"(업종별 단위) 같은 업무 정보 12px (웃음 문구 0). 이렇게 하면 레이어를 바꿔도 아래 격자의 y 좌표가 바뀌지 않는다.
- 게임 레이어 띠 글자는 "게임 용어 없음 + 웃음 등급 0"(방향서 §3-1). 그 문구는 UX 담당.

### 3-4. 전환해도 변하면 안 되는 것 (불변 표)

| 항목 | 상태 |
|---|---|
| 상단바(파일명·편집자 원·공유), 메뉴줄, 도구줄 | 위치·크기·색 **불변** (기능 버튼 비활성 모양만 §2-1 규칙) |
| 이름 상자·수식 입력줄 | 위치 불변, **내용만 교체**(숨기기 레이어의 선택 셀 주소·수식) |
| 열·행 머리글 줄 | 높이·폭·색 불변. 열 문자는 게임 레이어 A~I(균일 폭) -> 숨기기 레이어 A~J(열별 폭, §4) |
| 시트 탭 줄 | **불변.** 활성 탭만 이동 |
| 상태줄 | 위치 불변, 문장만 교체("준비") |
| 탭 제목·파비콘 | 불변 |
| 창 수 | 게임 2개 -> 숨기기 1개 (판 영역이 바뀌는 곳이므로 허용. 경계 막대가 사라지고 고정선이 나타나는 것은 "창 나누기 해제 + 틀 고정"처럼 자연스러움) |
| 사라져야 하는 것 | 메모·토스트·드롭다운·공유 패널·검산 입력·대화상자 (게임 레이어에 있으므로 자동) |

### 3-5. 속도 보장을 위한 CSS 지침 [요청 아님, 프론트 참고]

- 레이어 전환 시 레이아웃을 새로 계산하지 않도록 `contain: layout paint;`를 `.mc-layer`에 건다.
- 숨기기 레이어의 위장 숫자는 마운트 때 한 번만 만든다(방향서 §4-7).
- 큰 이미지·SVG 필터·`backdrop-filter`·`box-shadow` 블러를 격자 영역에 쓰지 않는다. 메모 그림자가 유일한 예외.

- 위치: 19~29행(11행 x 24 = 264px), B열 왼쪽 끝에서 시작, 폭 400px(창이 좁으면 320px). 모서리 0, 1px `--mc-line`, 바탕 `--mc-bg`. 시트 위에 떠 있는 개체라 약간의 그림자도 쓰지 않는다.

| 업종 | 보이는 4열 | 열 폭 |

### 4-7. 게임 화면과 같은 팔레트를 쓰는 이유

숨기기 시트에서 `--mc-cf-warn` 노랑, `--mc-cf-bad` 연빨강, `--mc-cf-good` 연파랑이 쓰이므로, 전환 순간 색의 계열이 갑자기 바뀌지 않는다. 게임 셀과 숨기기 셀이 같은 시트의 서식처럼 보인다.

### 5-4. 공유용 텍스트 복사 형식 [결정, 문구는 문구 팩]

- 복사 성공 알림은 토스트 "클립보드에 복사되었습니다"(`alert` 금지). 클립보드 권한 실패 시 숨은 `textarea` 선택 복사로 대체.
- 글자 수가 많은 경위는 60자에서 `…`로 자른다. 각 줄은 줄바꿈 `\n`으로 구분(CRLF 아님).

## 6. 공유 파일 누수 덮어쓰기 (`monthly-close.css` 맨 앞에 둘 것)

[확인] `src/app/globals.css`, `src/app/layout.tsx`를 읽었다. 공유 파일은 수정하지 않는다. **unlayered(`@layer` 밖) 규칙은 같은 중요도에서 `@layer base` 규칙보다 항상 이긴다**. 루트의 규칙은 모두 `@layer base`이므로 아래 덮어쓰기가 이긴다.

### 6-1. 새는 스타일 6가지

| # | 새는 것 (출처) | 위장에 미치는 영향 | 덮어쓰기 |
|---|---|---|---|
| 1 | **주황 포커스 링** `*:focus-visible { box-shadow: 0 0 0 3px rgba(255,122,41,.5) }` (globals 16행) | Tab을 쓰는 게임(홈·대화상자·숨기기 시트의 입력)에 주황 빛이 돈다 | `.mc-root :focus-visible` 로 2px 파랑 outline, `box-shadow: none` |
| 2 | **크림 바탕** `<body class="bg-[#FAFAF7] min-h-screen">` (layout 89행) + `themeColor` | 크롬 바탕, 스크롤 끝 바운스에 크림색이 비침 | `.mc-root` 전면 칠하기 + `body:has(.mc-root)` 바탕 |
| 3 | **줄 높이 1.6** `body { line-height: 1.6 }` (globals 10행) | 셀·메뉴·도구줄이 24px보다 커져 틀이 늘어남 | `.mc-root { line-height: 1.3 }`, 셀 22px 고정 |
| 4 | **4px 둥근 스크롤바** `::-webkit-scrollbar { width: 4px }` + thumb 둥근 막대 (globals 22~31행) | 앱 같은 가는 막대 | `.mc-root ::-webkit-scrollbar` 12px 각진 막대 + 표준 `scrollbar-color` |

1. 녹색 검사: `monthly-close.css`의 모든 `#rrggbb` / `rgba()`를 HSL로 바꿔, 채도 10% 이상이고 색상각이 80~170도이면 실패(자동 테스트 권장).

3. Tab을 누른 뒤 주황색이 화면 어디에도 없는지(홈·대화상자·숨기기 시트 입력).
4. 스크롤바가 4px 둥근 막대가 아닌지(맥 크롬·사파리, 윈도우 크롬·엣지).
5. 어떤 요소 위에서도 손 모양 커서가 나오지 않는지.
6. 모든 `transition`·`animation`이 계산된 스타일에서 `none`인지.
7. 페이지의 계산된 `font-family`가 `Pretendard`·`Crimson`·`Gowun`으로 시작하지 않는지.

## 7. 모바일 (창 1개 + 시트 탭 전환, 1024px 미만)

방향서 §2-A: 배치는 1024px 미만이면 창 1개 + 탭 전환. 터치 전용 장치는 `(pointer: coarse)`로 구분한다. 브라우저 확대 200%(데스크톱 960 CSS px)도 이 배치로 떨어지므로 확대로 읽는 사용자가 막히지 않는다.

### 7-1. 세로 배치 (360x640 기준, 위에서 아래)

| 영역 | 높이 | 비고 |
|---|---|---|
| 상단바 | 40 | 파일명(14px, 말줄임) + [공유] + [⋯]. 메뉴줄·도구줄은 생략 |
| 이름 상자 + 수식 입력줄 | 32 | 이름 상자 폭 56. 수식 줄은 한 줄 |
| 열 머리글 | 24 | 힌트 범위 선택용 탭 영역(높이 24는 WCAG 2.2 최소 24x24를 충족) |
| 격자 | 8행 x 40 = 320 | 행 머리글 폭 28, 열 폭 = (100vw - 28) / 8 = 41.5 -> **41px** (360px 기준), 셀 높이 40px |
| 메모 줄 | 36 | 13px, 최대 2줄, 바탕 `--mc-chrome`, 위 1px `--mc-line` (고정 메모의 모바일 대체) |
| 확정 줄 | 48 | [반영] 보조 버튼 높이 **44**, 폭 96 이상. 위치는 UX가 정함(방향서 §2-I) |
| 시트 탭 줄 | 44 + safe-area | 탭 폭 최소 64, 높이 44 |
| 합계 | 544 | 640 - 544 = 96px 여유(주소창 제외 시 사파리 SE 553 대비 9px 여유) |

- 상태줄은 모바일에서 **만들지 않는다**(공간 절약). 상태 문장은 메모 줄이 대신한다.
- 모바일 셀 글자 12px(41px 폭에 한글 3자 = 36px + 여백 2px씩). 2~3자 상한이 넘치지 않는다. 최소 지원 폭 360px.
- 세로 화면 우선. 가로로 눕히면 같은 배치를 쓰되 격자 영역이 세로로 스크롤된다(셀 높이는 40 유지).

### 7-2. 터치 영역

| 대상 | 최소 크기 |
|---|---|
| 판 셀 | 41x40 (24x24 이상 충족, 선택 -> 확정 2단계라 오탭 비용이 작음) |
| 열·행 머리글 | 24 x 41 / 28 x 40 (힌트 범위 고르기 전용) |
| 시트 탭, 확정 버튼, 토스트 | **44 x 44 이상** |
| 대화상자 버튼·입력 | 높이 44 |
| 라디오 행 | 높이 48 |
| [⋯] 버튼 | 44 x 40 |

- 확정은 **같은 셀 다시 탭** 또는 [반영] 버튼 중 하나(방향서 §2-I). 선택된 셀은 PC와 같은 2px 테두리, 핸들은 그리지 않는다(손가락이 가림).
- 내 차례가 오면 [상대 시트] 탭으로만 자동 전환. 탭 전환 자체에 이동 애니메이션 없음.
- 숨기기: 시트 탭 줄의 숨기기 탭(구분선으로 떼어 놓음)을 탭하거나 경보 토스트를 탭한다. 토스트는 상단바 아래 8px에 떠서 숨기기 탭을 가리지 않는다.
- 배치: 끌어서 놓기 없음. 자동 배치 버튼을 확정 줄에 크게(44px) 둔다.
- 키보드(검산 숫자판)가 올라오면 검산 표를 `visualViewport` 위쪽에 붙인다(프론트). 이때 시트 탭 줄은 키보드 아래로 밀려난다 -> 키보드 중에는 숨기기를 **키보드 닫기 + 경보 토스트 탭**으로도 하게 한다(상단바 [⋯]에 숨기기 항목 추가) [요청: UX].

### 7-3. 모바일 숨기기 레이어

4열(§4-6), 선택만, 차트 없음, 행 머리글 폭 28, 열 머리글 24. 필터 줄(필터 띠)은 24px 높이 그대로 유지(§3-3).

### 7-4. 모바일 결과 문서

폭 `calc(100vw - 16px)`, 결재란은 제목 아래 오른쪽 정렬(칸 폭 56), 본문 표는 라벨 칸 64 + 값 칸 가변. 작업 줄은 쌓아서 한 줄에 하나(높이 44).

## 8. 홈(방 밖) 시각 규격 — 같은 토큰, 시트 셸 없음

홈은 게임임을 밝히는 화면이다(방향서 §5-1). 시트 셸을 쓰지 않지만 같은 토큰으로 "문서 앱 시작 화면"처럼 보이게 한다.

- 배경 `--mc-chrome`, 컨테이너 최대 폭 960px 가운데, 좌우 여백 24px(모바일 16px), 세로 간격 24px.
- 상단 48px 바: 문서 아이콘 + "월마감" 24px/600. 오른쪽 아무 것도 없음.
- **양식 카드 3장**: 폭 (960-48)/3 = 304px, 높이 220px, 바탕 `--mc-bg`, 1px `--mc-line`, 모서리 4px. 위쪽 160px은 업종별 표 축소 그림(선 1px `--mc-grid`, 머리 행 `--mc-header-bg`, 막대 한 개 `--mc-accent`로 3업종 모두 같은 틀, 글자 없음), 아래 60px에 양식 이름 14px/600 + 보조 12px. hover/포커스 테두리 `--mc-accent`, 선택 시 테두리 2px + `--mc-accent-soft` 바탕. 모바일은 세로로 쌓고 높이 72px 가로형 카드.
- **안내 상자**: 바탕 `--mc-bg`, 1px `--mc-line`, 왼쪽 4px `--mc-accent` 줄, 안쪽 16px. 제목 15px/600, 규칙 3줄 13px, 그 아래 12px `--mc-text-faint`로 "Microsoft·Google과 무관", "회사 규정 확인은 본인 몫", 베타, "시트 화면에서 Tab은 시트 전환 키", "PC에서 더 잘 보입니다". 이 상자는 **숨기지 않고 항상 보이게** 둔다.
- 문서 번호로 열기: 입력(폭 160, 32px, `inputmode="numeric"`, 5자리) + 기본 버튼. 최근 문서 표: 행 높이 36, 13px, 머리 `--mc-header-bg`.
- 홈은 표준 Tab 이동을 쓰므로 주황 대신 §6의 파란 포커스 링이 보여야 한다.
- 홈에서만 문서 스크롤을 허용한다(`data-surface="home"`).

### 10-3. 키보드·스크린리더

- **MVP 제약(방향서 §5-4 수용)**: 게임 화면에서 Tab은 숨기기 키라 포커스 이동에 못 쓴다. 방향키·Enter·이름 상자 입력·마우스로 모든 조작이 된다.
- 격자: `role="grid"`, 행 `role="row"`, 셀 `role="gridcell"`, 선택은 `aria-selected` + `aria-activedescendant`. 셀 `aria-label` 예: "B7, 해당 없음", "C3, 반려", "D5, 종결, 내 업종 어휘의 짧은 이름". 화면의 `0`/`1` 대신 읽는 단어로.
- 상태줄은 `role="status" aria-live="polite"`, 경보 토스트는 `role="alert"`. 3초 안에 반응해야 하는 경보는 화면 낭독 사용자에게 불리하다는 한계를 홈 안내에 이미 있는 "PC에서 더 잘 보입니다"와 함께 고지(감수하는 제약).
- 한 번에 두 개 이상 읽히지 않도록 메모 본문은 `aria-live="off"`, 상태줄이 같은 결과를 한 줄로 낭독.
- `prefers-reduced-motion`: 어차피 움직임이 없다. `forced-colors: active`(윈도우 고대비)에서는 상태 바탕색이 사라지므로 칸 글자·취소선·안쪽 테두리·삼각형이 구분을 이어받는다. 이를 위해 침몰 안쪽 테두리와 선택 `outline`은 `forced-colors`에서 `CanvasText`/`Highlight`로 대체된다(별도 규칙 추가 필요 없음, outline은 시스템 색으로 자동 변환).
- 포커스 가시성: 입력·버튼 `outline: 2px` 파랑(오프셋 2px 또는 -2px), 홈·대화상자·숨기기 시트에서 보인다.

## 12. 열린 질문

**UX디자이너에게**
1. 오른쪽 창 10~14행 검산 표의 라벨 칸을 병합 5칸 이상으로 그려 줄 것(§1-4, 24자 라벨 폭). 와이어프레임 치수와 맞는지.
2. 창 머리 띠(24px) 문구와 숨기기 레이어의 "필터 줄" 문구(웃음 등급 0, 두 레이어 모두 업종 의존 없음)는 UX가 정한다. 높이만 고정.
3. ESC 하나로 드롭다운을 먼저 접을지 곧바로 숨길지(§2-9).
4. 모바일 [반영] 확정 줄의 위치(§7-1에서는 격자 아래 48px 줄로 가정)와 키보드가 올라온 상태에서의 숨기기 경로(§7-2).
5. 모바일 열·행 머리글을 힌트 범위 선택에 쓰는지(높이 24px 터치 영역으로 충분한지) 혹은 별도 힌트 선택 UI인지.
6. 결과 문서 본문 문구 길이: 경위 본문 4줄 84px 안에 들어가는 자수 상한(13px/20px 줄, 폭 약 480px = 줄당 한글 36자 x 4줄 = 약 140자)을 문구 팩 검사 기준으로 삼을 것.

**디자인팀장에게**
1. `.mc-root` / `.mc-shell` 2층 구조(§1-1)를 프론트와 맞춰 확정해 달라(방향서에 둘이 혼용됨).
2. 파비콘 실루엣이 구글 시트 아이콘과 가까운지 판단(§9-2). 더 보수적인 가로줄 3개 안으로 가는지 PM 확인 시점.
3. 침몰 판의 안쪽 1px 테두리와 취소선을 "UI 추가 표지"로 승인하는지(§11-2, §11-4).
4. 공유 텍스트(§5-4)의 4줄 고정 문구를 UX 문구 팩에 포함시킬지, 링크는 홈 주소로 고정할지.
5. 메모 삼각형·취소선이 문구 검수 규칙의 "웃음 등급 1"에 해당하는지(상시 노출 요소) 등급 지정.
6. 크롬 121+에서 `scrollbar-color` 때문에 우리 12px 막대 스타일이 무시되는 점(§6-2 #4)을 수용하는지. 수용 시 크롬은 OS 기본 막대.

**프론트팀장에게 (참고)**
- `apple-icon.png`, `og.png`는 UI가 만들 수 없다(§9). 페이지개발자 담당으로 넘긴다.
- 폭표(§1-4)의 한글 글자 수는 `canvas.measureText` 실측 테스트로 확정하는 것을 권장한다(맥·윈도우 글꼴 차이 +-8% [추정]).
