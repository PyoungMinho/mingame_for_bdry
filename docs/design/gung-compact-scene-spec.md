## 1. 현장 보기 (현장 그림 화면)

### 1-1. 정의

> 조사 라운드 첫 1분, 모두가 같은 그림을 보며 물건을 눌러 **이미 공개된 사실**을 한 줄씩 함께 읽는 공용 화면.

| 보기 | 어디서 | 라운드 | 상태 저장 |
|---|---|---|---|
| **A. 방장 폰(기본)** | 방장 `진행` 탭, 조사 라운드의 새 하위 단계 `scene`(고르기 앞) | 방장 진행 단계에 자동 고정(들어선 라운드까지 되돌아보기 가능) | 방장 폰 `gu:scene:v1` |
| **B. 큰 화면 모드** | 노트북·TV 브라우저에서 `/gung?view=scene&code=7F3K5` | 그 기기에서 직접 고름(2·3은 확인 1회) | 그 기기 `gu:scene:v1`(게임 상태 없음) |
| 보조: 현장 시트 | 방장·플레이어 폰의 `현장 보기` 링크(고르기·토론 중 언제든, 아이콘 lucide `Eye`) | 그 폰의 진행 단계 | A와 같은 키 |

**현장 ↔ 단서함 경계(헷갈리면 안 되는 한 줄)**: 현장에는 **모두가 이미 아는 것**만 나온다. 장소 단서 카드(몰래·숨기기 가능)의 내용은 현장에 나오지 않고, 현장에서 본 것은 단서함에 들어가지 않는다.

### 1-2. 정보 정책 — 이 화면의 가장 중요한 규칙

현장은 **공용 화면**이다. 여기에 새 사실을 넣으면 난이도 게이트(6인 R2 ≤50%, R3 끝 80%+)와 '숨기기' 규칙이 무너진다. 그래서 정보 등급을 둔다.

| 등급 | 내용 | 이번 개편 |
|---|---|---|
| 0 분위기 | 그믐·달 없음·고요 같은 공개 어휘만 | 허용(§1-10 어휘표) |
| **1 공개 재게시** | 앱이 **이미 보여 주는** 정보를 물건에 묶어 다시 보여 줌: 브리핑·배치도 라벨과 주석·장소 `sub`·공개 프로필·공용 카드(PB)·추가 증언(NPC)·기본 용어 | **허용(기본)** |
| 2 새 공개 사실 | 장소 카드에 있는 겉모습 같은, 앱이 아직 안 보여 준 사실 | **금지.** 쓰려면 원고팀 + 블라인드 재검증 + PM 승인(§5 결정 1) |

**하드 규칙**
- S1. 장소 카드·역할 패에만 있는 사물의 상태·흔적·냄새·글자·수량은 현장에 쓰지 않는다. 자동 검사: 현장 문장의 공백 제거 3글자 조각이 `privateOnly`(장소 카드+역할 패 − 공개 텍스트 모음)에 하나도 없어야 한다.
- S2. **정보 냄새 균등화**: 동궁전을 뺀 6곳은 정확히 핫스팟 2개·핫스팟당 줄 1개, 라운드와 무관하게 같다. 어느 곳이 '단서가 많은 곳'인지 현장 모양이 알려 주면 안 된다. 동궁전만 공용 단서(PB·NPC)가 놓이는 '현장'이다(브리핑이 사건 현장이라 밝힌 곳).
- S3. **라운드 게이팅**: 공용 카드 줄은 `getRoundBoard`/`publicBoardUpTo`(인원·라운드만 받는 기존 함수)가 그 라운드까지 내보낸 카드만. 4·5인 판 NPC 증언도 같은 함수가 정한다.
- S4. 길이: 환경 사물 한 줄(A) ≤ 40자 · 공용 카드 조각(B) ≤ 130자.
- S5. **역할·자리 무관**: 현장 모듈은 `assignmentOf`·`getSheet`·`getClue`·`clueSeal`을 import하지 않는다(방 코드에서 인원 n과 사건 표식만 쓴다). 큰 화면 기기가 코드만으로 누가 범인인지 계산할 수 없어야 한다.
- S6. 현장 문구·본 물건 기록은 결과 공유·OG URL·초대 링크에 넣지 않는다.

**PM이 든 예시 4개의 처리(솔직하게)**
| 예시 | 처리 |
|---|---|
| 탕약 사발 | 가능. 브리핑에 이미 있는 말(동온돌 머리맡) |
| 꿀단지 | 라운드 3 공용 증언(번 나인)이 나오는 라운드부터, 그 증언 문장으로만. 개인 단서(외매듭·티끌·명주실)는 현장에 못 나옴 |
| 은숟가락 · 편지 | 개인 단서에만 있는 사물이라 현장에 못 올림(올리면 '숨기기' 규칙과 충돌, 단서 냄새도 샌다) |

그래서 현장의 주인공은 **동궁전의 공용 단서 현장화**다. 가장 긴 글(PB-3 587자)이 '읽기'에서 '눌러 보기'로 바뀐다. 이것이 글 줄이기와 '다 같이 보는 화면'을 한 번에 푸는 방법이다.

### 1-3. 사용자 플로우

```
[방장 H6] 다음 조사 시작 → (신호 '둘째 조사를 시작하오'는 기존 그대로)
   ▼
H5a 현장 보기 (sub=scene · 조용한 60초 타이머 자동 시작)      큰 화면 기기도 이 순간 같은 라운드 열기(선택)
   ├ 물건 탭 → 관찰 카드(모두 읽음) ×(0~8)  · 본 물건 표시 ✓
   ├ 장소 옮기기: ‹ › 또는 [배치도] 탭
   └ 주 버튼은 언제나 활성 — 안 본 공용 단서는 캡션으로만 알림(막지 않음)
   │ [고르기 1분 시작 →]  ← 고르기 타이머 자동 시작(별도 시작 버튼 없음)
   ▼
H5b 장소 고르기 (select · 1:00)  ── 각자 폰: 장소 고르기 → 단서 몰래 열기
   │ [토론 5분 시작 →]
   ▼
H6 토론 (discuss · 5:00)  ── 필요하면 [현장 다시 보기](시트)
   │ [셋째 조사 시작 →] / [최종 변론으로 →]
```
**삽입 위치와 이유**: 라운드 진입 직후 · 장소 고르기 앞.
1) 공용 단서는 장소를 고르는 판단 근거라 먼저 보는 편이 자연스럽다. 2) 현장에 장소별 단서 냄새가 없으므로(S2) 순서가 난이도에 영향을 주지 않는다. 3) 낭독이 고르기 타이머를 잡아먹던 G2 문제가 사라진다(타이머는 현장이 끝난 뒤 시작).

**플레이어**: 게이트 `둘째 조사 시작됐어요 →`(R1·R2는 1탭, 시트 없음 — §2) → 방장 화면을 본다(폰은 내려놓아도 된다) → 방장이 `고르기`로 넘기면 각자 장소를 고른다. 폰에서 현장을 다시 보려면 `현장 보기` 링크.
**큰 화면 담당**: 링크 열기 → (표식 확인) → 조사 시작 외침에 맞춰 라운드 칩 선택 → 방장이 읽으라는 물건을 눌러 모두에게 보여 줌. 서버가 없으니 방장 폰과 자동으로 맞춰지지 않는다.

### 1-4. 정보 구조(IA)

```

< 900px(폰 세로)는 A와 같은 한 줄 스택. 큰 화면은 비밀이 없으므로 `⋮`에는 `본 물건 지우기`·`글자 크기`만 있다. 헤더에는 사건 표식만 보이고 방 코드·자리·역할은 어디에도 없다.

**F. 방장 `⋮ › 큰 화면으로 열기` 시트**
```

노트북·TV 브라우저에 이 주소를 열면

┌────────────────────────────────────┐

`보내기`는 기존 `share()`·`copyText()` 폴백 체인을 그대로 쓴다. 가장 쉬운 길은 폰 미러링이라는 점을 마지막 줄로 알린다.

### 1-6. 핫스팟 · 관찰 카드 · 본 물건 인터랙션

| 항목 | 사양 |
|---|---|
| 핫스팟 요소 | 실제 `<button>`(캔버스 위에 % 좌표로 얹음). 배경 그림은 `aria-hidden` 장식 |
| 크기 | 최소 **너비 24% · 높이 26%**(360px 캔버스 기준 86×58, 320px에서도 ≥ 48px). 장소당 최대 8개, 서로 겹치지 않고 간격 ≥ 2% |
| 라벨 | 사물명 ≤ 8자, 14px bold, 최대 2줄. 한지색(`--gu-paper`) 바탕 + `--gu-paper-ink` 글자(13.6:1) |
| 공용 단서 구분 | 파란 테두리 2px(`--gu-blue-ink` #86B4DA) + `공용` 텍스트 칩 + 아이콘 `ScrollText`. 색만으로 구분하지 않는다 |
| 새 표시 | 이번 라운드 공용 카드가 걸린 물건이 아직 안 열렸으면 좌상단 `새` 칩 |
| 본 물건 표시 | 열면 우상단 ✓ 칩(`--gu-green-fill` 바탕) + 라벨 대비 유지(흐리게 하지 않음). 스크린리더: "내문, 공용 단서, 본 물건" |
| 눌렀을 때 | 120ms 눌림색 → 관찰 카드 교체(모션 없음, 진동·소리 없음) |
| 다시 열기 | 본 물건도 언제든 다시 열린다. 막지 않는다 |
| 키 | `본 물건` 키는 `핫스팟id@라운드`. 같은 내문이라도 새 라운드의 새 줄은 다시 `새`가 뜬다 |

| 글자 | 폰 A: 사물명 22px·본문 22px(B는 20px). `글자 크게`(×1.2) 설정을 따른다. 큰 화면: `clamp(28px, 2.6vw, 44px)` |

**공용 단서를 놓치지 않게(완전성 보장)**
- 공용 카드는 쪼개 물건에 나눠 놓되, **모든 조각이 정확히 한 물건에만** 들어가야 한다(테스트로 잠금).
- `공용 단서 한 번에 보기 ▸`(기존 `PublicFold`) 접힘이 항상 있어 전문을 한 번에 볼 수 있다.
- 주 버튼 캡션 `공용 단서 N개를 아직 안 봤소`(막지 않음). 보이는 건 0개가 되면 캡션이 사라진다.
- 단서함·「?」의 공용 단서 전체 열람은 그대로다.

### 2-4. 진행표 — "게임 진행이 어떻게 되는지" 보는 화면

현재 진행을 보여 주는 것은 헤더 5기둥 레일(탭하면 단계 맞추기)과 플레이어 대기 화면의 6줄 목록뿐이다. 새로 `FlowStrip` 한 줄을 만든다.
```
개요 2 · 패 2 · 소개 2 · 조사 21(현장1+고르기1+토론5 ×3) · 변론 5 · 지목·진상 4      약 35분
```
- 위치: 플레이어 대기(P1), 방장 대기실(H1), 하는 법 시트 맨 위. 칸 6개(라벨 ≤ 4자 + 분).
- 목적: 시작 전에 "35분이면 끝난다"를 보여 줘 거부감을 줄인다. 분 합계는 상수에서 계산해 40을 넘으면 테스트 실패.
- 헤더 레일은 그대로(진행 위치 표시). 현장 화면에는 라운드 라벨 `조사 1/3`만 넣는다.

9. 큰 화면: 코드 오타→`BadCodeScreen`, ②③ 확인 1회, 새로고침 후 본 물건 복원, `gu:game:v1` 무변경.

## 핵심 결정 10줄

1. **현장 보기는 조사 라운드의 새 하위 단계(`scene`)**이며, 라운드 진입 직후·장소 고르기 앞에 1분(조용한 타이머)으로 들어간다.
2. **현장은 공개 정보 재게시만**(등급 1): 개인 단서 카드의 사물·상태는 현장에 올리지 않는다(은숟가락·편지는 불가, 탕약 사발은 가능).
3. **현장의 주인공은 동궁전의 공용 단서(PB·NPC) 현장화**: 587자 PB-3을 '읽기'에서 물건 3곳을 '눌러 보기'로 바꾸고, 전문 접힘·미확인 캡션으로 누락을 막는다.
4. **정보 냄새 균등화**: 동궁전 외 6곳은 라운드와 무관하게 핫스팟 2개·핫스팟당 줄 1개로 고정해 어느 장소가 단서가 많은지 알려 주지 않는다.
5. **큰 화면 모드는 `/gung?view=scene&code=…`**, 서버 없이 라운드를 직접 고르고(②③은 확인 1회), 게임 저장·역할 계산을 일절 쓰지 않아 비밀이 없다.
6. **핫스팟은 ≥ 86×58 실제 버튼**, 눌러 열리는 관찰 카드는 22px(큰 화면 28~44px) 낭독체, 본 물건은 ✓+접근명, 장소 이동은 `‹ ›`·배치도 시트·목록 보기를 병행한다(WCAG 2.1 AA).
7. **시간 예산 70분 → 약 36분(전환 포함 ≤ 40)**: 개요 450자, 패 확인 2분, 현장 1·고르기 1·**토론 5**분 ×3, 변론 45초, 진상 ≤ 650자·8비트.
8. **확인 시트 13종 → 6종**: 조사 1·2 게이트, 로비 시작, 지목→진상 게이트, 방장 진상 공개, 보너스 0개, 보드 내리기, 지목 바꾸기·보너스 열기를 없애고 조사 3 진입·범인 보기·단계 점프·큰 화면 ②③·파괴적 묶음·정황 건너뛰기만 남긴다.
9. **누르기 줄이기**: 자기소개 `다음 사람`·롤콜 자리 탭 삭제, 인장은 4자리 입력 즉시 올림, 보너스는 한 화면, 말투 칩 삭제(칩 6개).
