## 0. 결론

1. **화면은 HTML 한 장 안의 9개(V0~V8)이고, URL은 바꾸지 않는다.**
   - 1순위 사용자의 핵심 흐름은 4단계다: 시작(클라우드 고르기) → 수집 준비 → 결과 파일 넣기 → 리포트.
   - 고치는 법과 재점검은 리포트에서 갈라져 나간다.
   - 수집 단계는 데스크톱을 우선한다. 리포트와 체험 모드는 360px 화면까지 읽을 수 있게 지원한다.
2. **수집 3경로는 화면에서 '2개 + 대체 1개'로 보여 준다.**
   - 선택지: ① 파일 하나(CSV, 스크립트 없음) ② 수집기(권장).
   - ③ 붙여넣기는 처음부터 고르는 선택지로 두지 않는다. ②에서 내려받기가 막혔을 때 쓰는 입력 화면의 탭으로 둔다.
   - 이유: 선택 부담이 줄고, '셸 → 페이지' 방향을 헷갈릴 여지가 없어진다.
3. **T8 결정: 리포트는 목록으로 만들고, 집 단면도는 만들지 않는다.**
   - 집 메타포는 이름, 문 이름, 단색 선 아이콘 5개로만 전한다.
   - 상태색을 칠한 집 그림은 리포트 전체를 한 상태로 합친 것과 같은 효과를 낸다. 이는 §5-3 위반이고 녹색 과신을 부른다.
   - 같은 이유로 **문 단위 종합 배지도 화면에 그리지 않는다.** 문 머리에는 상태별 개수만 둔다. 엔진의 문 집계는 유지한다. 기획팀장 확인이 필요하다.
4. **5상태는 모양·글리프·색·글자 네 가지로 동시에 표시한다.**
   - 모양: ▲위험 · ◆주의 · ●이상 없음 · ■확인 불가 · ◌해당 없음(점선).
   - 상태 글자는 어떤 화면에서도 생략하지 않는다.
   - 라이트·다크 대비를 계산했다: 상태 글자는 최소 7.19:1(AAA), 아이콘은 최소 4.35:1 [확인: WCAG 상대 휘도 계산].
5. **회색(확인 불가)은 '할 일' 톤으로 만든다.**
   - 채운 진회색 둥근 사각에 물음표, 실선 테두리, 다른 상태와 같은 본문 대비, 왼쪽 빗금 띠.
   - '직접 볼 목록'은 손으로 체크할 수 있는 인쇄용 표로 만든다.
6. **색은 판정에만 쓴다.**
   - 빨강·노랑·초록·진회색은 5상태 전용이다.
   - 나머지 색: 베타 띠는 무채색, 체험 모드는 보라, 예외 라벨은 파랑, 강한 공지(7일 넘은 수집 결과, 비밀 패턴 감지)는 잉크 반전.
   - 폼 오류에도 빨강을 쓰지 않는다.
7. **톤은 '건강검진 결과지 + 기술 문서'로 정한다.**
   - 시스템 폰트를 쓴다. 일러스트·마스코트·이모지·그라디언트·숫자 카운트업·축하 연출은 하나도 넣지 않는다.
   - 같은 도메인의 게임·심리테스트 앱과 정반대 인상이 되고, 격리 조건(외부 폰트·이미지 0)과도 그대로 맞는다.
8. **격리 때문에 생기는 디자인 제약 중 놓치기 쉬운 두 가지**
   - 해시 기반 CSP에서는 마크업의 `style=""` 속성이 막힌다 [일반 지식, S1에서 확인]. 그래서 시각 값은 모두 클래스와 CSS 변수로 표현한다.
   - 비율 막대·도넛 같은 분포 그래프는 '점수'처럼 읽히기 때문에 쓰지 않는다. 숫자 칩만 쓴다.
9. **T2(판정 결과 모델)에 디자인이 요구하는 필드를 §4에 계층별로 정리했다.** 핵심은 다섯 가지다.
   - 문장이 아니라 사유 코드와 파라미터로 넘긴다(i18n과 금지어 린트를 위해).
   - 식별자는 {전체, 마스킹} 쌍으로 넘긴다. 그래야 Ctrl+P로 인쇄해도 마스킹된다.
   - 룰마다 증거의 기준 시각을 넘긴다. 자격증명 보고서는 수집 시각과 다를 수 있다.
   - 대상마다 바뀌지 않는 고유 키를 둔다.
   - '먼저 볼 3개'와 권한 해제 힌트는 엔진이 계산한다(정답지로 시험할 수 있게).
   - T1(수집 계약)에도 디자인 쪽 요구가 7개 있다. 예: 액세스 키 ID는 끝 4자리만 수집.
10. **표현 기준 위반 위험이 큰 지점 16곳과 대안 카피를 §5에 정리했다.** 새로 찾은 문제가 두 가지 있다.
    - 룰 제목 일부가 '이상 없음'과 붙으면 거꾸로 읽힌다. 예: "공개된 버킷 · 이상 없음". 제목을 상태 중립형으로 바꿔야 한다(T6).
    - 금지어 '인증'이 "다단계 인증", "Entra 인증"까지 잡는다. 린트에 문맥 허용 목록이 필요하다.
11. **일정**
    - STEP 3은 UX·UI 병렬 1세션 → 팀장 종합 1세션이다.
    - 가장 오래 걸리는 일은 룰 18장의 문구다(사유·영향·질문·고치는 법 3단계). DB설계자가 쓰고, 디자인이 톤과 금지어를 검수한다. STEP 4 초반까지 이어진다.

## 1. UX 검토: 흐름, 화면 구조(IA), 화면 전환, 빈·오류 상태

### 1-1. 기획서 대비 판단

기획서의 다음 결정은 UX상 옳고 그대로 유지한다.
- 3경로
- 셸 붙여넣기 블록 없음, 사용자가 직접 입력하는 명령은 2줄
- 리포트 순서
- 고치는 법을 별도 화면으로 분리
- 체험 모드의 띠와 테두리
- Before/After 비교

다음 7가지는 조정을 제안한다.

| # | 조정 | 이유 |
|---|---|---|
| a | 경로를 '2개 + 대체 1개'로 보여 준다 (§0-2) | 처음 고르는 선택지는 적을수록 좋다. 붙여넣기는 ②의 실패를 대신하는 경로라서 ②와 같은 판정 범위를 갖는다 |
| b | 문 단위 종합 배지를 그리지 않는다 (§2-1) | 녹색 과신을 막는다. 문은 초록인데 IdP MFA는 확인하지 못한 경우가 생긴다 |
| c | 분포 단위를 **점검(룰)**으로 하고, 정렬 순서를 하나로 맞춘다 | 대상(리소스) 단위로 세면, 큰 계정은 '이상 없음 214'처럼 초록이 부풀어 보인다. 대상 수는 룰 안에서 보여 준다 |
| d | 휴먼에러 표(§3-6)에 **⑦ 리포트 유실**을 추가한다 | HTML 한 장에 메모리 전용이라서 새로 생기는 실수다(뒤로 가기, 같은 탭에서 연 외부 링크, 드롭존 밖으로 떨어뜨린 파일, 새로 고침). 대응 장치 6개는 §1-3 |
| e | 수집 현황 격자(창의 R2)를 **'문별 수집' 줄**로 만든다 | 경로 카드·입력 화면·범위 패널에서 같은 컴포넌트를 쓴다. 판정이 아니라 수집 상태만 글자로 보여 준다 |
| f | R-03의 "리포트 첫 화면"을 **리포트 화면 최상단 블록**으로 해석한다 | 범위 패널을 2열로 압축한다. 데스크톱 첫 화면(약 900px)에 범위·못 보는 것·분포·'먼저 볼 3개' 머리까지 들어오게 한다 |
| g | 파싱 실패 시 리포트를 만들지 않는다. 입력 화면에 '확인 불가' 톤의 오류 패널을 띄운다 | 전부 회색인 리포트는 소음일 뿐이다. 이렇게 하면 INV-2(이상 없음 0개)도 자동으로 충족된다. 기획서의 "확인 불가 배너"를 이렇게 구현한다 |

### 1-3. 이동 구조와 전환 규칙

```
V0 시작 ─┬─ [AWS/Azure 점검] → V1 수집 준비 → V2 입력 → V3 리포트 ⇄ V4 고치는 법
         │                                              └→ V5 재점검 비교
         ├─ [체험 모드] → V6 → V3(체험 띠 + 보라 테두리) ⇄ V4
         ├─ [결과 파일이 이미 있어요] → V2
         └─ 머리 메뉴(모든 화면): 판정 규칙(V7) · 이 도구에 대해(V8)
```

**URL과 뒤로 가기**
- URL·쿼리·해시는 바꾸지 않는다. R-06의 취지에 맞고, 오프라인판에서도 똑같이 동작한다.
- 브라우저 '뒤로'는 `history.pushState({v:'V3'})`로 앱 안 이동에 쓴다. state에는 **화면 ID만** 넣는다. 브라우저가 세션 복원용으로 history state를 디스크에 쓸 수 있으므로 [일반 지식] 입력 데이터는 넣지 않는다.
- 데이터가 없는 화면으로 돌아가면 V0을 보여 준다.

**리포트 유실 방지 장치 6개 (⑦ 대응)**
1. 리포트가 메모리에 있으면 `beforeunload` 확인창을 띄운다.
2. 외부 링크는 모두 새 탭으로 연다(`noopener noreferrer`). 링크 옆에 도메인을 표기한다(예: `docs.aws.amazon.com ↗`).
3. 창 전체의 dragover/drop을 가로챈다. 드롭존 밖에 떨어진 파일은 브라우저가 열어 버리고, 그러면 페이지를 떠나게 된다 [일반 지식].
4. 실제 점검 리포트가 있는 상태에서 새 점검이나 체험 모드로 가면 확인을 받는다.
5. V4에서 V3으로 돌아올 때 스크롤 위치와 펼침 상태를 복원한다.
6. 동작 줄에 "이 탭을 닫으면 리포트는 사라집니다(저장하지 않음). 인쇄하거나 마스킹 사본을 저장하세요"를 항상 표시한다.

**화면 전환 시 처리**
- 새 화면의 h1로 포커스를 옮긴다.
- `document.title`을 바꾼다(예: "리포트 · 문단속 5").
- `aria-live`로 전환과 파일 인식 결과를 알린다.
- 맨 위로 스크롤한다(V4 → V3 복귀만 예외).

**오프라인판으로 열렸을 때**
- `file://`로 열렸으면 머리에 "오프라인판(파일)으로 열려 있습니다"를 표시하고, '오프라인판 내려받기' 버튼을 숨긴다.

### 1-4. 핵심 사용자 흐름

**F1. 1순위 · AWS · 수집기 (기본 흐름)**
- 경로: V0 [AWS] → V1 ② → 스크립트 읽기 · 해시 확인 · 내려받기 → CloudShell(업로드 → `sha256sum` 직접 입력 → PDF·저장소 값과 대조 → `bash` 직접 입력 → 계정 확인 Enter → JSON 생성) → 내려받기 → V2 드롭 → 인식 목록에서 계정·수집 시각 확인 → V3 → 먼저 볼 3개 → V4 → 콘솔에서 수정 → 다시 수집 → V5.
- 계정 혼동을 5겹으로 막는다:
  1. 셸에서 계정 확인(C-05)
  2. V2 인식 목록
  3. 리포트의 고정 신원 패널과 고정 맥락 줄
  4. V4의 '대상 계정' 줄
  5. V5의 계정 불일치 거부
- 붙여넣기 대체(F1-b): CloudShell에서 내려받기가 막히면 V2의 붙여넣기 탭을 쓴다. 출력이 크면 `--doors`로 나눠 여러 번 붙여 넣는다. 같은 실행(run id)의 조각끼리 합쳐지고, 문별 수집 줄이 채워진다. 이를 위해 T1에 요구가 있다(§4-3).

**F2. 1순위 · AWS · CSV만**
- 경로: V0 → V1 ① → IAM 콘솔 안내(메뉴 이름 대신 화면·속성 이름) → V2 → V3.
- 창문·창고·CCTV는 '수집 안 함'으로 회색 처리하고, "수집기를 쓰면 다섯 곳을 모두 봅니다"라고 안내한다.
- CSV에는 계정 별칭이 없다. 신원은 ARN 열에서 읽은 계정 ID로 표시한다 [일반 지식: 자격증명 보고서의 `arn` 열].

**F3. 재방문**
- V0 [결과 파일이 이미 있어요] → V2 → V3 → V5.

**F4. 2순위 학습자 (체험 모드)**
- 경로: V0 → V6 → V3(체험) → V4 → V7 → "학습용 계정으로 실제로 해 보기" → V1.
- V6 세트 카드에는 그 세트가 무엇을 가르치는지 적는다.
  - C: 위험이 어떻게 보이나
  - D: 확인 불가는 왜 생기나
  - A: 이상 없음과 해당 없음은 어떻게 다른가
  - B: 주의는 무엇을 묻나
- D 세트는 성공 지표 "확인 불가를 스스로 설명"과 바로 연결된다.

**F5. Azure**
- 흐름은 F1과 같다.
- 현관 섹션에는 가이드 카드(AZ-MFA-G)를 둔다: 포털 확인 3단계 + 본인 응답(예/아니요/모름).
- 비대칭을 문구로 드러낸다: "AWS 현관은 파일로 판정하고, Azure 현관은 직접 확인합니다".
- CSV 경로에서는 V2에 파일 자리가 2개 생긴다(스토리지 CSV, NSG CSV). AZ-MFA-1이 편입되면 포털 CSV 자리가 하나 더 생긴다.

### 1-5. 리포트(V3) 정보 구조

**순서 (기획서 §7-3을 유지하되 압축)**

0. **띠**: 베타 / 체험. 닫기 버튼은 없고, 스크롤하면 작게 줄어든다. `/flight`의 GlobalDemoBanner 패턴을 따른다 [확인: `src/app/flight/components/GlobalDemoBanner.tsx`].
1. **고정 맥락 줄(sticky)**: 별칭 + ID 끝 4자리 · 클라우드 · 기준 시각(KST) · ■확인 불가 n · 예외 n. 스크린샷을 어디서 잘라도 '누구 계정의 언제 상태인지'가 함께 찍히게 하는 장치다.
2. **조회 범위 패널(접을 수 없음, 2열 압축)**
   - 신원 / 범위 / 수집
   - 권한: 해제 힌트 문장은 항상 보인다. 거부된 호출 목록은 상위 3개만 보이고 나머지는 펼쳐서 본다.
   - 문별 수집
   - 못 보는 것 7개(전부 노출) + "못 막는 경로 4가지 →"
3. **배너 묶음(조건부)**: 오래된 수집 결과(24시간·7일) · 스키마 불일치 · 비밀 패턴 감지 · CSV 범위 미증명 · 예외 n건 적용(만료 m건 해제).
4. **분포**
   - 숫자 칩 5개: "점검 10개 — ▲위험 2 · ◆주의 3 · ■확인 불가 2 · ●이상 없음 2 · ◌해당 없음 1". 0도 표시하고 순서는 고정한다.
   - 상태 범례 1줄. 툴팁에만 숨기지 않는다.
   - d > 0이면 "아직 판단하지 못한 점검이 d개 있습니다 → 직접 볼 목록"을 고정한다.
   - §9-2 면책 전문을 작은 글씨 1단락으로 둔다.
5. **먼저 볼 3개 (점검 단위)**
   - 위험·주의를 priority 순으로 고르고, 모자라면 확인 불가로 채운다.
   - 위험·주의가 0개이고 회색이 있으면 '먼저 풀 것'(권한 해제 힌트)으로 바뀐다.
   - 전부 이상 없음·해당 없음이면 "확인한 범위에서 위험·주의를 찾지 못했습니다"를 쓰고, 못 보는 것을 다시 강조하고, 졸업 경로를 보여 준다. 축하 연출은 없다.
6. **문별 섹션 5개 (고정 순서: 현관 → 열쇠 → 창문 → 창고 → CCTV)**
   - 순서를 고정하면 위치가 학습되고 Before/After 비교도 쉬워진다.
   - 섹션 머리: 선 아이콘 + 문 이름(PM 용어 병기) + 상태별 개수 칩(0은 생략) + '직접 볼 것 n'.
   - 점검 행은 심각도 → priority 순으로 놓는다.
     - 접힌 상태: 배지 + 제목 + 사유 1줄 + 대상 수.
     - 이상 없음 행: 꼬리표(확인한 범위 · 기준 시각) + **'못 본 것 n' 칩**. 초록이 맹점 없이 혼자 나타나지 않게 한다.
     - 펼친 상태: 대상 표(위반 대상 먼저, 50개 단위로 더 보기) · 영향 1줄 · 확인할 질문 · 못 보는 것 · 근거 · [고치는 법].
   - 해당 없음 행은 섹션 끝의 "해당 없음 n개" 한 줄로 접는다(근거 1줄 포함).
   - 섹션 끝에 그 문의 검증된 실제 사례 1건을 링크한다.
7. **직접 볼 목록**
   - 담는 것: 확인 불가 대상 + 가이드 카드 + 범위 밖 고지 + 본인 응답.
   - 표 열: ☐ · 문 · 무엇을 · 왜 판단하지 못했나 · 어떻게 보나(콘솔 위치·속성·필요 권한) · 메모. [이 목록만 인쇄] 버튼.
8. **동작 줄**: 인쇄(옵션) · 마스킹 사본 저장 · 예외 파일 내보내기/불러오기 · 다시 수집한 파일과 비교 · 새 점검 · 유실 고지.
9. **바닥**: 졸업 경로(Prowler, Defender for Cloud, CIS) · 페이지 버전 · 룰셋 버전.

**문 단위 배지를 그리지 않는 이유**
- 문 색 하나는 '작은 종합 판정'이다.
- 현관에서 AWS-MFA-2가 해당 없음(콘솔 사용자 0명)이면 문이 초록이 된다. 그런데 Identity Center MFA는 직접 확인해야 하는 상태다. 이것이 정확히 ④ 녹색 과신의 함정이다.
- 엔진이 계산하는 `worstState`는 정렬과 인쇄 요약에만 쓴다.

### 1-6. 고치는 법(V4) 구조

```
← 리포트로
▲위험  콘솔 사용자 MFA                                   현관 · 대상 3명
대상 계정: acme-dev (••••1234) — 명령을 실행하기 전에 셸의 계정이 같은지 먼저 보세요
운영 영향: 낮음 (무채색 글자 칩)              마지막 확인 2026-10-19 · 근거 2 ↗
① 먼저 확인   무엇을 어디서 보는지 + 읽기 명령 예시(자리표시자 포함)
② 바꾸기      속성 이름 · 공식 문서 ↗ docs.aws.amazon.com
              ┌ 쓰기 명령 · 계정 설정을 바꿉니다 ─────────────┐
              │ aws iam … --user-name <사용자이름>             │  ← 복사 버튼 없음
              └──────────────────────────────────────┘
③ 되돌리기    1줄
대상: dev-runner, ops-kim, … (화면에서는 전체 이름, 인쇄에서는 마스킹)
[고친 뒤 다시 수집해서 비교하기 →]
```

- 3단계를 모두 펼친 상태로 보여 준다. 마법사처럼 한 단계씩 넘기지 않는다. R-11의 '먼저 확인과 되돌리기를 함께 보여 준다'를 이렇게 지킨다.
- 명령 블록은 두 종류로 나눈다.
  - 읽기 블록: 무채색 테두리.
  - 쓰기 블록: 두꺼운 잉크 테두리에 머리표 "쓰기 명령 · 계정 설정을 바꿉니다".
  - 둘 다 `<자리표시자>`를 점선 밑줄과 다른 바탕으로 강조한다.
- 180일이 지난 안내에는 '오래된 안내' 배너를 띄운다.
- 키 노출 관련 룰에는 런북 링크를 둔다.

### 1-7. 빈·오류·예외 상태 매트릭스

| 상황 | 감지 위치 | 리포트 | 표시(요지) | 사용자의 다음 행동 |
|---|---|---|---|---|
| 빈 파일·0바이트 | V2 | 안 만듦 | "빈 파일입니다" | 다시 내려받기 |
| 형식이 다름(이미지·PDF 등) | V2 | 안 만듦 | "결과 파일(JSON)이나 지원하는 CSV가 아닙니다" + 지원 목록 | — |
| JSON 파싱 실패(붙여넣기 잘림 포함) | V2 | 안 만듦 | 확인 불가 톤 패널: "읽지 못했습니다. 끝부분이 잘린 것 같습니다(마지막 글자 …)" | `--doors`로 나눠 붙이기, 파일로 다시 |
| 문단속 5 파일이 아님(schema 키 없음, 모르는 CSV 열) | V2 | 안 만듦 | "문단속 5 결과 파일이나 지원하는 CSV로 읽히지 않았습니다" | — |
| 스키마 메이저 버전 불일치 | V2 | 안 만듦 | "수집기 2.x 파일입니다. 이 페이지는 1.x만 읽습니다" | 버전 맞추기 |
| 마이너 버전 차이·필수 키 누락(INV-10) | V3 | 만듦 | 해당 영역은 확인 불가 + 상단 배너 "현관·열쇠 영역을 판정하지 않았습니다(필드 없음)" | 최신 수집기로 다시 수집 |
| CSV 열 누락 | V3 | 만듦 | 해당 점검은 확인 불가, 사유 "열 'mfa_active' 없음" | — |
| 결과 파일 안에서 비밀 패턴 감지(R-12) | V2→V3 | 만듦 | 잉크 반전 배너 + 그 값 자리에 "[가린 값]". 화면·인쇄·사본 어디에도 그리지 않는다 | 파일 출처 확인, 노출 런북 |
| **키가 든 파일로 보임**(`~/.aws/credentials`, `.env` 형태) | V2 | **거부** | "결과 파일이 아니라 키가 든 파일로 보입니다. 화면에 표시하지 않았고 어디에도 보내지 않았습니다. 입력칸을 비웠습니다." | 이 키를 다른 곳에 붙여 넣은 적이 있다면 교체 검토 |
| 수집 후 24시간 초과 / 7일 초과 | V3 | 만듦 | 맥락 줄에 "n시간 전" + 공지 배너 / 잉크 반전 강조 배너 | 다시 수집 |
| 수집 시각이 컴퓨터 시각보다 늦음 | V3 | 만듦 | "수집 시각이 이 컴퓨터 시계보다 늦습니다(시계 차이일 수 있음)" | — |
| 여러 파일의 계정이 서로 다름 | V2 | 합치지 않음 | 두 신원을 나란히 보여 줌 | 하나 빼기 |
| 같은 정보가 중복(수집기 JSON + CSV) | V2 | 만듦 | "수집기 파일에 같은 정보가 있어 CSV는 쓰지 않았습니다"(병합 규칙은 엔진이 정함) | — |
| 문 일부만 수집(`--doors`) | V3 | 만듦 | 문별 수집 줄에 '수집 안 함(--doors)', 해당 점검은 확인 불가(사유: 미수집) | — |
| 전부 거부(권한 없음) | V3 | 만듦 | '먼저 볼 3개' 자리에 '먼저 풀 권한' | 권한 확보 후 다시 수집 |
| 전부 이상 없음·해당 없음 | V3 | 만듦 | 축하 없음. "찾지 못했습니다(확인한 범위)" + 못 보는 것 + 졸업 경로 | — |
| 크기 상한 초과 / 1MB 넘는 파일 읽는 중 | V2 | 거부 / — | "n MB 넘는 파일은 읽지 않습니다" / "읽는 중" 글자 표시(워커는 CSP로 금지됨) | — |
| 재점검: 다른 계정·클라우드 | V5 | 비교 거부 | 두 신원을 나란히 보여 줌 | — |

## 2. 시각 언어 (T8 결정)

### 2-1. 집 단면도 vs 목록: **목록으로 결정. 집 단면도는 MVP에서 만들지 않는다** [설계 판단]

1. 상태색을 칠한 집 그림은 '집 한 채의 건강 사진'이 된다. 리포트 전체를 한 상태로 합친 것과 같은 효과로, §5-3 위반이고 ④ 녹색 과신을 부른다.
2. 문 단위로 색을 칠하면 룰·대상 단위의 정보가 가려진다.
3. 확인 불가(회색)가 그림 속 빈칸처럼 보여 옅게 읽힌다. '회색을 옅게 처리하지 않는다'는 원칙과 충돌한다.
4. 격리 조건에서는 인라인 SVG 일러스트에 다크 모드·인쇄·반응형·대체 텍스트까지 만들어야 한다. 비용에 비해 가치가 낮고, 흑백 인쇄에서는 의미가 사라진다.
5. 같은 도메인의 게임·심리테스트와 구분되는 '결과지' 인상에 역행한다.
6. 나중에 6번째 문(GitHub)을 넣을 때 목록은 행 하나만 늘리면 되지만, 그림은 다시 그려야 한다.

집 메타포는 이름, 문 이름, 선 아이콘 5개로 전한다. PDF나 교육 자료(페이지 밖)에서 단면도를 쓰는 것은 막지 않는다. 단, 상태색은 칠하지 않는다.

### 2-3. 회색(확인 불가) 톤 규칙: "경고가 아니라 사람이 볼 목록, 그러나 옅지 않게"

- 아이콘은 채운 모양이다. 위험·주의·이상 없음과 같은 무게를 갖는다. 외곽선만 있는 모양은 해당 없음만 쓴다.
- 본문 글자는 다른 상태와 같은 진한 잉크를 쓴다. '비활성' 관례(옅은 회색 글자, 낮은 대비)는 금지한다.
- 실선 테두리와 왼쪽 빗금 띠를 둔다. 빗금은 데이터 시각화에서 '데이터 없음'을 뜻하는 관례이고, 장식일 뿐 의미를 싣지 않는다.
- 분포 칩도 다른 상태와 같은 크기다.
- 문구에서 '오류·실패' 같은 탓하는 말을 쓰지 않는다. "조회 권한이 거부됐습니다(s3:GetBucketPolicyStatus). 이 권한으로 다시 수집하거나 콘솔에서 직접 보세요"처럼 **해소법이 함께 붙는 할 일**로 쓴다.
- 직접 볼 목록 인쇄본은 ☐ 체크 칸이 있는 할 일 표다.
- 회색이 많을 때는 원인별로 묶는다("권한 1개로 풀리는 점검 7개"). 회색이 부풀어 사용자가 무시하게 되는 것을 막는다.

### 2-6. 타이포·간격·형태

**글꼴**
- 본문: `-apple-system, BlinkMacSystemFont, "Apple SD Gothic Neo", "Segoe UI", "Malgun Gothic", "맑은 고딕", "Noto Sans KR", "Noto Sans CJK KR", Roboto, sans-serif`.
  - 설치돼 있을 때만 쓰이는 Pretendard 같은 이름은 넣지 않는다. 기기마다 모양이 달라지는 편차를 줄이기 위해서다.
- 고정폭: `ui-monospace, "SF Mono", SFMono-Regular, Menlo, Consolas, "D2Coding", "Noto Sans Mono CJK KR", monospace`.
  - 해시·명령·ID·리소스명에 쓴다.

**크기와 굵기**
- 크기는 13 / 14 / 16(본문) / 18 / 20 / 24 / 30px. 한글 가독성 때문에 최소 13px다.
- 행간은 본문 1.6, 제목 1.35. 굵기는 400 / 600 / 700.
- 숫자·시각에는 `tabular-nums`를 쓴다.

**줄바꿈**
- 한국어 문장은 `word-break: keep-all`.
- 리소스명·ARN은 `overflow-wrap: anywhere`. 적대 픽스처의 '아주 긴 이름' 대응이다.

**해시 표시**
- 64자리를 8자리씩 8묶음으로, 16px 고정폭으로 보여 준다.
- 묶음 간격은 CSS로만 준다. 텍스트에 공백을 넣지 않으므로, 복사해도 64자가 이어진 그대로 나온다.

**간격과 형태**
- 간격은 4px 단위: 4 / 8 / 12 / 16 / 24 / 32 / 48 / 64.
- 모서리 반경은 4px(배지·칩·입력), 6px(패널). 알약 모양은 쓰지 않는다. 그림자도 없다.

**레이아웃**
- 본문 최대 폭 880px. 스크립트 뷰어와 넓은 표는 1040px.
- 브레이크포인트는 600 / 1024.
- 터치 대상은 44px 이상.

**움직임**
- 펼침·접힘 120ms만 둔다. `prefers-reduced-motion`이면 0.
- 숫자 카운트업, 진입 애니메이션, 축하 연출은 없다.

### 2-7. 인쇄 레이아웃

- **공통**
  - A4 세로, 여백 14/12/16mm, 본문 10.5pt, 고정폭 9pt.
  - 라이트 토큰을 강제한다. 버튼·내비게이션·드롭존·스크립트 뷰어는 숨긴다.
  - 브라우저 기본 설정에서는 배경색이 인쇄되지 않는다 [일반 지식]. 그래서 의미는 모양·글자·테두리로만 싣고, 배경색은 장식으로 둔다.
  - 배지에만 `print-color-adjust: exact`를 건다.
- **전체 리포트 인쇄**
  - 머리: "문단속 5 리포트 · 올린 파일 기준 참고 자료" + (체험 모드면 "체험 모드 · 가짜 데이터"를 크게) + (베타 띠) + 신원(마스킹)·범위·수집 시각(KST/UTC)·수집기·페이지 버전·입력 파일 이름.
  - 본문: 분포 → 미판정 배너 → 먼저 볼 3개 → 문별 섹션.
    - 위험·주의·확인 불가는 펼친 상태로 대상까지 인쇄한다.
    - 이상 없음·해당 없음은 한 줄 + 꼬리표·근거만 인쇄한다.
  - 끝: 직접 볼 목록 → 못 보는 것 → 바닥에 §9-2 면책.
  - `<details>`는 닫힌 내용이 인쇄되지 않는다 [일반 지식]. `beforeprint`/`afterprint`로 펼치거나, 인쇄 전용으로 따로 렌더한다.
- **직접 볼 목록만 인쇄**
  - A4 한 장짜리 체크리스트. 행 높이는 10mm 이상(손으로 쓰는 메모 칸).
- **인증서처럼 보이게 하지 않는다**
  - 도장·서명란·'확인자'·'판정: 적합' 칸을 넣지 않는다. 인쇄본이 감사 증적처럼 오용되는 것을 막는다.
- **마스킹 기본값(R-13)을 Ctrl+P에서도 지킨다**
  - 식별자마다 화면용 span(전체)과 인쇄용 span(마스킹)을 함께 렌더한다.
  - CSS `@media print`에서 둘 중 하나만 보이게 한다.
  - 인쇄 옵션 "이름·ID 표시"(기본 꺼짐)는 루트 클래스만 바꾼다.
  - '인쇄' 버튼을 거치지 않고 브라우저 메뉴로 바로 인쇄해도 마스킹된 본이 나온다.

### 2-8. 다크 모드
- `prefers-color-scheme`만 따른다. 토글은 두지 않는다. 토글 상태를 기억하려면 저장소가 필요해 R-06에 걸린다.
- 인쇄는 항상 라이트다.

### 2-9. 접근성 요약 (WCAG 2.1 AA)
- 상태는 글자로 전달한다. 아이콘은 `aria-hidden`.
- 대비는 §2-2 기준을 지킨다.
- 드롭존은 키보드로 열 수 있는 '파일 고르기' 버튼을 겸한다. 모바일에는 드래그가 없으므로 버튼이 항상 보여야 한다.
- 표는 실제 `<table>`과 `<th scope>`로 만든다. 모바일에서는 CSS만으로 카드형으로 바꾼다.
- 200% 확대에서도 내용이 다시 흐르게 한다.
- 문서 언어는 `lang="ko"`.

| 외부 이미지 0(`img-src data: blob:`) | 콘솔 스크린샷 안내, 로고 이미지를 쓸 수 없다 | 안내는 글자로(메뉴 이름 대신 속성명, 기획서 §10). 아이콘은 인라인 SVG 약 20개. 파비콘은 data: SVG |
| 첫 로드는 문서 1건, 코드 분할·지연 로드 금지 | 모든 화면·체험 데이터·룰 문서·수집기 원문이 첫 로드에 들어간다 | 자산 예산(§3-3). 체험 세트는 작게 만든다 |
| `script-src`/`style-src` 해시 | **마크업의 `style` 속성이 막힌다.** CSP3에서 해시는 속성에 적용되지 않고 `'unsafe-hashes'`가 필요하다. 실행 중 CSSOM으로 바꾸는 것은 막히지 않는다 [일반 지식, S1에서 확인] | `style` 속성 0. 모든 값은 클래스와 CSS 변수로. 동적 너비 막대처럼 인라인 스타일에 기대는 디자인은 하지 않는다 |
| `worker-src 'none'` | 웹 워커를 쓸 수 없다 | 큰 파일을 읽는 동안 '읽는 중' 상태를 디자인한다 |
| `connect-src 'none'`, 원격 갱신 없음 | 업데이트 확인을 할 수 없다 | 페이지 버전과 룰 마지막 확인일을 표기한다. 180일이 지나면 '오래된 안내' 배너 |
| 영속 저장 0(R-06) | 테마 기억, '다시 보지 않기', 진행 저장을 할 수 없다 | 안내는 매번 보이므로 짧게 쓴다. 닫기 대신 작게 줄어들게 한다 |
| 바이트가 같은 오프라인판(R-08) | `file://`에서도 같은 화면이어야 한다 | 실행 중에 감지해 '오프라인판' 표시 |
| 스크립트가 실패하면 빈 화면 | 해시 불일치·확장 차단이면 백지가 된다 | 정적 HTML 셸에 안내문을 넣고, 스크립트가 부팅하면 숨긴다 |
| 적대적 입력(R-12) | RTL 제어 문자로 화면 글자를 속일 수 있다 | 입력값은 모두 텍스트 노드 + `<bdi>`(또는 `unicode-bidi: isolate`)로 그린다. 제어 문자는 ⟨U+202E⟩처럼 보이게 바꾼다 |

### 3-2. 톤: "건강검진 결과지 + 기술 문서"

기획서가 '이상 없음'을 건강검진의 "이상 소견 없음"에서 가져온 것과 같은 계열이다.

**규칙 6개**
1. 색은 판정에만 쓴다. 나머지 UI는 종이와 잉크 두 색이다.
2. 장식은 0이다.
3. 이미지가 아니라 글자로 말한다.
4. 기준 시각과 범위가 모든 결과 옆에 붙는다.
5. 움직임은 최소로 한다.
6. 모든 외부 링크는 도메인을 보여 준다.

**같은 도메인 앱과 구분하는 장치**
- 이 HTML만의 `<title>`과 파비콘(열쇠 구멍 글리프)을 둔다.
- 다른 앱으로 가는 링크·교차 홍보는 0이다.
- 일러스트·마스코트·이모지가 없다.
- 워드마크는 "문단속 5"를 시스템 폰트 굵은 글씨로 쓴다.
- 만든 곳 표기(Boundaryworks)와 저장소 링크로 출처를 밝힌다. PM 확인이 필요하다 [미확인].
- og:image는 MVP에서 넣지 않는다. 텍스트 메타만 둔다. 베타는 noindex이고 홍보도 하지 않는다.

### 3-3. 디자인 자산 예산 [설계 판단]

| 항목 | 예산 |
|---|---|
| 폰트 | 0 |
| 이미지 | 0 |
| 아이콘 | 8KB 이하 |
| CSS | 25KB 이하(비압축) |
| 체험 세트 8개 합계 | 120KB 이하 권고 |
| 전체 HTML | 600KB 이하(비압축) 권고. 상한은 프론트팀장이 T4에서 정한다 |

- 레포에 lucide-react가 있다 [확인: package.json]. 하지만 상태 아이콘 5종은 실루엣 규칙에 맞춰 직접 그린다.
- 문 아이콘·UI 아이콘은 lucide의 path를 인라인으로 복사해도 된다(ISC 라이선스 [일반 지식]).

### 3-4. 프론트엔드 전달 핵심 (팀장회의에서 공유)

1. `style` 속성 0. 클래스와 CSS 변수만 쓴다.
2. 외부 링크는 새 탭 + `noopener noreferrer` + 도메인 표기.
3. 창 전체 드롭 가로채기, `beforeunload`, `pushState`(화면 ID만).
4. 입력 문자열은 텍스트 노드 + `<bdi>` + 제어 문자 표시 + `overflow-wrap: anywhere`.
5. 마스킹은 이중 렌더하고 루트 클래스로 전환한다.
6. `<details>`는 인쇄 전에 펼친다.
7. 정적 셸 안내문을 두고, 부팅하면 숨긴다.
8. `file://`를 감지한다.
9. 화면 전환 시 h1 포커스, `document.title`, `aria-live`.
10. 띠는 닫기 없이, 스크롤하면 작게 줄어들게.
11. Tailwind 클래스는 쓰지 않는다. 레포 Tailwind `content`가 `src/app/**`를 훑으므로 [확인: tailwind.config.ts], cloudcheck 원본에 쓴 유틸리티가 전 앱의 전역 CSS 출력을 바꾼다.
12. 디자인은 UI 런타임(React·Preact·바닐라)과 무관하다. `<details>`, `<dialog>`, `<table>` 같은 네이티브 요소를 우선 쓴다.

## 4. 판정 결과 모델(T2)에 디자인이 요구하는 필드

### 4-1. 원칙
1. **문장 대신 코드 + 파라미터**(`{code, params}`)로 넘긴다. i18n 키 구조와 금지어 린트가 메시지 카탈로그 하나만 보면 되게 하기 위해서다. 엔진 출력에 한국어 문장을 넣지 않는다.
2. **식별자는 `{full, masked}` 쌍**으로 넘긴다. 엔진이 마스킹 함수를 공개하는 방식도 된다. 화면에는 전체, 인쇄·사본에는 마스킹을 CSS로 전환한다.
3. **안정 키 `key`**를 둔다. 예외 파일 매칭, Before/After 대상 비교, 렌더 키에 쓴다.
4. **시각은 ISO UTC**로 넘긴다. KST/UTC 표시 변환과 '지금과의 차이'(오래된 수집 결과, 오래된 안내)는 UI가 계산한다. 엔진의 순수성(INV-9)을 지키기 위해서다.
5. **정렬·선택 결과는 엔진이 산출**한다(먼저 볼 3개, 권한 해제 힌트 순서). 그래야 정답지(G3)로 시험할 수 있다.

### 4-2. 필드 목록

**A. 리포트 머리**
- `mode: 'real'|'demo'`, `demo?: {setId, nameKey}`
- `engine: {pageVersion, rulesetVersion}`
- `identity: {cloud, alias?: Masked, accountId: {full, last4}, tenant?: {last4}, principalType, principalName?: Masked, source: 'collector'|'csv-arn'|'unknown'}`
  - 화면 신원 패널은 기획서 §5-5대로 '별칭 + 끝 4자리'만 쓴다.
- `inputs[]: {fileName, kind, sizeBytes, schemaVersion?, collector?: {name, version}, collectedAt, runId?, doors[], scopeProven}`
- `collectedAt`: 대표값은 가장 오래된 입력의 시각. 입력이 여러 개면 `collectedAtRange`.
- `credentialReport?: {generatedAt?, generatedAtSource: 'report'|'approx'|'unknown'}`
- `scope.aws?: {regionsEnabled[], regionsSucceeded[], regionsFailed[{region, reason, receiptId}]}`
- `scope.azure?: {subscriptions[{last4, name: Masked, visible, queried, result}]}`
- `receiptsSummary`: 결과 코드 8종(ok·empty·notconfigured·denied·error·throttled·truncated·unsupported)별 개수
- `deniedCalls[]: {call, permission, scope, errorCode, receiptId, ruleIds[]}`
- `permissionUnlocks[]: {permission, unknownRuleCount, unknownTargetCount, ruleIds[]}`: 많이 푸는 순서로 정렬
- `doorCollection[]: {door, status: 'collected'|'partial'|'not-collected', reason, judgeLevel: 'full'|'findings-only'|'none'}`
  - `findings-only`는 "찾은 위험은 보여 주지만 '없음'은 확정하지 못합니다"를 뜻한다(INV-4, CSV 경로).
- `cannotSeeGlobal[]`: 고정 7개 + 조건부(예: 콘솔 사용자 0명 → IdP MFA)
- `distribution: {rules: Record<State,n>, targets: Record<State,n>}`: 화면은 rules를 쓴다(§7 D1)
- `priority: {mode: 'findings'|'unlock'|'none-found', ruleIds[≤3]}`
- `notices[]: {code, params}`: schema-mismatch(영향받은 문), secret-masked(개수), csv-scope-unproven, duplicate-input-ignored, partial-doors, exceptions(applied, expired, unmatched), future-timestamp

**B. 문**
- `doors[]: {door, ruleIds(정렬됨), countsByState, manualCount, worstState}`
  - `worstState`는 정렬·인쇄 요약용이다. 화면 배지로는 쓰지 않는다.

**C. 점검(룰)**
- `ruleId, cloud, door, titleKey, state, maxState`
- `allowsGreen`: false면 "이 점검은 '이상 없음'을 주지 않습니다"를 표기한다(AWS-KEY-3, AZ-MFA-1).
- `priority`: 18장 전체에 **중복 없는 정수**. '먼저 볼 3개'가 결정적이어야 하기 때문이다.
- `reason: {code, params}`: 상태별 한 줄. 예: "MFA 없는 콘솔 사용자 3명".
- `impactKey`: 영향 1줄. 위험·주의일 때.
- `questionKey?`: 주의일 때 확인할 질문.
- `naBasis?: {code, params}`: 해당 없음의 근거와 모수. 예: "IAM 사용자 4명 중 활성 키 0개".
- `evidenceAsOf: {at, source: 'collectedAt'|'credentialReport'|'approx'|'unknown'}`: 꼬리표의 '기준 시각'. IAM 룰은 보고서 생성 시각이다.
- `scopeTag: {kind: 'regions'|'subscriptions'|'account-global'|'csv-partial', covered, total}`: 꼬리표의 '확인한 범위'.
- `targetCounts: {total, byState}`: Before/After의 "위험 3 → 1"에도 쓴다.
- `unknown?: {reasons[{code, call?, scope?, errorCode?, receiptId?}], resolution: {kind: 'permission'|'path'|'portal'|'rerun'|'guide', permissions[], textKey}}`
- `cannotSee[]`: '못 본 것 n' 칩과 펼침용.
- `labels[]`: E 참조.
- `basis[]: {titleKey, url, kind: 'official'|'regulator'|'incident'}`, `incidentRef?: {titleKey, date, url, sourceName}`
- `guide?: {stepKeys[], selfAnswer?: {stepId: 'yes'|'no'|'unknown'}}`: AZ-MFA-G. 본인 응답은 메모리에만 둔다.
- **고치는 법 데이터**(룰 데이터를 참조해도 된다): `fix: {observe: {textKey, where?, commands[]}, change: {textKey, property, docUrl, commands[]}, revert: {textKey}, impact, prodImpact, lastVerified, runbookUrl?}`
  - `commands[]: {kind: 'read'|'write', text}`: text 안의 자리표시자는 반드시 `<…>` 형식으로 쓴다. 쓰기 명령에 자리표시자가 1개 이상 있는지 린트로 확인할 것을 제안한다.

**D. 대상(항목)**
- `key`, `type`: iam-user · access-key · root · bucket · security-group · trail · storage-account · container · nsg · subscription · account-setting · region
- `display: {name: Masked, region?, subscription?: Masked, facts[{code, params}]}`
  - facts 예: 키 끝 4자리, 나이(일), 마지막 사용일, 포트·CIDR, '공인 IP 연결됨'(IP 값은 표시하지 않음).
- `state`, `reason: {code, params}`, `labels[]`
- `onlyThisDenied?`: INV-7. "이 대상만 점검 조회가 거부됨(점검을 막는 정책일 수 있습니다)" 표기용.
- `evidence: receiptIds[]`, `secretMasked?`

**E. 라벨**
- `{type: 'exception'|'intended-public'|'name-hint'|'self-answer'|'legacy-hint'|'beta'|'demo', params}`
- exception의 params: `{reason, until, createdAt, expired}`

**F. 직접 볼 목록**
- `manualChecks[]: {kind: 'unknown-target'|'unknown-rule'|'guide-card'|'out-of-scope'|'self-answered', door, ruleId?, targetKey?, title: {code, params}, why: {code, params}, how: {code, params}}`
  - `how`에는 콘솔 위치·속성·필요 권한이 들어간다.

**G. 재점검 비교**
- `compare: {accountMatch, cloudMatch, before: {identity, collectedAt}, after: {…}, reordered, sameCredentialReport, rules[{ruleId, before: {state, byState}, after: {state, byState}, change: 'better'|'worse'|'same'|'became-unknown'|'became-known'}]}`

**H. 입력 인식(리포트 이전 단계)**
- `recognition[]: {fileName, status: 'ok'|'empty'|'wrong-type'|'parse-error'|'not-cloudcheck'|'schema-major'|'credentials-file'|'too-large'|'account-mismatch'|'superseded', detail: {code, params}, identityPreview?, collectedAt?, doors[]}`
  - parse-error의 detail에는 오류 위치와 '끝이 잘린 것 같음' 추정을 넣는다.

### 4-3. 수집 계약(T1)에 디자인이 요구하는 것
1. **액세스 키 ID는 끝 4자리만** 수집한다.
   - 사용자는 콘솔에서 끝 4자리로 키를 대조할 수 있다.
   - 비밀 패턴 감지(R-12)가 AKIA/ASIA 키 ID에 잘못 반응하는 것을 막는다 [일반 지식: 키 ID 접두사].
   - 민감도도 낮아진다.
2. **`run: {id, doors[], part?}`**를 넣는다. `--doors`로 나눠 붙인 조각을 합치고, 문별 '수집 안 함' 사유를 표시하는 데 쓴다.
3. **Azure 구독의 표시 이름과 상태**를 넣는다. "조회 N / 보이는 M" 목록에 쓴다.
4. **영수증의 `call`이 사용자가 요청할 권한 이름과 1:1로 대응**하게 한다(AWS IAM 액션명, Azure RBAC 작업명). "이 권한이 있으면 K개를 풀 수 있습니다" 문구에 쓴다.
5. **공인 IP는 값이 아니라 있음/없음/모름 3값**으로 받는다. 화면에 값이 필요 없고, 마스킹 부담도 사라진다(C-07의 취지).
6. **실행 주체의 유형과 역할 이름**을 넣는다. 'SecurityAudit 역할로 실행했는지' 보여 주는 데 쓰고, 인쇄에서는 마스킹한다.
7. **자격증명 보고서 `generatedAt`의 출처**(보고서 안의 값 / 추정 / 모름)를 넣는다. 콘솔 CSV에 생성 시각이 들어 있는지는 [미확인]이다(기획서 §17-1).

### 4-4. 앱 설정(빌드 상수)으로 둘 것. 판정 결과에는 넣지 않는다
- `cloudAvailability: {aws, azure: 'open'|'beta'|'soon'}`
- 룰별 출시 여부(AZ-MFA-1)
- 기준값: 24시간, 7일, 180일
- 파일 크기 상한
- `hashChannels: {repo: url|null, pdf: {edition, page}|null}`: G9 전에는 PDF 행을 "준비 중"으로 표시한다.
- 페이지 버전

### 5-2. 룰 제목 × 상태 결합 문제 (T6 입력)

일부 제목은 '이상 없음' 배지와 붙으면 반대로 읽힌다. 예: "공개된 버킷 · 이상 없음"은 '공개됐는데 괜찮다'로 오독된다. 그래서 **제목은 점검 대상을 가리키는 상태 중립형 명사구**로 쓴다.

| 룰 | 현재 제목 | 제안 |
|---|---|---|
| AWS-STO-2 | 공개된 버킷 | 버킷 공개 상태 |
| AZ-STO-2 | 공개된 컨테이너 | 컨테이너 공개 상태 |
| AWS-NET-1 / AZ-NET-1 | 인터넷에 열린 관리·DB 포트 | 관리·DB 포트의 인터넷 노출 |
| AWS-KEY-4 | 남에게 맡긴 열쇠(외부 계정 신뢰) | 역할 신뢰 설정(외부 계정) |
| AWS-KEY-1 | 오래된 액세스 키 | 액세스 키 나이 |
| AWS-KEY-2 | 쓰지 않는 자격증명 | 자격증명 마지막 사용 |
| AZ-STO-1 | 계정의 익명 공개 허용 | 익명 공개 차단 설정 |

- 나머지(루트 계정 문단속, 콘솔 사용자 MFA, 계정 전체 퍼블릭 액세스 차단, CloudTrail 장기 기록, 스토리지 공유 키 회전, 활동 로그 장기 보관, Blob 접근 기록, Entra MFA 포털 확인, 관리자 열쇠 출입 제한 안내)는 그대로 둬도 된다.
- 검수 방법: 모든 제목을 허용된 상태 배지와 하나씩 붙여 읽는 검토 표를 STEP 3 카피 덱에 넣는다.
- priority 원칙 제안. 최종 결정은 백엔드팀장이 한다.
  - 순서: '외부의 누구나 지금 닿는가(익명 노출, `*` 신뢰)' → '계정 장악(루트·MFA)' → '자격증명 위생' → '기록'.
  - 18장 전체에서 동점이 없어야 한다.

### 5-3. 금지어 린트 보강
- **'인증' 동음이의 문제**: 금지어 '인증'(certification)이 기술 용어인 "다단계 인증(MFA)", "Entra 인증", "인증 방법", "인증 정보"까지 잡는다.
  - 문맥 허용 목록이 필요하다.
  - 일본어 v1.1에도 같은 문제가 있다: 認証(多要素認証).
- '통과'는 네트워크 문맥에서도 쓰지 않고 '허용'으로 쓴다.
- 린트는 화면에 표시되는 메시지 카탈로그에만 건다. 영수증 코드 `ok` 같은 내부 식별자는 대상이 아니다. 화면 표시는 '성공'으로 매핑한다.
