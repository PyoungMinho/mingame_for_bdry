## 1. 화면 구조 (Information Architecture)

### 1-1. 라우트·파일 맵

```
/gung                         단일 클라이언트 상태머신 (하위 페이지 없음)
/gung?code=7F3K5              초대 링크 진입 → 플레이어 플로우
/gung?code=7F3K5&as=host      방장 복구 진입(폰 교체·외부 브라우저 전환)
/gung?code=7F3K5&v=1          (선택) 사건 데이터 버전 — 불일치 시 경고 배너
/gung/og/result?o=c&n=5&h=3&j=4&m=52&r=0&d=20261002   결과 이미지(Edge, 1200×630)
/gung/og.jpg                  정적 커버(레이아웃 OG + 카톡 초대 카드 이미지)
```

- 화면 전환은 URL 라우팅이 아니라 **클라이언트 상태(phase)** 로 한다. 브라우저 히스토리에 의존하지 않으므로 새로고침·인앱 뒤로가기에 강하다(§12 백 가드).
- `useSearchParams` 사용 컴포넌트는 `<Suspense>`로 감싼다(Next 14 정적 렌더 요구).

### 1-2. Phase 정의 (방장·플레이어 공통 enum)

```ts
type SetupStep = 'home' | 'create' | 'invite' | 'join' | 'landing' | 'seat';
type Phase =
  | 'lobby'      // 대기 (방장: 롤콜 / 플레이어: 입장 완료)
  | 'briefing'   // 사건 개요 낭독
  | 'cards'      // 각자 비밀 패 확인
  | 'intro'      // 자기소개(신분 낭독) — 이 단계 이후 공용 화면에 역할명 표기 허용
  | 'r1' | 'r2' | 'r3'   // 조사 라운드 (방장 하위: 'select' 2분 → 'discuss' 7분)
  | 'defense'    // 최종 변론 (1인 1분, 자리 순)
  | 'vote'       // 동시 지목 (방장 하위: 'ready'→'countdown'→'input'→'tally'→('revote')→'final')
  | 'reveal'     // 진상 공개 (방장 하위: beat 인덱스)
  | 'result';    // 점수·공유
```

- **Header 좌측**: 셋업 화면 = `‹ 뒤로`(ChevronLeft) / 방장 인게임 = `↶ 되돌리기`(Undo2) / 플레이어 인게임 = 비움.
- **Header 우측**: 화면 꺼짐 방지 표시(🕯 = lucide `Flame` 점등 / `Moon` 미지원) + `⋮`(EllipsisVertical) 메뉴.
- **BottomTabs**: 셋업 화면·H9 진상 공개·O7 카운트다운 중에는 숨김. 플레이어는 첫 탭 라벨이 `지금`(Footprints), 방장은 `진행`(Landmark). `내 패` = `Contact`, `단서함` = `ScrollText`.
- **ActionBar 규칙**: "게임을 앞으로 미는 버튼"은 항상 이 자리(엄지 영역). 방장 본인의 플레이 액션(장소 고르기 등)은 본문 **인라인 버튼**으로 분리해 진행 버튼과 섞지 않는다.
- 탭 전환 시 모든 봉인 카드는 즉시 재봉인(§10).

### 6-3. 쓰기·읽기 규칙

1. **모든 상태 전이 직후 동기 저장**(작은 JSON, setItem 1회). `pagehide`에서 한 번 더 flush.
2. **저장 금지 목록**: 봉인 열림 여부, 사건 본문(역할 시트·단서 텍스트) — 본문은 언제나 `code`로 재계산한다.
3. 복원 시 봉인은 **항상 닫힘**. 토스트 "이어하는 중 · {n}번 자리 · {단계명}" 1.5초.
4. 타이머 복원: `running`이면 `remaining = endsAt - now`. 0 이하면 "끝" 상태로 복원하되 **징은 다시 울리지 않는다**. 되돌리기로 복원된 타이머는 **멈춤 상태**로 돌아온다(재개는 방장이).
5. 되돌리기 스냅샷: 방장의 **단계·하위단계·지목 입력·진상 비트·롤콜 체크** 변경 시 push. 타이머 멈춤/재개/+30초는 push하지 않음(직접 되돌릴 수 있으므로).
6. URL `code` ≠ 저장 `code` → O9. 같으면 자동 복원. `?as=host`는 저장이 없을 때만 방장 모드 생성.
7. `updatedAt`이 12시간 초과 → 자동 이어하기 하지 않고 삭제.
8. 다중 탭: `storage` 이벤트 무시, 마지막 쓰기 승(희귀 케이스).
9. `caseVersion` ≠ 현재 번들 버전으로 저장된 게임 → 복원하되 Banner(warn) "사건 내용이 갱신됐어요. 새 방을 권해요".

## 7. 서버 없는 동기화 · 결정론 · 데이터 구조 가정

### 7-1. 방 코드

```
형식      : 4자 시드 + 1자 인원  →  저장/URL '7F3K5', 표시 '7F3K-5'
시드 문자 : 23456789ABCDEFGHJKMNPQRSTUVWXYZ  (31종 — 0 O 1 I L 제외) → 31⁴ ≈ 92만
인원 문자 : 4 | 5 | 6
생성      : crypto.getRandomValues (방장 폰에서만, Math.random 금지)
검증      : /^[2-9A-HJKMNP-Z]{4}[4-6]$/  (입력은 대문자화·하이픈/공백 제거 후)
사건 표식 : caseTag(seed) = A[h % 16] + ' ' + B[(h >>> 4) % 16]  (h = hash32('gung:tag:' + seed))
            A = 달빛 새벽 안개 촛불 비단 옥빛 서리 먹빛 단풍 청자 봉황 대숲 눈발 금박 연기 은장
            B = 매화 난초 국화 대나무 학 나비 거북 사슴 연꽃 모란 소나무 까치 두루미 석류 목련 해태
```

### 7-2. 결정론 엔진 (`src/lib/gung/`)

- PRNG: `hash32` + `mulberry32` + `mix` — `src/lib/flight/rng.ts`와 **동일 알고리즘을 `src/lib/gung/rng.ts`로 복제**한다. (flight는 아직 미커밋 staged 상태 → import하면 배포가 flight에 묶인다. import 금지.)
- `Math.random`·`Date`·로케일 의존 금지. 같은 `(code, caseVersion)` → 모든 기기에서 같은 결과.
- 배정: `seats = shuffle(setups[n].cast, rng(mix(hash32(caseId), hash32(seed))))` — 자리 1~n에 역할 1:1. 방장도 무작위(자리 1이라고 특정 역할 고정 없음).
- 범인: `setups[n].culprit`가 단일이면 그 역할의 자리. 배열이면 시드로 1개 선택(변주 사건 — Phase 2 콘텐츠 대비).
- 단서: `getClue(round, placeId, seat)` = `clues[round][placeId]`가 1장이면 그 카드(같은 장소 = 같은 단서 — "나도 거기 갔는데 그 말 거짓이오" 플레이가 생김), 여러 장이면 `index = mix(hash32(seed), hash32(\`${round}:${placeId}:${seat}\`)) % len`.
- **화면 규약**: 개인 화면 컴포넌트에는 `ResolvedCase` 전체를 내리지 않는다. `getSheet(rc, mySeat)` / `getClue(...)` 결과만 props로 전달. 다른 자리 데이터는 P10(모두의 패)·H9/P9(진상)에서만 계산.

**판정 규칙(기본값 — 기획이 바꾸면 `scoring`/본문으로 덮음)**
- 개인 적중 = **1차 지목** 기준(재지목은 판결에만 쓰임).
- 판결: 1차 최다 득표가 단독 1위면 그 사람이 지목됨. 동률이면 동률 후보 대상 재지목 1회. 재지목도 동률 = 아무도 지목 안 됨. **지목된 사람 = 범인 → 검거, 그 외 → 도주.**
- 자리 비운 사람은 투표자·후보에서 제외.
- 동점 순위는 공동 순위.
