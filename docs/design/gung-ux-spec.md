## 0. 핵심 전제 — 서버 없이 "같은 사건"을 어떻게 공유하는가

이 게임의 모든 UX 결정은 아래 세 가지 기술적 전제 위에서 성립한다. 개발팀(프론트/백엔드)과 반드시 공유해야 할 가정이다.

### 0-1. 방 코드 = 시드 + 인원수 (하나의 문자열)

```
코드 형식:  7F3K-5
            └┬─┘ └┬┘
          4자 시드  인원수(4~6, 1자리)

- 4자 시드: 혼동되는 문자 제외(0/O, 1/I/L 미사용) 대문자+숫자 32종 → 가독성·오타 방지
- URL:  /gung?code=7F3K5   (화면 표시는 "7F3K-5"처럼 중간에 하이픈을 넣어 읽기 쉽게)
- 코드 하나 = (seed, playerCount) 튜플 전체. 별도의 "인원 입력" 단계가 필요 없다(브리프의
  "방 코드(시드+인원) 하나로 모든 폰이 같은 사건을 공유" 요구사항을 코드 자체에 인코딩).
```

### 0-2. 사건은 로컬에서 계산된다 — 서버 호출 없음

- 모든 폰은 같은 결정론적 함수 `generateCase(seed, playerCount)` 를 **각자의 브라우저에서** 실행해 동일한 결과를 얻는다(의사난수 시드 방식, `src/lib/flight/rng.ts`와 동일한 패턴의 시드 PRNG를 재사용 제안).
- 함수 출력: 역할 배정표(자리 1~N → 역할), 진범 자리, 라운드별 장소-단서 매핑, 그날 밤 타임라인, 자리별 개인 미션.
- **중요한 함의**: 이 함수는 사실 모든 폰에서 "모든 사람의 모든 정보"를 계산할 수 있는 순수함수다. 비밀이 지켜지는 이유는 서버가 숨겨서가 아니라 **UI가 "내 자리" 슬라이스만 화면에 그리기로 약속했기 때문**이다(UI 컨벤션에 의한 비밀, 암호학적 비밀 아님). 유일한 예외는 게임 종료 시점의 "진상 공개" 화면 — 그때는 의도적으로 전체 데이터를 그려서 보여준다. 이 경계(언제 전체를 보여주고 언제 내 것만 보여주는지)는 라우팅 레벨이 아니라 **화면 단위 약속**이므로, 개발 시 "내 자리 외 데이터는 렌더 트리에 아예 올리지 않는다"는 원칙을 지켜야 한다(React state에 다른 사람 데이터를 들고 있다가 개발자도구로 들여다보는 걸 막을 수는 없지만, 적어도 화면·DOM에 노출하지 않는다).

### 0-3. "방장"은 기술적 권한이 아니라 사회적 역할이다

- 서버가 없으므로 "이 사람이 방장이다"를 기술적으로 강제할 방법이 없다. 대신 **진입 경로**로 역할을 자연스럽게 분기한다.
  - `/gung` (코드 없이 진입) → "방 만들기" 선택 → 방장 화면 플로우로 진입. 방장은 자리 1번으로 고정.
  - `/gung?code=XXXX` (초대 링크로 진입) → 자동으로 플레이어 화면 플로우(자리 입력부터) 진입.
- 누구나 코드를 알면 이론적으로 방장 화면도 열어볼 수 있지만, UX는 "코드를 만든 사람 = 자연스럽게 방장 흐름을 타는 사람"으로만 설계한다. 권한 분리가 아니라 **진입 동선 분리**.

### 0-4. 모든 "여러 폰의 값을 하나로 모으는" 순간은 사람 목소리로 집계한다 — 구술 집계(Voice Tally) 패턴

서버가 없으니 여러 폰의 상태를 실시간으로 합산할 방법이 없다. 이 게임에서 "여러 사람 값 합산"이 필요한 세 지점(대기실 자리 확인, 투표 집계, 미션 성공 집계)은 전부 같은 패턴을 쓴다:

> **방장이 입으로 묻고 눈으로 확인하고, 방장 폰에 손으로 입력한다.** 플레이어 폰은 각자의 로컬 판단(내 자리, 내 투표, 내 미션 성공 여부)만 들고 있을 뿐, 서로에게 전송하지 않는다.

이 패턴은 3번 반복되므로(3·4·6-3·7-2절), 디자인 전체에서 일관된 인터랙션(큰 아바타 탭 그리드 + 집계 숫자 자동 합산)으로 통일한다.

## 1. 사용자 역할별 전체 플로우 + 화면 목록

### 1-1. 방장(Host) 플로우 — 10 화면

```
H1 홈
 │ [방 만들기] 선택
 ▼
H2 방 만들기 (인원 4~6 선택 → 코드 생성, 나는 자리1)
 │
 ▼
H3 초대 공유 (카톡 공유 카드 + 코드 큰 글씨 + 복사)
 │  (카톡 단톡방에 전송 → 플레이어 플로우 1-2로 분기)
 ▼
H4 대기실 (구술 집계: 자리별 roll-call 체크리스트)
 │ [전원 확인됨 → 브리핑 시작]
 ▼
H5 브리핑 낭독 (모두 같이 보는 긴 글, 방장이 낭독)
 │ [낭독 완료 → 조사 시작]
 ▼
H6 라운드 진행 ×3 (R1→R2→R3, 선택2분+토론7분 타이머 + 공용 단서 공개)
 │ [R3 완료 → 최종 변론]
 ▼
H7 최종 변론 (자리 순서 안내 + 1인당 1분)
 │ [변론 완료 → 투표]
 ▼
H8 투표 입력 (구술 집계: 셋 세고 지목 → 집계 매트릭스)
 │ [집계 완료 → 진상 공개]
 ▼
H9 진상 공개 (타임라인 재구성 + 범인 공개, 극적 연출)
 │ [공개 완료 → 점수]
 ▼
H10 점수·결과 공유 (스코어보드 + 구술 집계: 미션 성공 + 카톡 결과카드 공유)
```

### 1-2. 플레이어(Player) 플로우 — 8 화면군

```
P1 초대 랜딩 (카톡 인앱 브라우저, 사건 티저 + 코드 자동 입력됨)
 │ [입장하기]
 ▼
P2 자리 입력 (1~N 중 선택, 시계방향 확인 안내)
 │ [확인]
 ▼
P3 내 역할 비밀 카드 (꾹 눌러 보기 — 공개프로필/비밀/동선/거짓말/미션/말투, 범인은 +범행사실)
 │ (방장 "브리핑 시작" 구두 신호 대기 — H5와 동시에 다같이 봄)
 ▼
[라운드 게이트] "방장이 '○라운드 시작'을 외치면 눌러주세요"
 │
 ▼
P4 장소 선택 (해당 라운드 장소 1곳 탭, 확정 시 잠김)
 │
 ▼
P5 단서 카드 + 공개 여부 (받은 단서 확인 → 공개/비공개 토글 → 공개 시 낭독 유도)
 │ (R1~R3 반복, 라운드 탭으로 왕복 가능)
 │
 ├─▶ P6 내 단서함 (상시 접근 가능한 탭 — 지금까지 받은 단서 전체 + 공개여부 기록)
 │
 ▼ (R3 종료, 최종 변론 — 방장 음성 안내로 순서 확인만, 별도 화면 최소)
P7 투표 (내 지목 선택 → 잠김 → 방장에게 "제출완료" 화면 보여주기 또는 손가락 지목)
 │ (방장 "진상 공개 시작" 구두 신호 대기)
 ▼
P8 진상·결과 (잠금 해제 → 진상 공개 수신 → 내 결과: 맞음/놓침 + 미션 성공 자가체크 + 결과카드 공유)
```

### 1-3. 두 플로우의 접점 (구두 신호 지도)

| 시점 | 방장 화면 | 방장의 말 | 플레이어 화면 반응 |
|---|---|---|---|
| 대기 완료 | H4 | "자, 다 왔으니 시작합니다" | (반응 없음, 그냥 기다림) |
| 브리핑 종료 | H5 | "자, 조사 시작!" | P3 → 라운드 게이트 해제 |
| 라운드 전환 | H6 | "2라운드 시작!" | 라운드 게이트 탭 → P4(R2) |
| 토론 종료 | H6 타이머 종료음 | "자 이제 최종 변론" | 자연스레 P7 이전 대기 |
| 변론 종료 | H7 | "자 이제 투표, 셋 셀게요" | P7 투표 또는 손가락 준비 |

| 전체 종료 | H10 | "미션 성공한 사람 손!" | (각자 폰에서 이미 확인한 결과를 손으로 표현) |

## 3. 서버 없는 동기화 UX

### 3-1. 구두 신호 + 수동 라운드 이동

- 진행의 "시계"는 오직 **방장 폰의 타이머**뿐이다. 플레이어 폰은 독립 타이머를 갖지 않는다(복잡도·오차 누적 방지, 방장 음성이 유일한 진실원).
- 라운드 전환은 방장의 구두 선언("2라운드 시작!") → 각 플레이어가 **자기 폰에서 직접 "라운드 게이트" 버튼을 탭**해야 다음 콘텐츠가 열린다. 자동 전환 없음(통제감 유지, 늦게 반응해도 무방 — 2절 라운드 게이트 참조).
- 최종 변론처럼 순서가 중요한 구간은 방장 폰에 "지금 차례: N번" 큰 표시 + 진행 레일을 두고, 플레이어는 자기 폰을 특별히 조작할 필요가 없게 최소화(발언만 하면 됨).

### 3-2. 잠금 규칙 (soft lock)

- 플레이어 화면 상단에 항상 **라운드 탭 바**(R1 | R2 | R3 | 변론 | 투표)가 떠 있다. 아직 열리지 않은 미래 탭은 자물쇠 아이콘과 함께 탭 가능하지만 누르면 "아직이에요, 방장 신호를 기다려주세요" 토스트만 뜨고 진입은 막지 않는 **부드러운 잠금**이다(완전 차단이 아니라 안내).
- 과거 라운드 탭은 언제든 읽기 전용으로 재열람 가능(복기·알리바이 확인용) — 되돌리기 쉬운 설계가 "취했을 때 실수해도 안전"하다는 제약과 직결.
- "장소 선택"처럼 한 번 확정하면 되돌릴 수 없는 액션에는 반드시 확인 다이얼로그를 둔다("이 장소로 조사하시겠습니까? 라운드당 1곳만 가능").

### 3-3. 실수 복구

- 모든 전진 버튼 곁에는 암묵적으로 "뒤로" 동작이 보장된다(브라우저 뒤로가기 또는 화면 내 "이전으로" 링크) — 단, 이미 확정된 선택(장소, 투표)은 되돌리기가 아니라 **재확인 다이얼로그를 통한 명시적 변경**만 허용(실수 방지와 복구 가능성 사이의 균형).
- 자리 번호를 잘못 입력했을 때: P2/설정 아이콘에서 언제든 "자리 다시 고르기" 가능. 자리를 바꾸면 그 즉시 새 자리에 맞는 비밀 카드로 다시 계산되어 보여진다(결정론적이므로 위험 없음, 단 이미 진행된 라운드의 "내가 고른 장소·단서" 로컬 기록은 리셋된다는 경고 문구 노출).
- 라운드 게이트를 잘못 눌러 너무 일찍 다음 라운드로 가버렸을 때: 라운드 탭 바에서 이전 탭으로 다시 돌아갈 수 있으므로 치명적이지 않음.

## 5. 엣지 케이스

### 5-1. 늦게 온 사람

- 모든 플레이어 화면에는 자리 입력(P2) 직후 작은 **"지금 다른 사람들은 어디까지 왔나요?"** 셀프 동기화 선택지를 노출: [브리핑 중] [조사 1라운드] [조사 2라운드] [조사 3라운드] [최종 변론] [투표 중] — 선택하면 그 지점으로 바로 이동(라운드 게이트도 자동 통과). 서버 없이도 "방의 현재 위치"를 구두로 전달받아 바로 맞추는 핵심 장치.
- 늦참자의 비밀 카드·역할은 코드+자리 번호만 있으면 언제 계산해도 동일하므로, 늦게 들어와도 배정이 어긋나지 않는다(0-2절 결정론 덕).
- 대기실(H4)에서 5/5 미달 상태에도 방장이 "그냥 시작"할 수 있는 작은 오버라이드 링크를 제공(늦참 확정 시).

### 5-2. 폰 화면 꺼짐 / 배터리

- 게임 시작 시 가능하면 `navigator.wakeLock.request('screen')` 호출. 지원 환경이면 작은 "화면 꺼짐 방지 켜짐" 인디케이터 아이콘 상시 노출.
- 미지원 환경(일부 인앱 브라우저)에서는 1회성 배너: "이 브라우저는 화면 자동 꺼짐 방지를 지원하지 않아요. 폰 설정에서 화면 자동 잠금 시간을 늘려두는 걸 추천해요."
- 배터리가 완전히 꺼졌다 재부팅돼도, 페이지 재진입 후 **같은 코드 + 같은 자리 번호**를 입력하면 100% 동일한 역할·단서가 재생성된다(0-2절). 이 보장을 자리 입력 화면 하단에 작게 명시: "같은 코드·자리로 다시 들어오면 내용이 그대로예요."

### 5-3. 새로고침

- `localStorage` 키: `gung:{code}:seat`, `gung:{code}:roundPos`, `gung:{code}:clueLog`, `gung:{code}:vote`, `gung:{code}:missionCheck`.
- 새로고침 시 저장된 `code`와 URL의 `code`가 일치하면 자동 복원 + 가벼운 토스트("불러왔어요: 5번 자리, 조사 2라운드"). 불일치/빈 값이면 정상적으로 P1~P2부터 다시 시작.
- 비밀 카드·단서 내용은 복원되어도 **항상 가려진 기본 상태**로 되돌아간다(4절 자동 재가림 원칙과 일치 — 지속성과 보안을 둘 다 지킴).

### 5-4. 인원이 바뀜

- 인원(N)은 방 코드에 인코딩되어 있어 바꾸는 즉시 **완전히 다른 사건**이 생성된다. 따라서:
  - **브리핑 전**: 방장이 H2로 돌아가 인원을 바꾸고 코드를 재생성 — 비용 없음(아직 아무도 비밀 카드를 보지 않았으므로). H4 대기실에 "인원을 확정하면 바꿀 수 없어요" 경고로 사전 방지 유도.
  - **브리핑 후 노쇼 발생**: 그 자리는 "비워둔다"는 설정으로 인정하고 진행(host가 "그 사람은 급한 전동으로 처소를 비웠다고 합시다"처럼 인-픽션 처리를 멘트로 제안). 해당 자리의 단서는 그냥 아무도 받지 않은 채로 둔다. 방장은 선택적으로 자신의 폰에서 그 자리 번호를 "대리 열람"(설정 안쪽에 숨겨진 보조 기능, 길게 눌러 진입)해 이야기 완결성을 위해 참고할 수 있음 — 단 주변에 다른 플레이어가 보이면 스포일러 위험이 있다는 경고 문구 동반.
  - **도중 추가 인원 도착**: 코드가 이미 N으로 고정되어 역할표에 빈자리가 없으므로, 추가 인원은 "서기(기록관)" 관전 모드로 참여 — 비밀 역할은 없지만 타이머 보조·메모 역할로 즐길 수 있는 경량 화면 제공(설계 메모, 실제 화면은 UI 단계에서 확정).

### 5-5. 자리 번호 중복 입력

- 서버가 없어 기술적 중복 탐지는 불가능. 완화 장치 3단:
  1. P2 화면에 "번호를 소리 내어 확인하세요" 안내 문구로 사전 예방.
  2. H4 대기실 roll-call에서 방장이 중복 체크 시도하면 "이미 체크된 번호예요" 토스트로 1차 포착.
  3. P3 비밀 카드 상단에 자리 번호가 큼지막하게 항상 노출되어, 극 중 대화에서 번호가 어긋나면 금방 티가 나 자연스레 정정됨(게임 플레이 자체가 안전망).
- 언제든 "자리 다시 고르기"로 재입력 가능(3-3절).

### 5-6. 카톡 인앱 브라우저

- 뷰포트: `100vh` 대신 `100dvh` 사용(주소창 표시/숨김에 따른 레이아웃 요동 방지 — 이 레포 `/zombie`, `/rewind`와 동일 컨벤션 유지).
- Wake Lock API, Web Share API가 인앱 브라우저에서 불안정할 수 있음 — 상단 ⋮ 메뉴의 "다른 브라우저에서 열기"를 안내하는 1회성 팁 배너를 결과 공유 전후로 노출.
- Kakao 공유 SDK가 로드되지 않는 환경(예: 테스트 중 데스크톱 접근) 대비, "카톡으로 공유" 버튼 옆에 "링크 복사"를 상시 보조 버튼으로 병행 노출(단일 장애점 제거).

## 7. 접근성 (WCAG 2.1 AA)

### 7-1. 어두운 조명·술자리 맥락 보정

- 기본 다크 테마 대비는 AA 최소치(4.5:1 본문, 3:1 대형텍스트)를 **상회**하도록 UI디자이너에게 권고 — 어두운 술집 조명 + 음주로 저하된 시각 판단력을 감안해 실사용 난이도가 WCAG 기준 테스트 환경보다 가혹함.
- 본문 기본 폰트 크기 18px 이상, 비밀 카드·타이머 숫자는 24px 이상 권장.
- 모든 탭 대상 최소 48×48px(WCAG AA 44px 기준보다 상향) — "취해도 오조작 없는 큰 버튼" 제약 반영.

### 7-2. 색에만 의존하지 않기

- 투표 결과(맞음/틀림), 신호 상태 등 색으로 구분하는 모든 요소는 아이콘(✅/❌)과 텍스트 라벨을 항상 병행.
- 역할별 색상 코드(있다면)는 UI 토큰 설계 시 아이콘/이름 라벨과 함께 사용하도록 UI디자이너에게 전달.

### 7-3. 모션·깜빡임

- 진상 공개(H9)의 인장 스탬프·플래시 연출은 `prefers-reduced-motion: reduce` 시 즉시 최종 상태로 대체. 1초 내 3회 이상 점멸하는 효과는 사용하지 않음(광과민 발작 예방, WCAG 2.3.1).
- FLIP류 이동 애니메이션을 쓰는 곳이 있다면(예: 라운드 전환) 동일 가드 적용.

### 7-4. 정직한 한계 — 비밀 카드와 스크린리더의 긴장

- "꾹 눌러 보기"로 가려진 비밀 콘텐츠는 스크린리더로 접근 시 **소리로 크게 읽혀 비밀이 노출되는 역설**이 있다. 완전한 해법은 없으나 다음을 적용한다:
  - 비밀 콘텐츠 영역에 `aria-live`를 쓰지 않는다(자동 낭독 금지, 명시적 포커스+활성화해야만 노출).
  - 포커스 시 "주변에 아무도 없을 때만 이어폰으로 확인하세요" 안내를 스크린리더 사용자에게도 동일하게 제공(`aria-describedby`).
  - 그 외 모든 공개 화면(브리핑, 타임라인, 결과, 타이머, 투표 UI)은 제약 없이 완전한 스크린리더 지원을 제공해 전체 경험의 접근성을 담보한다. 비밀 유지와 완전한 음성 접근성은 이 장르에서 본질적으로 상충하므로, 이를 숨기지 않고 명시한다("접근성은 선택이 아니다"는 원칙을 "전부 아니면 전무"로 포기하지 않고 가능한 최대치를 적용).

### 7-5. 포커스 순서 (혹시 데스크톱 브라우저로 열렸을 때 대비)

```
홈/랜딩: 주 버튼 → 보조 버튼
자리 입력: 1→N 순서대로 자리칩 → 확인 버튼
비밀 카드: 탭 메뉴(공개프로필→비밀→동선→거짓말→미션→말투) → 꾹눌러보기 버튼
투표: 자리 목록(자기 자신 제외, disabled 명시) → 확정 버튼
```

## 8. UI·개발 핸드오프 노트

- **폰트 후보 제시(최종 선정은 @UI디자이너)**: 사극풍 디스플레이 서체는 한글 지원이 되는 Google Fonts 중 다음을 후보로 제안.
  - `Song Myung`(송명) — 필압이 느껴지는 붓글씨풍 세리프, 제목/로고에 강한 사극 톤.
  - `Nanum Myeongjo` Bold — 묵직한 명조, 브리핑 본문·타임라인 등 긴 텍스트에 가독성 양호.
  - `East Sea Dokdo` — 손글씨/서예 느낌, 개인 미션 카드·인장 스탬프 보조 텍스트 같은 포인트 요소에만 짧게 사용 권장(장문 가독성 낮음). `/rewind`의 `Nanum Pen Script` 활용 패턴과 유사한 포지션.
  - `Black Han Sans` — 두꺼운 임팩트형, "범인 확정" 같은 극적 1회성 타이틀에 후보.
  - 본문(UI 전반)은 기존 레포 컨벤션대로 Pretendard 계열 유지, 위 서체들은 타이틀·스탬프·낭독 화면 등 "장식적/극적 포인트"에 한정 사용 권장.
- **데이터 모델 가정(기획/개발 확인 필요)**: 용의자 6종을 `중전·후궁·내관·어의·상궁·별감(호위무사)`으로 임시 설정, 인원 4/5/6명에 따라 앞에서부터 사용(4명=중전~어의, 5명=+상궁, 6명=+별감). 장소는 라운드 공통 5곳(세자의 침전/내명부 처소/약방/수방/후원)으로 가정, 라운드마다 각 장소의 단서 내용만 교체. 최종 확정은 @기획 또는 콘텐츠 담당과 재검토 필요.
- **공용 단서 vs 개인 단서 구분**: 라운드 진행 화면(H6)의 "공용 단서 공개" 버튼은 장소 선택과 무관하게 모두에게 동일 노출되는 스토리 단서, 장소 선택으로 받는 단서(P5)는 그 장소를 고른 사람만 받는 개인 단서. 이 2트랙 구조는 케이스 생성 함수(`generateCase`)가 양쪽을 모두 산출해야 함을 전제로 한다.
- **투표 2모드**: "손가락 동시 지목"과 "각자 폰 비밀투표"는 플레이어 체감은 다르지만 방장 폰의 최종 집계 매트릭스 UI는 동일하게 수렴하도록 구현 — 모드 분기는 입력 경로만 다르게.
- **서기(기록관) 관전 모드**: 5-4절의 추가 인원 대응책, 상세 화면 설계는 미정(이번 스펙 범위 밖, 필요 시 후속 스펙에서 확정).
