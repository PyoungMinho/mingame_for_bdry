## 0. 결론

1. **694키 전수 검토, 169키 수정**(공통 16 · AWS 103 · Azure 50). 키·파라미터·자리표시자·구조 변경 0. 금지어 0, 시간 약속 0, '항목' 0.
2. **가장 큰 경향은 '판정보다 넓게 말하는 문장'을 좁힌 것**이다(R1·R3, 58건). 특히 이상 없음·해당 없음 사유 6곳이 실제 판정 조건보다 넓게 말해 '안전'으로 읽힐 수 있었다 — 예: AWS-STO-2 "버킷 n개 모두 공개 설정이 없음"(차단 4개가 켜진 **공개 정책 버킷도** 이상 없음이므로 거짓), AWS-KEY-4 "외부 계정이나 모든 주체를 믿는 설정이 없음"(ExternalId로 보호된 외부 신뢰가 있어도 이상 없음), AWS-KEY-2 "모두 45일 안에 사용"(만든 지 7일 안 된 **미사용** 자격증명도 이상 없음).
3. **사실이 틀린 문장 6곳을 공식 문서로 고쳤다**(R2 중 핵심): AZ-NET-1 오탐 설명이 거꾸로 서술됨(특정 IP만 막는 Deny는 포트를 막지 못한다 → 서브넷·NIC 두 NSG 평가로 교체), Azure `$web`가 "항상 공개"(→ 정적 웹사이트를 켤 때, 방화벽은 적용됨), AZ-STO-1 오탐 이유에 정적 웹사이트(→ 이 설정과 무관), AWS-MFA-1 "다시 수집하면 풀립니다"(→ 보고서를 최대 4시간 다시 씀), AZ-NET-1 "좁힌 뒤 문제가 없으면 삭제"(→ 서로 다른 선택), AWS-NET-1 오탐 "LB·VPN 뒤라면"(→ 실제 노출을 오탐으로 오해하게 함).
