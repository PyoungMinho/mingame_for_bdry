## 0. 요약

### 0-1. PM 질문 — "혼자서 즐기는 모드도 넣은 거니?"
**넣었다기보다, 게임 전체가 1인용이다.** 별도 '혼자 모드' 토글이 없고, 다인 모드도 없다. 방 코드·초대·계정·서버·투표 UI가 하나도 없다. 폰 한 대로 혼자 약 25분 플레이한다. 술자리 4~6인용인 /gung과는 정반대 용도다.
- 화면 반영(P0): 타이틀에 칩 3개 「혼자서」「약 25분」「가입 없음」을 둔다. 설정 하단에는 「혼자서 즐기는 1인용 게임이에요. 기록은 이 기기에만 저장돼요.」를 쓴다.
- 「형사 모드」(P1)는 난이도 모드(신뢰 3칸·힌트 없음)이고 다인 모드가 아니다. 지금은 `RULES[mode]` 상수와 props 확장 지점만 열어 둔다(§8-4).

### 0-2. 핵심 결정 10줄
1. **1인용 전제.** 타이틀 칩 「혼자서·약 25분·가입 없음」을 두고, 저장은 이 기기의 localStorage에만 한다. 다인 UI는 0이다.
2. **고정 틀.** 상단 HUD(허브 96px: 시계+12핍 / 인게임 52px: 숫자형 + 12칸 헤어라인)와 하단 탭바(집 안·사람·수첩)를 쓴다. 상단 세그먼트는 쓰지 않는다. 기준은 360px에서 계산한 폭 예산이다.
3. **색 의미 고정.** 앰버 = 행동 비용·주 CTA, 골드 = ★ 전용, 핑크 = NEW, 그린 = 무료·통했다, 레드 = 오답·위조·사이렌, 바이올렛 = AI 정정, 시안 = AI·정보다. 모든 상태는 아이콘+글자를 함께 쓴다.
4. **유료 행동은 항상 2탭.** 남은 행동이 3 이상이면 인라인 띠, 2면 확인 시트, 1이면 '마지막 행동' 시트를 띄운다. 마지막 행동 시트 문구는 대상 종류와 ★ 수에 따라 3가지로 바뀐다.
5. **조사.** 장면이 HUD와 레일 사이를 꽉 채우고, 대사는 말할 때만 아래에서 덮는다. 하단 핫스팟 레일로 모든 점에 닿는다. 해금 전 핫스팟은 아예 그리지 않는다. 간격 규칙(d ≥ 10)과 좌표 수정 2곳이 있다.
6. **심문.** 하단 패널이 [줄 카드·◀▶·추궁/증거 제시] 모드와 대사 모드를 오간다. 증거 시트는 맨 위에 대상 줄을 고정하고, 푸터에 슬롯 A/B와 버튼을 둔다.
7. **판정 5종(★·◆·반쯤·우회·오답)은 글자·아이콘·모션·진동 4채널로 구분한다.** 반쯤과 우회에는 「감점 없음」 칩을 단다. 돌파 뒤에는 항상 결과 카드를 띄운다. 카드의 해금 목록은 돌파 전후 '열린 것'의 차이로 만든다.
8. **수첩.** 4탭(증거·인물·타임라인·의문)을 위에 두고, 의문 탭 아래에 '정리된 것'(`explain`)을 쌓는다. 힌트는 수첩 안에만 있다. `verified` 로그에는 태그를 달지 않는다(블라인드 검증본과 같은 정보량).
9. **저장.** 시스템 3-3 `RunState`를 그대로 쓰고 선택 필드만 더한다(`accuse`·`hintLog`·`seen`·`screen.tab/line/replay`). meta에는 `settings`·`coach`·`lastEnding`을 더한다. UI는 원시 필드를 읽지 않고 엔진 셀렉터만 호출한다.
10. **공유·폰트·템포.** 공유는 텍스트+`/witness` URL로 한다. OG 쿼리는 정수·열거형(g,s,e,r,k,v)만 받는다. 신규 폰트는 2종(Black Han Sans, Nanum Gothic Coding)이다. 글자 속도는 보통 36자/초 · 빠름 80자/초 · 즉시이고, 연출 합계 목표는 3분 이하다.

## 3. 레이아웃 규격

### 3-1. 공통 프레임
- 모바일 세로 우선. 점검 폭은 360 / 375 / 390 / 430px이고, 320px은 깨지지 않기만 하면 된다. 콘텐츠 최대 폭 `--wt-maxw: 480px`(모든 데스크톱), 가운데 정렬, 양옆은 비 오는 앰비언트 배경.
- 거터 16px, 4px 기반 스페이싱. `min-height: 100dvh`, 하단 `env(safe-area-inset-bottom)`.
- 쉘: `overscroll-behavior: contain`(당겨서 새로고침 방지), `touch-action: manipulation`(더블탭 확대 방지, 핀치는 허용), viewport `maximumScale: 5`.
- 높이가 내용에 맞춰 늘어나야 하는 박스(대사·줄 카드)에는 고정 `height`를 쓰지 않는다. `min-height`만 쓴다(WCAG 1.4.12, 글자 130%).

| 심문 | HUD 52 · 제목 줄 32 · 무대(flex, 최소 120·최대 420) · 하단 패널(내용 높이, 최소 300) | 무대 ≈ 140 | ≈ 167 | ≈ 314 |
| 증거 시트 | 78dvh: 핸들 16 · 대상 줄 52 · 탭+정렬 44 · 격자(스크롤) · 푸터 ≈ 140 | 격자 ≈ 245 | ≈ 270 | ≈ 380 |

- 심문 하단 패널(최소 300) = 줄 카드(헤더 24 + 본문 3줄 × 29 + 패딩 24 ≈ 135) + ◀▶ 줄 48 + 버튼 56 + 캡션 18 + 간격 24 + safe 16. 글자 130%에서는 줄 카드가 약 190으로 늘고, 무대가 최소 120까지 줄어든다.
- 대사 박스: 최소 높이 = 3줄 + 이름표(약 130px). 4줄이면 늘어나고, 그 이상(글자 확대)이면 패널 내부 스크롤.

### 3-5. 터치 · 한 손
- 최소 44, 기본 48, 주 버튼 56. 핫스팟 히트 영역 48×48(보이는 점 12px). 인접 간격은 12px 이상, 반대 의미 버튼 사이(제시 vs 나가기, 취소 vs 넘긴다)는 24px 이상.
- 주 버튼은 오른쪽. **왼손 모드**(설정)는 추궁/제시 바, 시트 푸터, 비용 프롬프트, 확인 시트의 버튼 순서를 좌우로 뒤집는다(`data-hand='left'` → `flex-direction: row-reverse`). 탭바 순서는 그대로 둔다.
- 스와이프·길게 누르기는 필수 경로에 쓰지 않는다(전부 버튼 대체 경로가 있다). 가장자리 20px 스와이프는 무시한다(iOS 뒤로 제스처).

```

  증언                       : 이 증언은 끝까지 할 수 있다.

── 보조(작은 글씨, ★ ≥ 3일 때만) ──

```
- 프롬프트가 떠 있는 동안 HUD의 곧 쓸 핍이 외곽선으로 깜빡인다(3회 후 정지).

### 5-5. 허브 (W10)
- **집 안**: 2×3 타일, 블루프린트 스킨. 배치는 집 구조를 따른다 — `[서재][손님방] / [거실][주방] / [옥상 정원][다용도실]`. 타일 ≥ 160×84, 타일 안에는 방 이름(Pretendard 800 15) + `ActionChip` + (NEW). 하단에 범례 `[무료][행동 1][잠김][NEW]` + `[List] 목록` 토글(설정에 기억). 목록 뷰(행 56px)는 스크린 리더용으로 항상 DOM에 있고, 지도 SVG는 `aria-hidden`.
- **목표 줄** 「목표 · 결정적 모순 3개를 깨면 지목할 수 있다」는 첫 ★ 전까지만 보인다. 그 뒤에는 접힌다(`ChevronDown`으로 다시 펼침).
- **사람**: 용의자 4명(S1→S4) 블록 + 또박이 블록. 인물 블록 = 원형 초상 56 + 이름 · 한 줄 소개 + 세트 행들. 또박이 블록은 초상 대신 스피커 + LED 링, 라벨 「증인」, 테두리 모양이 다르다(용의자가 아님을 시각으로 구분). 대질이 열리면 맨 위에 「대질」 섹션이 생긴다(두 초상 겹침 + 제목).
- 행동 ≤ 3: 상단 띠 대신 HUD `Siren` 아이콘 + 4초 토스트 「사이렌 소리가 가까워진다」(1회).

### 5-6. 조사 (W20) — `SceneView` · `HotspotDot` · `HotspotRail`
- 장면: viewBox **1500×1000** SVG 한 장. 표시 높이 = HUD와 레일 사이 전부, 폭 = 높이 × 1.5. 가로 패닝(`overflow-x: auto; touch-action: pan-x`, 스크롤바 숨김). 데스크톱은 드래그 + ←/→ + 양끝 쉐브론 버튼.
- 입장할 때 초기 스크롤은 아직 안 본 핫스팟 중심으로 간다. 화면 밖 핫스팟은 가장자리 배지 「◀ 2」로 알린다. 입장 직후 1회만 가장자리 쉐브론이 2번 넛지한다.
- **핫스팟 렌더 규칙**: `unlock` 미충족 → 렌더하지 않음(D09). 일반과 유머 핫스팟은 **똑같이** 그린다. 상태별 표시:

| 상태 | 점(보이는 12px, 히트 48) | 레일 칩 |
|---|---|---|
| 미조사 | 흰 점 + 시안 링, 퍼지는 링 3회 후 정지 | `● 라벨` |
| 기기 | 링 안 `Cpu` 12 | `Cpu 라벨` |
| 정밀 | 앰버 점선 링 + `ScanSearch` 14 + `+1` 칩 | `라벨 · 정밀 +1` |
| NEW(해금) | 핑크 점, 펄스 3회 | `라벨 · NEW` |
| 조사함 | muted 링 + `Check` 12, 펄스 없음 | `라벨 ✓`(Check 아이콘) |

- 레일(56px): 맨 왼쪽에 고정 [나가기], 이어서 진행 「3/5」, 그다음 x 오름차순 칩(높이 40, 최소 폭 72, 가로 스크롤). 칩을 탭하면 그 점으로 패닝(220ms)한 뒤 같은 조사를 연다. 레일이 키보드·스크린 리더의 정식 경로다.
- 대사 중: 장면 위 `--wt-scrim-scene`, 점·레일 입력 차단. 대사 패널은 아래에서 덮는다(최대 40%).
- 다시 본 핫스팟: 독백을 한 줄 요약으로 즉시 표시 + [수첩에서 보기]. 비용 0, 재획득 없음.
- 튜토리얼(W04): 첫 점(분필 선)만 활성, 나머지는 흐림. 증거 1개 이상이면 금색 아닌 **앰버** [브리핑 시작]이 레일 오른쪽 끝에 켜진다.

### 5-7. 기기 로그 시트 (W21)
- 흐름: 핫스팟 `lines`(독백·또박이 인사)를 대사 패널로 재생 → 끝나면 92dvh 시트가 열린다. **열리는 순간 증거 획득·저장**(D11).

- **진실 유형을 화면에 쓰지 않는다**(「기록」「해석」 칩 금지). 또박이 LED는 줄 `truth === 'refusal'`일 때만 레드(본문이 이미 거부를 말한다). 그 밖의 또박이 줄은 대기 시안이고, 대사(`Dialogue.face`)에 따라 바뀐다(UI 6-5 매핑).
- 순환: 마지막 줄 다음은 1번(토스트 「처음 줄로」 1.2초). 스와이프 임계 48px.
- 추궁: 그 줄 **첫 추궁에만** 컷인 「다시 말해 봐!」(350ms). 이후 추궁은 컷인 없이 대사를 즉시 표시(타이핑 생략)하고, 부수 효과는 없다. 결과 처리: 숨은 줄 → 토스트 「증언이 늘었다 · {n}번」 + [보러 가기](자동 이동 없음) / 메모형 증거 → W22 카드 / 의문 → 토스트 「수첩: 의문 1개 추가」 + 수첩 아이콘 점 / 새 핫스팟 해금 → 토스트 「{장소}에 새 단서 · NEW」.
- 대질(W34): 무대 2인(각 48% 폭). 말하는 쪽은 밝게(scale 1.03), 듣는 쪽은 brightness .6. 줄 카드 왼쪽 띠 = 화자 색 + 이름 텍스트. 또박이 쪽 초상에는 LED 상태 아이콘+라벨(§4-2)을 단다. 입장 컷은 대질 1이 1초, 대질 2가 2초('줄이기'에선 페이드). 비용 칩은 「무료」만 붙고 프롬프트는 없다.
- 체크포인트: 세트에 들어가기 직전 엔진이 `checkpoint`를 찍는다(시스템 3-3). UI는 진입 액션만 보낸다.

### 5-10. 증거 시트 (W31) — `EvidenceSheet`
```
┌ 핸들 ───────────────────────────── [X]
│ 이 줄에 낸다 ▸ 1/4 "저녁 뒤론 손님방에 있었어요…"    ← 대상 줄 고정(2줄 말줄임)
│ [증거 11] [인물 6]                      [ArrowUpDown 최근 ▾]
│ ┌─────┐ ┌─────┐ ┌─────┐   3열 EvidenceCard S(≈104×132), 간격 10, 스크롤
│ └─────┘ └─────┘ └─────┘
├───────────────────────────────────────
│ 선택: 순경의 초동 메모 — 22:39 발견. 사이드… [Info]
│ [A: 카드 미니 ×] [B: + 비어 있음]
│ [ 하나 더 겹치기 ]              [ 이걸로! ]   ← 두 장이면 [ 닫기 ] [ 함께 제시 ]
└───────────────────────────────────────
```
- 선택 규칙: 카드 탭 → 슬롯 A. A가 차 있으면 새 카드가 A를 교체한다. **B는 [하나 더 겹치기] 또는 슬롯 B 탭으로만 무장**되고, 무장된 뒤의 다음 탭이 B에 들어간다. 둘 다 차 있을 때 새 카드를 탭하면 B를 교체한다(D17). 선택한 카드를 다시 탭하면 해제된다.
- 정렬 기본은 **최근 획득순**이다(최근 / 시각 / 종류). 관련도 정렬·강조는 하지 않는다.
- 카드 상세: 길게 누르기(450ms) 또는 `[Info]` → W41(읽기 전용).
- 처음 3번 열 때 하단 안내 「두 장을 겹쳐 낼 수도 있다. 하나 고르면 [하나 더 겹치기]가 켜져요.」를 띄우고, 이후에는 `[Info]` 뒤로 접는다.
- 반쯤 맞음 직후 같은 줄에서 다시 열면 직전 카드가 슬롯에 남아 있고 슬롯 B가 1회 깜빡인다. 이 직전 선택은 UI 상태이며 저장하지 않는다. 줄을 깨거나 세트를 나가면 초기화된다.
- 제시 버튼은 첫 탭 직후 비활성(중복 제출 방지).
- **slot 모드**(지목 W51): 헤더 「수단 칸에 낼 증거」, 인물 탭 비활성(안내 「인물 프로필은 칸에 넣을 수 없다」), 슬롯 A/B 없음. 한 장 탭하면 바로 칸에 들어가고 시트가 닫힌다. 다른 칸에 있던 카드면 옮긴다(D25).
- 접근성: `role="dialog" aria-modal`, 카드 `role="checkbox"`(최대 2), 포커스 트랩, 닫으면 [증거 제시]로 포커스 복귀.

### 7-2. `RunState` — 시스템 3-3 그대로 + **선택 필드만 추가**(v는 1 유지, 없는 필드는 기본값으로 읽는다)
```ts
type ScreenName = 'intro' | 'rules' | 'hub' | 'location' | 'testimony' | 'accuse' | 'siren';
type RunStateUI = RunState & {
  mode?: 'normal';                                   // P1 형사 모드 확장 자리('detective'). 없으면 normal
  screen: {
    name: ScreenName; ref?: Id;                      // 시스템 원래 필드
    tab?: 'house' | 'people' | 'notebook';           // 허브 마지막 탭
    line?: number;                                   // 심문·대질 줄 인덱스
    replay?: Id;                                     // 직전 돌파 id — 판정 직후 닫았으면 W11부터 (UX R3)
  };
  accuse?: {                                         // 지목 초안 (UX R1)
    stage: 'suspect' | 'slots' | 'confirm';
    culprit?: Speaker; means?: Id; opportunity?: Id; motive?: Id;
    forced?: boolean;                                // 사이렌 강제 지목(경고 생략)
  };
  hintLog?: { text: string; target?: Id }[];         // ≤2, 수첩 정리 메모 재열람 (UX R6)
  seen?: Id[];                                       // 수첩에서 본 증거·의문 id — NEW 점 소거 전용, 규칙에 영향 없음
};
```
- 핫스팟 '조사함'은 엔진이 `visited`에 핫스팟 id(`'L0.h1'`)를 함께 넣는다고 가정한다. 엔진이 별도 필드를 쓰면 셀렉터 `isExamined`만 맞추면 된다(§8-2).
- 반쯤 맞음 직후 슬롯 유지·시트 정렬·패닝 위치는 **UI 상태(저장 안 함)**다.

### 7-3. `meta`
```ts

  bestGrade?: 'S' | 'A' | 'B' | 'C';

  settings: {
    speed: 'normal' | 'fast' | 'instant';
    text: 'm' | 'l' | 'xl';
    fx: 'auto' | 'full' | 'short' | 'reduced';
    haptics: boolean; leftHand: boolean; readFast: boolean;
    hubView: 'map' | 'list';
  };
  coach: CoachId[];                      // 본 코치마크
  lastEnding?: {                         // 제출 후 새로고침 복원 + 공유
    ending: EndingId; grade: 'S' | 'A' | 'B' | 'C';
    stars: number; evidence: number; wrong: number; hints: number;
    actionsLeft: number; playMs: number;
    missed: Id[]; unbrokenStars: number; hiddenTeaser: boolean;
    newAchievements: AchId[]; at: number;
    pendingView: boolean;                // true면 로드 시 엔딩 화면으로. 엔딩을 떠나면 false
  };
};
```
- 오인 체포 엔딩 id는 `wrong-${Speaker}` 한 형식으로 용의자 4명 모두에게 똑같이 정의한다. 특정 인물 id만 나열하면 빠진 사람이 범인이라는 스포일러가 된다. 도감의 오인 체포 칸(3)은 `Solution.culprit`을 뺀 나머지로 런타임에 만든다.

### 7-4. 복원 앵커
| 저장된 `screen` | 복원 화면 |
|---|---|
| `intro` / `rules` | 해당 컷·카드 처음 |
| `hub` | 마지막 탭(`tab`) |
| `location` | 같은 장소, 핫스팟 상태 유지. 대사 도중이었다면 그 핫스팟 대사 처음부터 |
| `testimony` | 같은 세트·같은 줄(`line`). `replay`가 있으면 W11 결과 카드부터 |
| `accuse` | `accuse.stage`의 단계에서 초안과 함께 |
| `siren` | W12 |
| run 없음 + `lastEnding.pendingView` | W60 엔딩 |
| 진입 시 저장 손상 / `v` 불일치 | run 폐기 + meta 보존. 타이틀에 1회 띠 「새 버전이라 이전 수사는 이어갈 수 없어요. 도감은 그대로예요.」 / 「기록을 읽지 못해 새 수사로 시작해요.」 |

### 7-5. 읽기·쓰기 규칙
- 모든 읽기·쓰기는 try/catch로 감싸고, 실패하면 메모리 폴백(gung `useGungNotes` 패턴 복제)으로 간다. 폴백 중에는 타이틀·설정 상단에 띠 「이 브라우저는 저장을 막고 있어요. 탭을 닫으면 기록이 사라져요.」(차단하지 않음). 게임은 끝까지 돈다.
- 첫 렌더는 저장을 읽지 않는다(SSR 일치). 마운트 후 1회 읽고 화면을 결정한다.
- 증거 획득·판정은 **연출 전에 저장**한다(연출 중 새로고침 = 결과 카드부터 복원).
- 엔딩 도착 = `meta` 갱신(endings·plays·lastEnding·achievements·secrets·bestGrade) → `run` 삭제.
- 두 탭 동시 실행은 마지막 쓰기가 이긴다. `storage` 이벤트 토스트는 P1.

## 8. 데이터 가정 · 엔진 계약

### 8-1. 전제
- **엔진과 사건 데이터는 시스템 설계서 3장 데이터 모델(`Evidence`·`Location`·`Hotspot`·`TestimonySet`·`Line`·`Break`·`Unlock`·`Solution`·`RunState`)을 그대로 따른다.** 판정 순서는 3-4(돌파 → 반쯤 → 우회 → 오답), 신뢰·되감기는 3-5, 비용은 2-1, 행동 0 처리는 2-5, 엔딩·등급은 4-2를 따른다.
- 엔진은 React 없이 테스트하는 순수 모듈이다(rewind 선례: `engine.ts` + `engine.test.ts` + `validate.ts`). **UI는 원시 배열(`visited`·`opened`·`freePass` 등)을 직접 해석하지 않는다.** 비용·상태·해금은 전부 엔진 셀렉터에서 받는다. 그래야 비용 규칙이 엔진 테스트 한 곳에서만 검증된다.
