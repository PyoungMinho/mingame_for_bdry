### 2-2. 실행 순서 원칙
1. **먼저 지금 상태를 고정**: `npm run type-check` → `npx vitest run`(전체) → 결과 수치 기록. 실패가 있으면 그것이 첫 버그다.
2. 리스크 순서: G0-4 유출 → 숨기기(PM 오라클) → 판정·시계·동시성 → 재접속 → 누수 → 화면 세부 → 문구·시각.
3. 기존 테스트가 이미 덮는 케이스는 "기존: 파일명"으로 표시했다. 실행자는 **새로 쓰지 말고 그 테스트가 실제로 기대 결과를 단언하는지 읽어서 확인**만 하고, 빠진 단언만 `qa/`에 보강한다.
4. 시간 의존 케이스는 실제 시간을 기다리지 말고 L1/L2의 가짜 시계로 경계값(±1ms)을 친다. L3에서는 대표값 1회만.
5. 클린 빌드(`rm -rf .next && npm run build`)는 dev 서버를 멈춘 뒤에 돌린다(같은 `.next`를 쓴다). 또는 `git worktree`로 분리.
