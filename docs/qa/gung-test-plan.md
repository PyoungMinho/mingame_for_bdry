## 0. 결론 먼저

- **판정: 조건부 릴리즈 불가.** P1 의심 버그 3건(BUG-01 범인 식별 단서, BUG-02 자리 비우기로 범인 캐기, BUG-03 인원 숫자 오타 미검출)을 고치거나 PM이 위험을 받아들이기 전에는 배포하지 않는다.
- 엔진(`src/lib/gung`)은 테스트가 촘촘하다. 배정 결정론, 라운드 잠금, 저장 화이트리스트, 공유 폴백은 기존 테스트로 덮여 있다. 반면 화면 레이어에서 범인이 새거나 결과가 어긋나는 경로와 실기기(카톡 인앱) 경로는 거의 비어 있다.
- 지금까지 찾은 의심 버그는 **33건**이다(P1 3 · P2 10 · P3 15 · 설계 리스크 5). BUG-01·03·04·05·06·07·08·09는 엔진 탐침 스크립트로 직접 재현했다(§4 "확인 방법" 칸).
- 원고와 디자인이 서로 다르게 정한 곳이 8군데 있다. PM이 정해야 한다(§5).

## 1. 테스트 범위

### 1-1. 포함

| 영역 | 대상 |
|---|---|
| 셋업 | S1 홈 · S2 방 만들기 · S3 초대 · S4 코드 입력 · S5 초대 랜딩 · S6 자리 고르기 · O9 이어하기 충돌 · 코드 오류 화면 |
| 방장 | H1~H10 전 단계, 되돌리기(↶·토스트), O1 단계 맞추기, O8 자리 비우기, 메뉴 |
| 플레이어 | P1~P10, T1 내 패, T2 단서함, O1, 자리 바꾸기 |
| 엔진 | 코드·표식(room), 배정(assign), 덱·공용/NPC(deck), 상태머신·지목·점수(game), 저장(storage), 공유(share), 데이터 검사(validate) |
| 서버 | `/gung/og/result` Edge 이미지 라우트, 정적 `public/gung/og.jpg` |
| 환경 | iOS·Android 카카오톡 인앱, iOS Safari, Android Chrome, 데스크톱 Chrome / 375×667 기준, 320px 최소 |
| 비기능 | 엿보기 방지(DOM 비노출), 스포일러 순서, 접근성, 저장 장애 내성, 화면 꺼짐 방지, 소리 |

### 1-2. 제외

- 서버 동기화: 서버가 없는 설계라 기기 간 실시간 일치 검증은 하지 않는다. "같은 코드 = 같은 결과"라는 결정론만 검증한다.
- 사건 콘텐츠의 추리 난이도와 공정성: 원고 6장의 몫이다. QA는 데이터가 원고와 글자 단위로 같은지만 본다(기존 `case-data.test.ts`).
- Phase 2 항목(코일향, 서기 모드, 범인 변주 콘텐츠). 단, 엔진의 범인 배열 분기는 기존 테스트로 덮여 있다.
- 부정행위 전면 차단: 번들에 사건 전문이 들어 있어 기술적인 사용자는 언제든 범인을 알 수 있다. 수용 리스크로 §4-3에 적는다.

### 1-3. 요청서 표기 정정

- 요청서의 `?r=`는 **구현에 없는 파라미터**다. 실제 계약은 `?code=7F3K5` + 선택 `&as=host`(방장 복구)·`&v=1`(사건 버전)이다(`src/lib/gung/room.ts:131-167`). `?r=`로 들어오면 홈으로 떨어져야 한다(JOIN-04).

## 2. 테스트 전략

### 2-1. 리스크 기반 우선순위

| 리스크 | 사용자 영향 | 우선 검증 |
|---|---|---|
| 범인이 진상 전에 드러남(어깨 너머·DOM·공유 카드) | 그 판 전체가 무너진다 | SEAL-01/09, RVL-02, SHR-03, OG-03, VOTE-03 |
| 기기마다 배정이 다름(코드 오타·버전 차이) | 조용히 게임이 깨진다 | ASG-02/03, ROOM-07/08, JOIN-05 |
| 진행 꼬임(더블탭·뒤로가기·새로고침) | 취객 환경에서 바로 터진다 | FLOW-03/09/12/13/15 |
| 판결·점수 오류 | 승패가 뒤집힌다 | VOTE-04~09/14, SCR-01/02 |
| 카톡 인앱 비호환 | 초대한 사람 대부분이 겪는다 | KKO-01~06, SEAL-13 |

### 2-2. 테스트 레벨

| 레벨 | 기호 | 도구 | 목표 |
|---|---|---|---|
| L1 단위 | U | vitest(node) `src/lib/gung/*.test.ts` | `src/lib/gung` 라인 커버리지 ≥ 90%(현 설정은 gung을 커버리지 대상에서 빼고 있다 → 실행 시 `--coverage.include=src/lib/gung/**`) |
| L2 통합 | I | vitest + @testing-library/react + jsdom (`GungApp.smoke.test.tsx` 방식: Date만 가짜, `tap()`은 1초 전진) | 핵심 플로우 100% |
| L2' 멀티기기 시뮬 | S | 엔진 하네스: 같은 코드로 방장 1 + 플레이어 n−1의 독립 `GameState`(독립 시계·독립 메모리 저장소)를 만들어 스크립트 진행 | 기기 간 결정론 |
| L3 실기기 | M | 실제 폰 4~6대(§6-3 매트릭스) | 핵심 시나리오 8개 |
| L4 라이브 | L | 배포 후 WebFetch/curl | OG·공유 카드·회귀 |

- 새 의존성은 들이지 않는다(레포 규칙 §12-3: `package.json` 무수정). Playwright 같은 E2E 도구가 없으므로 E2E는 S(시뮬) + M(실기기)로 대신한다.

### 2-3. 우선순위 정의

- **P0** 릴리즈를 막는다: 게임 성립, 스포일러, 데이터 결정론
- **P1** 핵심 플로우, 공정성, 데이터 유실
- **P2** 품질과 사양 일치
- **P3** 개선, 다듬기

"레벨" 칸 표기: `U/I/S/M/L` + `기존`(이미 자동화됨, 회귀만 확인) / `신규`(QA실행자가 작성)
