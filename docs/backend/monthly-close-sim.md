# 월마감 밸런스 시뮬 (G0-3) — 1만 판 × 2조건

- 실행: 2026-11-07 · API설계자 · `MC_SIM_GAMES=10000 MC_SIM_PRINT=1 npx vitest run src/lib/monthly-close/engine/simulate.test.ts` (약 65초). 기본 `npm test`는 2,000판씩만 돌린다.
- 방식: **실제 엔진**(createRoomState → joinSeat → place → fire → 검산 answer/advance → 힌트 → 경보 보고)을 그대로 구동. 가상 시계(차례마다 +8초), 시간 초과 없음. 시드 고정(`20261107`/`20261108`)이라 재현된다.
- 봇: 기획서 부록 B와 같은 정의의 "보통"(무작위로 쏘다 맞으면 상하좌우). 양쪽 실력 동일. 힌트를 가지면 3종(열·행·3×3 중 무작위 종류, 3×3은 미확인 칸이 가장 많은 곳) 중 하나를 쓰고, 값으로 후보 칸을 좁힌다/제외한다.
- 검산: 풀 수 있는 사람은 확률 p로 2~9초에 정답. 힌트 없는 판 p=0, 힌트 있는 판 p=0.6(실측 정답률 59.6%). 경보 켬(반응 ms는 0~4.5초 균등이라 약 1/3이 3초 초과로 실패 — 경보 로직 구동용 값이고 실제 실패율이 아님).

## 판정

- **통과**: 중앙값, 선공 편차(0.0~1.8%p), 상한 도달률.
- **한 항목 초과: 힌트를 더 받은 쪽 승률 61.2% > 60%.** 1.2%p 초과이고, 이 봇은 힌트를 항상 즉시 사용하며 정보를 완전히 활용한다. 사람은 이보다 덜 활용하므로 실제 수치는 낮을 가능성이 있다[추정]. 기획서 조정 기준("힌트를 더 많이 받은 쪽 승률이 60%를 넘으면 `HINTS_PER_GAME`을 다시 본다")에 해당하므로 **기획팀장 확인 사항**이다. 플레이테스트에서 실측한 뒤 판단해도 된다. 엔진은 `HINTS_PER_GAME` 상수 하나로 바뀌고 다른 코드 수정이 없다.
- 힌트가 있으면 판이 약 1라운드 짧아지고(17→16) 상한 도달이 거의 사라진다(2.5%→0.3%).
- 힌트 없는 판의 `moreHintsWinRate`는 정의상 없음.

## 참고

- 이 시뮬은 "사람이 검산을 풀어서 힌트를 받는" 확률을 p로 단순화했다. 실제 정답률·속도는 플레이테스트 몫(퀴즈 10초 안에 풀리는 비율이 30% 미만이면 `QUIZ_MS` 15초).
- 경과시간 비교·0.2초 동시 지급은 시뮬이 아니라 `engine/core.test.ts`의 결정적 케이스로 검증한다.

## QA 수정 재측정 (2026-11-08 · @백엔드팀장) — BUG-15·16 수정 후 + SIM-02 기획 판단

### 기획 판단(진행자) — SIM-02

**`HINTS_PER_GAME = 2` 유지.** G0-3 힌트 항목("힌트를 더 받은 쪽 승률 60% 이하")은 시뮬이 아니라 **출시 후 실측**으로 판정한다. 근거: `mc_matches.hints`(자리별 받은 힌트 수)·`winner_seat`, `is_test = false`만, 힌트 수가 다르고 승패가 갈린 판. **실측이 60%를 넘으면 `HINTS_PER_GAME = 1`로 내린다**(★ 상수 하나, 엔진 수정 없음). 시뮬 값(완벽 봇 61.2%, 사람 모델 53.2%)은 참고 범위로만 쓴다.

### 무엇을 바꿨나

- 엔진: 미뤄진 검산을 합치지 않고 라운드마다 하나씩(BUG-15), 경보 실패 쉼이 걸린 차례의 시간 초과가 그 쉼을 소진(BUG-16), 검산 확정 settleAt + 1ms부터(BUG-03). 상세 `docs/backend/monthly-close-qa-fixes.md`.
- 시뮬: 기존 조건은 접속이 늘 정상이고 시간 초과가 없어 BUG-15·16 경로를 아예 타지 않는다. 그래서 **잡음 옵션**(`SimOptions.noise`)을 추가했다 — 발사마다 30% 확률로 한 사람의 접속 신호가 6초보다 오래됨(그 발사로 시작하는 라운드는 출제 조건 불충족 → 미룸), 차례마다 5% 확률로 시간 초과. 잡음을 안 주면 난수 소비가 예전과 같아 **기존 3조건 수치는 완전히 동일**(아래 표가 위 D3 표와 같은 이유).

### 판정

- **BUG-16**: 수정 전에는 겹침이 생기면 **100% 2턴 손실**(쉼이 남거나, 둘 다 실패한 경우 같은 처리 안에서 바로 자기 차례를 skip)이었고, 수정 후 0. 1만 판당 약 150~170회(판의 1.5% 안팎)라 체감 빈도는 낮지만 규칙("같은 차례 최대 1턴")대로 됐다.
- **BUG-15**: 잡음 아래서 판당 검산이 2.836 → 2.848(perfect), 2.857 → 2.865(human)로 늘어 **잡음 없는 판(2.853 / 2.869)과 같은 수준**이 됐다. 차이가 작은 것은 합쳐지려면 한 회차가 다음 출제 라운드까지 4라운드 연속 미뤄져야 해서(30% 잡음에서 약 0.8%) 드문 경우이기 때문이다. 접속이 오래 끊기는 실제 판(한 사람이 몇 분씩 숨김)에서는 효과가 더 크다. 판당 검산이 3이 아닌 것은 판이 12라운드 전에 끝나거나 둘 다 힌트 상한에 닿아서다(기획대로).
- **G0-3 나머지 기준**(판 길이 15~22, 선공 편차 5%p 미만, 상한 5% 이하)은 잡음 조건 포함 전부 통과.
- **힌트 승률**: 잡음 조건에서도 perfect 59.3%·human 53.4%로 기존 판단과 같다. 위 기획 판단대로 **2 유지, 출시 후 `mc_matches` 실측 60% 초과 시 1로**.
