## 0. 판정 요약

**디자인 관점 Go.** 단, 아래 다섯 가지를 디자인 단계(STEP 3)에서 반드시 확정한다는 조건이다.

1. **화면은 셸 하나로 만든다.** 방 안의 배치, 대전, 퀴즈, 힌트, 경보, 결과, 숨기기는 모두 같은 스프레드시트 셸 안에서 셀 내용과 활성 시트 탭만 바뀌는 상태로 처리한다. 화면 틀이 한 번도 바뀌지 않아야 옆에서 볼 때 아무 일도 없어 보이고, 0.1초 전환도 쉽다.
2. **판 두 개는 분할 창 두 개로 나눈다.** 두 판이 한 열 머리글(A~H)을 함께 쓸 수는 없다. 그래서 창마다 머리글을 따로 두고, 판은 각 창의 A1:H8에 놓는다(§7 모순 1).
3. **숨기는 키와 돌아오는 방법을 다르게 한다.** Tab·ESC는 게임 화면에서 언제나 숨기기다. 숨기기 시트 안에서는 진짜 시트처럼 Tab은 다음 칸, ESC는 편집 취소로 동작하고, 돌아올 때는 아래 시트 탭을 클릭한다(§4, 기획팀장 확인 필요).
4. **루트 레이아웃이 물려주는 누수 6가지를 라우트 안에서 막는다.** 가장 위험한 것은 Tab을 누르면 켜지는 주황색 포커스 링과 탭 제목 뒤에 붙는 "| 문제팩토리"다(§2-5). 공유 파일은 수정하지 않는다.
5. **웃음 문구는 노출 등급과 길이 상한을 지킨다.** 메모는 마우스를 올렸을 때만 보이면 이름 상자로 쏜 사람과 도발을 받은 사람이 못 본다. 그래서 짧게 자동으로 띄웠다가 스스로 닫히게 한다(§3).

디자인 단계 소요는 파이프라인 기준 약 0.75~1일로 본다[추정]. 가장 큰 덩어리는 화면이 아니라 **업종 문구 묶음 3종**이다(§6).

## 1. 화면 구조 (IA)

### 1-1. 원칙: "셸은 하나, 바뀌는 건 셀 내용뿐"
- 라우트는 2개(홈, 문서)다. 문서(방) 안에서는 페이지 이동이나 화면 전체를 덮는 모달을 쓰지 않는다. 대화상자는 입장할 때 한 번만 쓴다.
- 업종 차이는 **글자뿐**이다(파일명, 시트 탭 이름, 항목 이름, 메모, 퀴즈 라벨, 숨기기 시트 데이터). 색, 배치, 컴포넌트는 3업종이 100% 같다. 그래서 업종을 추가할 때 디자인 비용은 0이고 문구만 든다.

### 1-3. 시트 셸 해부도 (PC, 창 안쪽 1366×640 기준)

```

- **분할 창 2개**: 왼쪽은 내 시트(내 항목 + 상대가 쏜 곳), 오른쪽은 상대 시트(내가 쏜 기록). 창마다 열 머리글 A·B·C…와 행 번호가 따로 있다. 판은 각 창의 A1:H8이고, I열 이후와 9행 이후도 빈 셀로 창 끝까지 이어진다. 기획의 "게임판 섬처럼 보이지 않게"를 이렇게 지킨다.
- **창 머리(24px)**: 차례는 게임 용어 없이 알린다. 내 차례면 오른쪽이 "상대 시트 · 편집 가능"이고, 상대 차례면 "상대 시트 · 읽기 전용(B님 편집 중)"이 되며 셀 선택을 막는다.
- **판 아래 빈 행 활용(진짜 시트처럼 표가 셀 안에 있다)**:
  - 10~13행 항목 표: 항목 이름(짧은 이름), 칸 수, 상태(정상 / 1건 반려 / 종결). 배 목록을 업무 표로 보여 준다. 상대 항목은 **내 업종 어휘**로 번역해 보여 준다.
  - 9행과 I열 = 합계 행·열: 열 힌트 결과는 그 열의 9행에(예: E9 = 2), 행 힌트 결과는 그 행의 I열에 값으로 남긴다. 셀을 선택하면 수식 입력줄에 `=COUNTIF(E1:E8,">0")`가 보인다. **수식 입력줄에 "→ 2"를 붙이지 않는다**(실제 시트 문법이 아님, §7-7).
  - 3×3 힌트: 범위에 점선 테두리를 두르고, 결과는 15행 이후 "검토 의견" 표에 한 줄로 남긴다.
  - 상대가 내 판을 조회한 기록(기획 §4 공정성)은 왼쪽 15행 이후 "변경 내역" 표에 중립 문장으로 남긴다("14:32 B님 E열 검토"). 웃음 문구는 넣지 않는다.
- **도구줄은 리본이 아니라 한 줄이다**(§2-2). 실제로 동작하는 버튼은 [공유], [의견 남기기 ▾](도발), [Σ](힌트 사용, §7-8), 배치 때 [자동 배치]·[배치 완료]뿐이다. 나머지 아이콘은 장식이고, 눌러도 아무 일도 일어나지 않는다.

### 1-5. 핵심 사용자 플로우

```

## 2. 시각 언어: "시트처럼 보이되 엑셀을 베끼지 않는다"

### 2-1. 쓰는 것 / 쓰지 않는 것

| 쓴다 (누구나 쓰는 시트 문법) | 쓰지 않는다 (기획 §6 + 디자인 추가) |
|---|---|
| 격자, 열 문자, 행 번호, 이름 상자, 수식 입력줄(✕ ✓ fx), 시트 탭, 상태줄, 셀 선택 테두리와 채우기 핸들, 메모 표시 삼각형, 텍스트 메뉴줄(파일·편집·보기…), 한 줄 아이콘 도구줄 | Microsoft·Excel·Google 이름과 로고, 초록 X 아이콘, 리본(탭 + 큰 아이콘 묶음), Office 전용 글꼴 파일(Calibri·Aptos 등) |
| 직접 그린 단색 선 아이콘(lucide-react, 레포에 이미 있음 [확인]) | **녹색 계열 전체**(색상각 약 80~170°). 엑셀 고유 녹색뿐 아니라 구글 시트도 녹색이므로 강조색으로 녹색을 아예 쓰지 않는다 |
| 운영체제 기본 한글 글꼴(맑은 고딕 / Apple SD Gothic Neo)을 이름으로만 지정 | Office 기본 테마 색(차트 파랑·주황 기본값), 엑셀의 "연한 빨강 채우기" 프리셋 값 그대로, ".xlsx"나 "- 스프레드시트" 같은 탭 제목 접미사 |
| 각진 모양(모서리 2~4px) | 둥근 카드, 그라데이션, 그림자 많은 카드 UI(게임 앱처럼 보임) |

목표는 기획대로 "구별할 수 없는 수준"이 아니라 **"5초 곁눈질 통과"**다. 틀은 흔한 문법으로 만들고, 고유 장식은 빼서 법적·시각적 거리를 둔다.

### 2-2. 리본 대신: 메뉴줄 1줄 + 도구줄 1줄
- 리본은 탭을 누르면 큰 아이콘 묶음이 바뀌는 2단 구조다. 이 구조를 쓰지 않는다.
- 대신 **텍스트 메뉴줄(28px)과 단색 아이콘 도구줄(36px)**을 둔다. 웹 문서 앱과 데스크톱 앱이 공통으로 쓰는 형식이다. 아이콘은 8~10개로 제한한다: 되돌리기, 다시 실행, 확대 비율, 글꼴, 크기, 굵게, 기울임, 밑줄, 테두리, 채우기, 맞춤, Σ.
- 메뉴줄을 눌렀을 때 드롭다운을 만들지는 MVP에서 선택 사항이다. 만든다면 "도움말 > 인수인계서(규칙)" 하나만 실제로 동작하게 한다.

### 2-4. 셀 상태 인코딩 (흑백으로 봐도 글자로 구분됨)

| 상태 | 채움 | 셀 글자 | 표시 |

| 내 항목(내 시트) | 연노랑 `#FFF3BF` | 짧은 이름 2~3자("법카") | 조건부 서식처럼 보임 |
| 해당 없음(빗나감) | 회색 `#EEF0F2` | `0`(흐린 글자) | 데이터 칸처럼 읽힘 |

| 선택 | — | — | 2px 강조색 테두리 + 채우기 핸들 |

- 기획 스케치의 "침몰 = 진빨강"은 **중간 빨강으로 낮춘다**. 칸 4개가 진빨강으로 이어지면 주변 시야에 걸린다(A-5 "굵고 큰 빨간 글씨 금지"와 같은 취지). 반려와 종결은 채움 진하기뿐 아니라 **글자(`1` → 짧은 이름)와 삼각형**으로도 구분되므로 색약 사용자도 읽을 수 있다.
- `0`/`1`을 쓰는 이유: 칸에 글자가 있어야 데이터 시트처럼 읽힌다. 또 힌트 수식 `">0"`와 의미가 맞는다.

### 2-5. 루트 레이아웃이 물려주는 누수 차단 (공유 파일 무수정, 라우트 안에서 처리) [확인 + 프론트 전달]

| # | 물려받는 것 | 위장에 미치는 영향 | 라우트 안 처리 |
|---|---|---|---|
| 1 | 제목 템플릿 `"%s \| 문제팩토리"` [확인: 루트 layout.tsx] | 탭 제목이 "월마감_v7 \| 문제팩토리"가 되어 **즉시 노출된다**. `title`을 문자열로만 주면 템플릿이 붙는다(flight 레이아웃 주석에 같은 경고가 있음 [확인]) | `title: { absolute: ... }` 필수. 방 안에서는 업종 파일명을 클라이언트에서 `document.title`로 다시 지정 |

| 4 | `body` 바탕 `#FAFAF7`, 줄 높이 1.6 | 셀 높이가 틀어지고 크림색 바탕이 비친다 | 셸을 화면 전체 고정(100dvh)으로 두고 바탕을 직접 칠한다. 셀 줄 높이를 명시한다 |
| 5 | 전역 스크롤바 4px 둥근 막대 | 시트 앱답지 않은 얇은 막대(권장 수준) | 셸 안 스크롤 영역에만 10~12px 각진 스크롤바. 문서 자체는 스크롤하지 않는다 |

## 3. 웃음 문구가 위장을 깨지 않게 하는 표기 규칙

### 3-1. 노출 등급 (모든 문구는 등급 하나에 속한다)

| 등급 | 자리 | 규칙 |
|---|---|---|
| 0 금지 | 숨기기 시트, 탭 제목, 링크 미리보기, 파비콘, 이름 상자, 열·행 머리글, 창 머리 | 웃음 문구 0개. 업무 문장만 |
| 1 상시 노출 | 판 셀의 짧은 이름, 항목 표, 시트 탭 이름, 파일명 | **제3자가 읽어도 업무 단어**여야 한다(검수 규칙 1). 긴 농담 이름은 여기 두지 않는다 |
| 2 잠깐 노출 | 셀 메모(자동으로 떴다 닫힘), 상태줄 문장, 검산 표 라벨, 경보 토스트 | 작은 글씨, 정해진 시간 뒤 사라짐, 길이 상한(§3-5) |
| 3 연 사람만 | 배치 표의 긴 항목 이름, 의견 남기기 목록, 결과 문서 본문, 메모 위에 마우스를 올렸을 때 | 가장 웃긴 문장은 여기에 둔다. 판이 끝났을 때나 본인이 연 순간에만 보인다 |

**가장 센 웃음(침몰 메모, 시말서)일수록 노출이 짧거나 본인이 연 자리**에 둔다. 비평 C5("웃길수록 눈에 띈다")에 대한 디자인 답이다.

### 3-2. 셀 메모 사양
- **모양**: §2-3 메모 상자. 최대 폭 220px, 12px / 줄 높이 1.45, 안쪽 여백 6×8px, 최대 3줄. 머리 줄에 작은 회색 글씨로 "B님 · 방금" 또는 "검토 결과"를 단다(진짜 메모처럼).
- **위치**: 해당 셀의 오른쪽 위 모서리에 붙인다. 창 오른쪽 끝에 닿으면 왼쪽으로 뒤집는다. 이름 상자, 수식 입력줄, 다른 창을 가리지 않는다. **한 창에 고정 메모는 최대 1개**, 화면 전체에 2개까지다.
- **자동 고정(기획 A-5 보완)**: "마우스를 올리면 보임"만으로는 이름 상자로 쏜 사람과 도발을 받은 사람이 메모를 못 본다. 그래서 결과가 나오는 순간 그 셀의 메모를 자동으로 띄운다.
  - 노출 시간 = 2.5초 + 글자당 0.07초, **3~7초 사이**(40자 기준 약 5.3초).
  - 시간이 다 되거나, 같은 창에 새 메모가 뜨거나, 다른 셀을 선택하면 즉시 닫힌다(사라지는 연출 없음).
  - 닫힌 뒤에도 삼각형이 남아 있어 마우스를 올리면 다시 볼 수 있다(등급 3).
- **종류별 표시**: 해당 없음은 회색 줄, 반려와 종결은 빨강 줄 + 삼각형, 도발(의견)은 강조색 줄 + 머리 줄에 보낸 사람 이니셜.

### 3-3. 상태줄 사양
- 12px, 보조 글자색, 한 줄 28자 이내. 웃음 문장(예: 승리 "모든 변경 사항이 저장되었습니다.")은 **5초 뒤 중립 문장으로 돌아간다**("준비", "편집 가능 · 00:14").
- 상태줄 문장은 반드시 시스템 메시지처럼 읽혀야 한다(검수 규칙 1).

### 3-4. 도발(의견 남기기)
- 도구줄 [의견 남기기 ▾]를 누르면 문구 8~10개 목록이 뜬다(13px, 업무 메신저 "빠른 답장" 모양). 쓸 수 없을 때는 비활성으로 두고 "2회차 뒤 가능"이라고 보조 글자로 적는다(3턴에 1번).
- 받는 쪽: 보낸 사람이 마지막으로 쏜 내 시트의 셀에 메모가 자동으로 뜬다(§3-2 시간 규칙). 상태줄에는 "B님이 의견을 남겼습니다"만 나온다(문구 본문은 메모에만).

### 3-5. 문구 길이 상한 (문구 묶음 작성 기준) [결정]

| 자리 | 상한 | 이유 |
|---|---|---|
| 판 셀 짧은 이름 | 2~3자(한글) | 64px 셀에서 넘치지 않음. 넘치면 바로 티가 난다(A-5) |
| 항목 표 이름 | 8자 | 병합 셀 3칸(192px) 안에 들어감 |
| 배치 표 긴 이름 | 14자 | "부장님 법카 내역"처럼 |
| 셀 메모 | 40자 | 3줄 이내 |
| 상태줄 | 28자 | 한 줄 |
| 검산 표 라벨 | 24자 | 병합 셀 한 줄 |
| 경보 토스트 | 20자 + 단축키 칩 | 한눈에 읽혀야 3초 안에 반응할 수 있다 |
| 파일명 | 18자 | 탭 제목에서 잘리지 않는 길이 |
| 시트 탭 이름 | 4자 | |

모든 웃음 문구는 일반 굵기·본문색·12~13px로 쓴다. 빨간 글자, 굵게, 느낌표 연속, "ㅋㅋ", 이모지는 금지다. "^^"는 업무 메신저 관용 표현이라 도발 문구에서만 허용한다.

### 3-6. 숨기는 순간 같은 프레임에 지울 것 (프론트 체크리스트)
고정 메모 전부, 상태줄 문장(숨기기 시트용 "준비"로), 수식 입력줄(숨기기 시트에서 선택한 셀의 진짜 수식으로), 이름 상자(숨기기 시트 셀 주소로), 열린 드롭다운(의견 남기기, 메뉴), 공유 패널, 알림 토스트, 검산 입력 포커스. **탭 제목과 상단바는 그대로 둔다**(바뀌면 그게 티다).

## 4. 숨기기 키와 위장 동작 사양

| 상황 | 동작 |
|---|---|
| 게임 화면(배치·대전·결과·연습)에서 Tab, Shift+Tab, ESC | 즉시 숨기기 시트로 전환. **포커스가 이름 상자나 검산 칸에 있어도, 드롭다운이 열려 있어도, 한글 조합 중이어도** 무조건 동작한다(조합 중이면 입력칸 포커스를 풀고 전환). 브라우저 기본 Tab 이동은 막는다 |
| Ctrl/Alt/Cmd + Tab | 무시한다(브라우저나 OS가 처리). 대신 창을 벗어나면 자동으로 숨는다 |
| 창 포커스 잃음, 탭 가려짐 | 자동으로 숨기기 시트. **돌아와도 숨긴 상태를 유지한다**(상사 앞에서 창을 다시 클릭했을 때 게임이 뜨면 안 됨) |
| 경보 토스트 클릭, 숨기기 시트 탭 클릭 | 숨기기(마우스로 숨는 경로, 경보 판정에도 인정) |
| **숨기기 시트 안에서 Tab / ESC / 방향키 / Enter** | **진짜 시트처럼** 동작한다: Tab은 오른쪽 칸, ESC는 편집 취소. 게임으로 돌아가지 않는다 |
| **게임으로 복귀** | 아래 시트 탭에서 게임 탭(예: "월결산")을 클릭하거나 탭한다 |

**비대칭으로 정한 이유** [요청: 기획팀장 확인]
- 기획서는 숨기는 키만 정했고 돌아오는 방법은 정하지 않았다. PM 확정 사항(Tab 주 키, ESC 보조)은 그대로다.
- 숨기기 시트는 "클릭·방향키·입력이 되는 진짜 시트"여야 한다(A-5). 엑셀에 익숙한 사람은 값을 넣고 Tab으로 오른쪽 칸으로 간다. 이때 Tab이 게임으로 돌아가는 키라면 **상사 앞에서 시트에 숫자를 치다가 게임이 튀어나온다.** 숨기기는 급하고 복귀는 급하지 않으므로, 복귀는 의도한 클릭 한 번으로 충분하다.
- 덤으로 숨기기 시트 안에서 Tab을 누르면 칸이 오른쪽으로 움직이므로, 옆에서 보면 정말 시트 작업처럼 보인다.

**기타**
- 전환 속도: 게임 셸과 숨기기 시트를 둘 다 미리 그려 두고 표시만 바꾼다. 목표는 0.1초 이내다(G0-5). 서버에 보고하는 view_state는 결과를 기다리지 않는 비동기 전송으로 하고, **화면 전환이 서버 응답을 기다리면 안 된다.**
- 숨기기 시트에서 Ctrl+S를 누르면 "저장됨" 토스트를 1~2초 띄운다(A-5). 움직이는 칸은 현재 시각과 마지막 저장 시각뿐이다.
- 숨기기 시트 데이터는 실명이나 급여처럼 보이지 않게 한다. 인사·총무는 사람 이름 대신 팀 코드를 쓴다. 차트는 강조색 + 회색 막대로 그리고 Office 기본 차트 색은 쓰지 않는다.
- 접근성: 게임 화면에서는 Tab을 쓸 수 없으므로 방향키, Enter, 마우스로 모든 동작이 가능해야 한다. 홈은 표준 Tab을 유지하고, 안내 상자에 "시트 화면에서 Tab은 시트 전환 키입니다"를 적는다. MVP에서 받아들이는 제약이다.
- 한글 입력 상태에서 이름 상자에 "B7"을 치면 "ㅠ7"이 된다. 두벌식 자모(ㅁ ㅠ ㅊ ㅇ ㄷ ㄹ ㅎ ㅗ)를 A~H로 바꿔 받고 소문자도 받는다. 검산 칸은 `inputmode="numeric"`이다.
- 검산 확정은 **Enter만** 받는다. 엑셀 습관으로 Tab을 누르면 숨기기가 된다. 칸 안 흐린 안내 글자는 "Enter로 확정"이다.

## 5. PC 우선 + 모바일 처리

| 구분 | PC (≥1024px, 마우스) | 모바일 (<1024px 또는 터치 위주) |
|---|---|---|
| 판 | 분할 창 2개 동시 | **창 1개 + 아래 시트 탭 전환**: [내 시트] [상대 시트] │ [손익](숨기기 시트 탭, 구분선으로 떼어 놓음). 탭 높이 44px 이상 |
| 셀 | 64×24(56×24) | 정사각형 약 40~48px(360px 폭 기준 (360−24−16)/8 ≈ 40) |
| 크롬 | 상단바·메뉴줄·도구줄·이름 상자·수식 입력줄 | 상단바(파일명 + 공유) + 이름 상자·수식 입력줄 1행만. 메뉴줄과 도구줄은 생략하고, 도발과 힌트는 상단바의 [⋯]로 |
| 쏘기 | 선택 → Enter 또는 다시 클릭 | **탭으로 선택 → 같은 셀 다시 탭 또는 아래 [반영] 버튼(44px)**. 잘못 눌러 한 발 날리는 일을 막는다 |
| 메모 | 셀 옆에 뜨는 메모 | 마우스를 올릴 수 없으므로 시트 탭 바로 위 **"메모 줄"** 한 줄(13px, 최대 2줄, 같은 시간 규칙). 표시된 셀을 탭하면 다시 보인다 |
| 차례 전환 | 창 머리 문구 | 내 차례가 시작되면 [상대 시트] 탭으로 자동 전환. 상대가 쏜 결과는 메모 줄로("상대 검토: C4 해당 없음"). 내 시트로는 자동 전환하지 않는다 |
| 검산 | 오른쪽 창 10행 자리 | 창 맨 위에 고정. 숫자 자판이 올라와도 가리지 않게 한다 |
| 숨기기 | Tab / ESC / 토스트 클릭 / 탭 클릭 / 창 벗어남 | **[손익] 탭을 탭하거나 경보 토스트를 탭**. 앱 전환이나 화면 꺼짐도 자동 숨기기. 물리 키보드가 있으면 Tab·ESC도 동작 |
| 숨기기 시트(단순화 정의) | 30행×10열 + 차트 | 같은 데이터를 4열만 보이게 하고 가로 스크롤. 차트는 생략 |
| 경보 | 판 위 가운데 토스트 | 화면 위쪽 토스트. 판정 기준은 3초로 같음(A-3) |

- 모바일은 **"공유받은 링크를 폰으로 열었을 때 막히지 않는 수준"**이 목표다. 주 경험은 PC다. 홈에 "PC에서 더 잘 보입니다"를 한 줄 적는다.
- 가로로 눕힌 휴대폰도 모바일 배치로 처리한다. 세로 화면을 우선한다.

## 8. 다른 팀장에게 넘길 디자인 의존 사항

**프론트팀장**
- 라우트 레이아웃의 메타데이터: `title.absolute`, `robots noindex`, 아이콘·OG·themeColor 덮어쓰기. 스타일은 `monthly-close.css` + `.mc-shell` 범위에서만(flight·dongne·liar 선례).
- 키 처리는 문서 단위 캡처 단계에서 받는다. 게임 화면에서는 Tab·Shift+Tab·ESC를 무조건 가로채고(입력칸, IME, 드롭다운 포함), 숨기기 시트에서는 시트 키로 되돌려 준다.
- 게임 셸과 숨기기 시트를 둘 다 미리 그려 두고 표시만 바꾼다. 전환은 서버를 기다리지 않는다.
- 문서 수준 스크롤은 없다(셸이 100dvh 고정). 격자는 창별 스크롤 영역이다. 셀 수가 많지 않으므로(창당 약 10×30) 가상 스크롤은 필요 없다[추정].
- 셸을 먼저 만들어 G0-5를 앞당긴다(§6-1).

**백엔드팀장**
- view_state 보고는 빈번하고(숨을 때마다) 화면이 응답을 기다리지 않는다. 경보 판정용 ms 값은 클라이언트가 잰다(기획 A-3 그대로).
- 힌트 보유형 채택 시 보유 수를 공개 상태에 넣는다(값은 서버만).
- 종료 후 상대 배치 공개(채택 시).
- 의견 남기기 3턴 쿨다운은 서버가 판정하고, 화면은 남은 회차만 받는다.
- 재대결 요청·수락 상태(토스트 2개).

## 9. 기획팀장에게 확인 요청 (방향서에 넣어 주길 바람)
1. **숨기기 복귀 비대칭**(§4): Tab·ESC는 숨기기만 하고, 복귀는 게임 시트 탭 클릭으로 한다.
2. **힌트 보유형**과 검산 도중 숨기기 처리(§7-8).
3. **종료 후 상대 항목 공개를 P0에 넣을지**(§7-14).
4. **G0-6 규칙 4를 PM 몫으로 옮길지**(§7-18).
5. 기획서 표기 정리: "ESC 시트" → "숨기기 시트", 경보 표시 "[ESC]" → "[Tab]"(§7-2).
