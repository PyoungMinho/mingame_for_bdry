# 창의팀 제안서 (ROUND 2) — 월마감 (셀 좌표 해전)

작성: @창의기획자 (Sonnet) / 입력: R1 창의팀원 아이디어 60개, PM 확정 흐름, 진행자 힌트안
개정: PM 피드백 2건 반영 (1. 퀴즈 오답 규칙 수정, 2. 웃음 필수 요구 -> 8절 "웃음 장치" 신설)
원칙: PM 확정 흐름(업종 -> 방 번호 초대 -> 배 숨기기 -> 턴제 -> 힌트)은 그대로 두고, 비평이 짚은 리스크를 설계로 피한다.
톤 원칙: **"화면은 진지하게, 글은 웃기게."** 큰 애니메이션·소리는 위장을 깨므로 웃음은 전부 글자에서 나온다.

## 1. 핵심 아이디어 (3개)

1. **"화면 전체가 위장, ESC는 2차 방어"**. 가장 오래 노출되는 것은 게임 화면 자체다. 처음부터 "집행(내 판) vs 계획(상대 판)"을 나란히 놓은 업무 문서로 설계하고, ESC는 완전히 다른 대형 보고서로 갈아끼운다.
2. **좌표는 공통, 어휘와 농담은 각자 업종**. 판은 진짜 열 문자/행 번호(D5:K12)를 쓰므로 "F9"만 주고받는다. 업종 선택은 로컬이라 회계 직원과 영업 직원이 붙어도 각자 자기 업종 용어와 농담으로 본다. 네트워크로는 좌표·배 종류 번호·메시지 템플릿 번호만 오간다.
3. **"검산 요청" 퀴즈 -> 수식 힌트** + **"글로 웃기는" 문구 시스템**(8절). 퀴즈는 틀려도 재도전 가능(5절), 웃음은 셀 메모·결재 문구·시말서가 담당한다.

## 2. 제안 근거

- **빈 자리 확인**: Spreadsheet Solitaire(혼자 솔리테어 + 보스키), Battlesheets(구글 시트 공유 수작업), 국내 엑셀 위장 주식 사이트(보기 전용)는 있으나 "동료 1대1 실시간 + 위장 시트 + 힌트 + 업무 말투 개그" 조합은 R1 조사에서 못 찾음.
- **위장의 원리**: 스프레드시트에서 숫자 한 칸은 가장 평범한 물체이고, 이름 상자에 "F9" 입력 후 Enter는 실제 업무 동작과 같다.
- **웃음의 원리**: "업무 말투로 쓴 전쟁"은 이미 /liar, /coffeeball에서 검증한 직장인 공감 코드다. 소리·움직임 없이 글만으로 웃기면 위장과 웃음이 충돌하지 않고 오히려 "웃음 참기"가 게임 경험이 된다.
- **Supabase 재활용 판단**: `src/lib/pae/useRoom.ts`는 `rooms/room_players/hands` 테이블과 패 규칙에 묶여 있어 그대로는 부적합. **패턴만 재활용**(클라이언트 생성, `channel('room-코드')`, broadcast, presence, 언마운트 시 `removeChannel`). DB 테이블 없이 Broadcast + Presence만 사용 -> **PM이 SQL 돌릴 일 없음**.

## 3. 화면 흐름 (각 화면의 "업무 화면" 변환)

| # | 화면 | 업무 화면으로 보이는 방식 |
|---|---|---|
| 1 | **업종 선택** | "새 문서 > 템플릿 선택" 갤러리. 카드 4장: 회계 월마감표 / 인사 연차현황 / 영업 파이프라인 / 물류 재고실사. 하단 회색 안내 한 줄("2인 공동 편집 문서입니다. 점심·휴게 시간에 사용하세요") |
| 2 | **방 만들기 / 입장** | 상단 "공유" 버튼 = 방 만들기 -> 6자리 "문서 ID" + "링크 복사". 입장은 "문서 ID로 열기" 입력 또는 링크(`/monthly-close/482913`, 링크 입장 시 업종 선택 먼저). 대기 중 "공동 편집자 대기 중...". 정원 2명, 3번째는 "읽기 전용: 편집 권한 없음" |
| 3 | **배 배치** | 좌측 "집행" 표에서 셀 범위로 배치(클릭 + R키 회전, 90초, "자동 배치"). 배치된 칸은 연노랑 채움(조건부 서식처럼 보임). 준비되면 상태바 "모든 편집자 준비됨" |
| 4 | **턴** | 우측 "계획" 표 셀 선택 후 Enter, 또는 이름 상자에 "F9" 입력 후 Enter. 내 차례 = 상태바 "편집 중", 상대 차례 = "다른 사용자가 편집 중". 타이머는 "자동 저장까지 00:14". 결과는 **셀 메모**(8절)로 표시 |
| 5 | **검산 요청 / 힌트** | 시트 하단에 "검산 요청" 표가 뜨고 합계 칸에 숫자 입력. 오답이면 칸에 `#VALUE!`. 승자는 우측 "검토 의견" 패널에 수식 힌트를 받음. 입력줄에 `=COUNTIF(E5:E12,">0")`처럼 실제 수식 표시 |
| 6 | **결과** | 졌으면 **시말서**, 이겼으면 **포상 품의서**(8-5절). 하단에 "결산 보고"(명중률, 소요 시간, 버전 v7)와 변경 내역 로그 |
| 7 | **재대결 / 공유** | "v8로 저장"(= 재대결), 상단 "이 문서 전적 2:1". "사내 메신저로 공유" = 시말서/품의서 이미지(P1) 또는 텍스트 복사(P0) |

**명중/빗나감 서식**(평범한 서식 변화만):
- 빗나감: 숫자가 회색으로 흐려짐 + 셀 메모 "반영 대상 아님"(8-2절)
- 명중: 연한 빨강 채움(조건부 서식 "기준 초과" 느낌), 숫자 유지 + 셀 메모
- 침몰: 진한 빨강 채움 + 모서리에 **빨간 삼각 메모 마커**. 마우스를 올리면 업무 말투 메모
- 번쩍임, 흔들림, 효과음, 큰 팝업 없음.

## 4. 판 규칙

| 항목 | 확정안 | 근거 |
|---|---|---|
| 판 크기 | **8x8** (진짜 열/행 주소, 예: D5:K12) | 10x10은 너무 길어짐 |
| 배 | 3척: 길이 **4 / 3 / 2** (총 9칸), 가로·세로, 겹침 불가, 맞닿음 허용 | 구조 단순, 업종 어휘 3개만 필요 |
| 승리 조건 | **먼저 배 2척 침몰시키는 사람 승** | 9칸 전부 맞히기는 후반이 지루함 |
| 라운드 | 라운드 = 두 사람 각 1발. 같은 라운드에서 동시 달성하면 **무승부** | 선공 이점 제거 |
| 상한 | 25라운드, 초과 시 명중 칸 수 비교, 같으면 무승부 | 장기전 방지 |
| 턴 제한 | **20초**, 초과 시 발사 포기(패널티 없음), **연속 3회 초과 시 부재 패** | 자리 비움 대응 |
| 자리비움 | 판당 1회 "다른 시트 확인 중" 60초 정지(상대에겐 "다른 사용자가 편집 중"으로 동일 표시) | 상사 접근 시 불이익 최소화 |
| 목표 시간 | **6~8분**(배치 90초 + 약 20라운드 + 퀴즈 3회) | 점심·휴식 1~2판 |
| 선공 | 방 코드 시드로 결정 | 서버 불필요 |

구현 전 **봇 간 시뮬레이션 1000판**으로 평균 라운드 수를 측정, 18~24라운드가 아니면 판 크기·승리 조건 재조정(예: 7x7).

## 5. 힌트 제도 확정안 (진행자 안 채택, PM 피드백 반영)

진행자 안(업무 계산 퀴즈 -> 먼저 정답자가 수식 힌트)을 기준으로 한다. 상식 퀴즈 비추천에 동의.

### 5-1. 퀴즈 규칙 (수정본)
- **시점**: 라운드 4, 8, 12 시작 시 총 3회. 둘이 같은 문제를 동시에 푼다.
- **오답**: 입력칸이 **3초 잠기고 셀에 `#VALUE!`가 표시**된 뒤 **다시 도전 가능**. 횟수 제한 없음. (기존 "틀리면 실격" 폐지: 한 번 틀리면 상대가 무조건 이기는 문제 해소)
- **제한 시간**: **10초**. 그 안에 먼저 정답을 입력한 사람이 힌트 1개. **아무도 못 맞히면 그 회차는 힌트 없음**.
- **동시 정답**: 호스트가 수신한 시각이 빠른 쪽이 승자.
- **속도 편향 점검**: 3초 잠금 때문에 "찍기 연타"는 손해이고 한 번 틀리면 상당한 시간 손실이다. 10초 안에 정답 경쟁이라 암산이 느린 쪽이 불리하긴 하지만, 이득은 힌트 1개(발사 턴 소비 없음)로 제한되고 총 3회뿐이라 영향은 작다. 봇 시뮬레이션과 플레이 데이터에서 퀴즈 승자의 승률이 60%를 넘으면 힌트 효과를 줄이거나 문제 난이도를 낮춘다.
- **난이도 고정**: 암산, 계산기, 실제 엑셀 모두 허용("직장인 특권"). 단, 10초이므로 문제는 암산 가능한 수준(예: 두 자리 수 4개 합).
- **유형 3종 무한 자동 생성**: 4개 금액 합계 / 공급가액 -> 부가세 10% / 두 값의 차액. 방 코드 + 라운드를 시드로 양쪽이 동일 문제 생성 -> 서버 불필요.
- **퀴즈 문장도 웃기게**(8-4절): "팀장님 이번 주 아아 결제 내역 합계는?" 등.

### 5-2. 힌트 종류 (승자가 선택)
승자가 3종 중 하나와 파라미터를 고른다(단순 보상이 아니라 판단이 들어간다). 발사 턴을 소비하지 않으며, 방어자 클라이언트가 자동 계산해 응답.
- A. `열 COUNTIF`: 선택한 열의 배 칸 수
- B. `행 COUNTIF`: 선택한 행의 배 칸 수
- C. `3x3 스캔`: 중심 셀을 고르면 그 범위의 배 칸 수(0~9), 범위가 노랗게 윤곽 표시

**버린 안**: IF 방향, OR 인접(P2 보류), 포인트 구매·상대 결재 승인형(느려짐), ±1 노이즈(초보에게 불친절).

## 6. 업종별 위장 시트

### 6-1. 첫 출시: 4종

| 업종 | 근거 |
|---|---|
| **회계 / 재무** | PM이 직접 언급. 월마감 표는 가장 전형적인 스프레드시트 |
| **인사 / 총무** | 연차표는 달력형 격자라 판 구조와 겹침. 전 직군이 아는 시트 |
| **영업 / 마케팅** | 고객사 x 주차 격자. 사용자 층 넓음 |
| **구매 / 물류** | SKU x 구역 격자. 숫자가 많아 숫자 위장이 쉬움 |

**보류**: 개발(번다운 - 스프레드시트 상시 사용층 아님), 근무표, 회의실 예약표(위장력 최고지만 공용 시트라 P1 5번째 후보), 점심 투표.
**제작 비용 절감**: JSON 설정 + 공용 격자 엔진. 설정 1개 = 어휘 사전 + 장식 표 + 퀴즈 문장 + 8절 문구 팩. 업종 추가는 반나절~1일(문구 팩 포함).

### 6-2. 판 머리글 / 배 이름 사전

| 업종 | 가로 머리글(8열) | 세로 머리글(8행) | 길이4 배 | 길이3 배 | 길이2 배 | 파일명 | 시트 탭 |
|---|---|---|---|---|---|---|---|
| 회계 | 4월~11월 | 현금, 매출채권, 재고, 선급금, 미지급금, 차입금, 매출, 판관비 | 부장님 법카 내역 4칸 | 미수금 3칸 | 출처 없는 영수증 2칸 | 월마감_최종_진짜최종_v7 | 손익 / 월결산 / 비고 |
| 인사 | 11/3(월)~11/12(수) 평일 8일 | 팀 코드 8개(T-101 등) | 퇴사 예정자 4칸 | 연차 몰아쓰기 3칸 | 반차인 척 조퇴 2칸 | 연차사용현황_v7 | 현황 / 신청 / 부서별 |
| 영업 | 1주차~8주차 | 고객사 8곳(A사~H사) | "곧 계약합니다" 4칸 | 견적만 3번째 3칸 | 연락 두절 2칸 | 파이프라인_v7 | 리드 / 단계별 / 목표 |
| 물류 | W1~W8 구역 | 품목 코드 8개(SKU-101~108) | 어디 갔는지 모르는 팔레트 4칸 | 전산엔 있고 현물엔 없는 재고 3칸 | 반품 2칸 | 재고실사_v7 | 실사 / 입출고 / 발주 |

- 배 이름은 로컬 표시용(상대가 다른 업종이어도 침몰 알림은 내 어휘로 번역: 배 종류 번호만 오감).
- 셀 숫자는 방 코드 시드로 만든 그럴듯한 금액/수량. 배 칸 여부와 무관하게 값 분포 동일.
- 열 문자(A~)와 행 번호는 시트 크롬에 그대로 두고 판이 그 위에 놓임 -> "F9"가 화면 주소와 일치.

### 6-3. ESC 위장 시트 ("오래 봐도 티 안 나는" 장치)
1. **진짜처럼 동작하는 격자**: 셀 선택, 방향키, 타이핑 후 Enter로 수정, SUM/AVERAGE 재계산. 클릭해 봐도 반응한다.
2. **정합성**: 소계와 합계가 실제로 맞게 생성. 시트 1장당 약 30행 x 10열 + 간단한 막대 차트 1개.
3. **움직이는 곳은 원래 움직이는 곳만**: 환율/시세/현재 시각 셀, "마지막 저장 14:32"와 몇 분마다 한 번 도는 자동 저장 아이콘, 커서 깜빡임. 본문 숫자는 자동으로 안 바뀐다(R1의 숫자 미세 변동은 본문에서는 오히려 이상해 보여 철회).
4. **Ctrl+S**: 브라우저 저장창을 막고 "저장됨" 토스트 1~2초.
5. 스크롤바 위치, 고정 머리행, 하단 "준비" 텍스트, 줌 100%.
6. **ESC 시트 안에서는 웃음 문구 없음**: 위장 시트는 100% 진지하게(들키는 순간을 대비).

### 8-4. 퀴즈 표도 웃기게
문제 문장 후보를 업종별로 20개 이상 준비하고 숫자 4개만 시드로 바꾼다. 문제 자체는 진지한 표 형태.
- 회계: "팀장님 이번 주 아아(아이스 아메리카노) 결제 내역 합계는?" / "야근 식대 4건 합계는?" / "회식 2차 영수증 4장 합계는? (1차 제외)" / "탕비실 간식 구매 4건 합계는?"
- 인사: "이번 주 팀 연차 사용일 합계는?" / "금요일 반차 4건 합계(시간)는?" / "회의실 예약 취소 4건 합계(분)는?"
- 영업: "'곧 계약합니다'라던 고객 4곳 견적 합계는?" / "이번 달 접대 4건 비용 합계는?" / "미팅 후 '검토해보겠다' 4건의 금액 합계는?"
- 물류: "분실 의심 박스 4건 수량 합계는?" / "재고 실사 불일치 4건 수량 합계는?" / "택배 파손 신고 4건 합계는?"
- 부가세: "공급가액 {N}원, 부가세(10%)는?" 앞에 "(대표님 개인 지출 아님)" 같은 한 줄 주석.
- 오답 시 셀에 `#VALUE!`, 입력칸 옆에 한 줄 메모: "다시 확인해 주세요." / "계산기 쓰셨나요?" / "숫자가 마음에 안 드시나 봅니다."

### 8-5. 결과 화면 -- 시말서 / 포상 품의서
결과는 **문서 양식**으로 나온다(공유 이미지는 P1, P0은 텍스트 복사).

**시말서(진 사람)** -- 본문 템플릿(가변 변수: {이름}, {좌표}, {배 이름}, {라운드}):
> 시말서
> 소속/성명: {이름}
> 본인은 {라운드}라운드에서 {좌표}에 {배 이름}을(를) 방치한 중대한 과실을 범하였기에 이에 경위서를 제출합니다.
> 상기 건에 대해 깊이 반성하며, 향후에는 확인 주기를 단축하고 {좌표} 인근 셀을 사전 점검하겠습니다.
> 재발 시 점심 한 번 사겠습니다.
> 서명: {이름} (인)

변형 몇 가지: "본인은 상대의 힌트 요청 건을 선제 검토하지 못하여…", "본인의 마지막 한 발이 빗나간 책임을 통감하며…", "(법인카드 건과는 무관함)" 등.

**포상 품의서(이긴 사람)**:
> 포상 품의서

> 포상 내역: 오늘 점심 1회 (패자 부담)
> 결재선: {이름} -> {상대 이름} (반려 불가)

* 공유 시 **사내 메신저용 이미지**(문서 모양, 개인정보 없음, 이름은 입력한 닉네임만). 상대가 다른 업종이어도 각자 자기 업종 어휘로 양식이 나온다.

### 8-6. 결재 경보 -- "동시에 허겁지겁 ESC" 이벤트
- 판당 **1회**(라운드 6~16 사이 랜덤 시점, 방 코드 시드로 양쪽 동일)로 두 화면에 동시에 작은 배너 **"결재 요청 1건이 도착했습니다"** 가 뜬다(소리 없음, 모션 없음, 상태바 + 작은 배지).
- 둘 다 **가능한 한 빨리 ESC**를 눌러 위장 시트로 전환. **늦게 누른(또는 5초 내 안 누른) 쪽은 다음 턴 한 번 쉼**. 같은 시간이면 둘 다 영향 없음. 반응 시간은 각 클라이언트가 배너 표시 시점부터 재서 서로 교환(서버 불필요).
- 웃음 포인트: 둘이 동시에 화들짝 ESC를 누르고 위장 시트 안에서 눈치를 보며 복귀 타이밍을 재는 상황.
- 주의/완화: (1) 판당 1회로 제한, 설정에서 "결재 경보 끄기" 가능(P1). (2) 모바일은 ESC가 없으므로 "결재 올림" 탭 버튼으로 대체. (3) 배너 자체가 게임 화면 위에 뜨므로 모양은 일반 알림 토스트로 만들고, 문구는 업종별 4~5개 중 랜덤:
  - "결재 요청 1건이 도착했습니다. (긴급)"
  - "팀장님이 문서를 열람 중입니다."
  - "공동 편집자 1명이 추가되었습니다. (본인 확인 필요)"
  - "검토 의견이 등록되었습니다. 확인해 주세요."
- 이 이벤트는 실제 상사 접근을 가장하는 가짜 경보이므로 웃음 포인트이면서 ESC 습관을 만드는 훈련 역할도 한다.

### 8-7. 기타 소소한 글 장치 (P1)
- 상태바 랜덤 문구: "자동 저장 중... (취소 불가)", "계산 중... (사실 기다리는 중)", "마지막 편집자: {상대 이름}"
- 시트 탭에 "비고" 탭: 열어보면 규칙 요약이 업무 인수인계 문서 말투로 적혀 있음("인수인계서: 1. 배는 총 3척입니다. 2. 본인의 배는 본인만 압니다...")
- 문서 전적 "2:1"이 되면 상단 배너 "이 문서의 다툼은 아직 종결되지 않았습니다."

## 9. 동료 유입 · 재방문 장치

**P0(최소)**
1. **링크 초대 + 6자리 문서 ID**: 카톡/슬랙에 붙이면 업무 파일 링크처럼 보임. 로그인 없음.
2. **혼자 연습 봇 "박대리"**: 콜드스타트 해결. 같은 프로토콜을 로컬에서 수행해 테스트도 쉬움. 봇은 탐색 + 명중 후 인접 사격 1단계, 도발 템플릿도 보냄(웃음 체험 보장). 퀴즈는 6~12초 후 임의 응답.
3. **재대결 = "v8로 저장"** + 문서 전적 "2:1".
4. **결과 복사**: 한 줄 텍스트(시말서/품의서 요약) + 링크.

**P1**: 시말서/품의서 이미지 공유, 내기 메모 칸(자유 텍스트 1줄, "오늘 점심"), 5번째 시트(회의실 예약표), 판 종료 후 배치 공개 + 해시 검증, 파비콘 점 알림, 결재 경보 끄기 옵션.
**P2(검증 게이트 후에만)**: 부서 대항 주간 승률, 데일리 퍼즐, 봇 3단계, 관전, 추가 힌트, 시즌. 계정·랭킹·DB가 필요한 것은 전부 P2.
**하지 않을 것**: 알림, 계정, 랭킹, 수익 모델, 광고(Vercel 서브도메인은 AdSense 불가).

## 11. 실현 방안 / MVP 범위

### 아키텍처 요약
- 라우트: `src/app/monthly-close/`(+ `[room]/`), 로직 `src/lib/monthly-close/`.
- 실시간: Supabase Broadcast + Presence, 채널 `mc-{코드}`. 이벤트: `join`, `ready`, `fire(좌표)`, `result(결과, 배 종류, 메모 번호)`, `quiz_answer`, `hint_pick`, `hint_result`, `taunt(템플릿 번호)`, `alert_react(ms)`, `sync`, `rematch`.
- 권위: **방어자 클라이언트가 자기 배치로 판정**(서버 검증 없음, 친구 간 게임이므로 허용). 새로고침은 내 배치를 sessionStorage에 저장하고 접속 시 `sync`로 로그 교환.
- 순수 TS 엔진(배치 검증, 판정, 힌트 계산, 퀴즈 생성, 봇)을 UI와 분리해 단위 테스트. 문구 팩은 JSON(업종별).

### P0 (필수)
- 업종 선택 4종, 방 생성/입장(ID·링크), 정원 2명
- 8x8 배치, 턴제 발사(셀 클릭, 이름 상자), 20초 타이머, 승패/무승부
- 검산 퀴즈 3회(오답 3초 잠금 `#VALUE!` 후 재도전, 10초) + 힌트 3종
- 업종별 어휘/배 이름/**셀 메모 문구 팩** 4종 + ESC 위장 시트 4종(동작하는 격자)
- **도발 템플릿, 시말서/품의서(텍스트), 결재 경보 1회**
- 위장 규칙 전부, 봇 1단계, 재대결(v8) + 전적, 모바일 탭형 레이아웃
- 테스트: 엔진 단위 테스트 + 봇 시뮬레이션(평균 라운드 18~24 확인)

### P1 / P2
위 9절 참고.

### 빌드 규모 (대략)
- 파일 약 30개, 코드 약 4,000줄(엔진 400 + 테스트 300, 실시간 프로토콜 350, 격자 렌더러 500, 배치/발사 UI 450, 퀴즈·힌트 350, 위장 시트 엔진 400, 문구 팩 JSON 4종(콘텐츠 ~250항목), 결과 문서/도발/결재 경보 250, 랜딩 150, 봇 200).
- **콘텐츠 작성이 코드만큼 큰 비용**: 문구 팩이 웃음의 품질을 좌우하므로 코드와 별도로 카피 검수 시간 필요.
- 새 라우트 단독, 공유 파일 수정 없음, Supabase 테이블/SQL 없음. 파이프라인 기준 약 2일 규모.

### 검증 게이트(출시 후 2주 제안)
- 방 생성 대비 완주율 60% 이상, 재대결률 40% 이상, 링크 입장 대비 첫 판 완료 50% 이상.
- **웃음 지표**: 시말서/품의서 복사율(결과 화면 노출 대비 20% 이상)을 대리 지표로 사용. 미달이면 규칙보다 문구 팩 교체를 먼저.
