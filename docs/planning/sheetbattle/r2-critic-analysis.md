# 비평팀 분석 보고서 (ROUND 2, 비평기획자) — 시트 좌표 해전

PM 확정 사항(뒤집지 않음)
- 흐름: ① 업종 선택(위장 시트 결정) → ② 방 번호로 친구 초대(1대1 실시간) → ③ 각자 셀에 배 숨기기 → ④ 턴제로 쏘기 → ⑤ 중간에 힌트(퀴즈로 얻는 방식)
- 퀴즈 오답: 틀리면 3초 입력 잠금(#VALUE! 표시) 후 재도전 가능. 10초 안에 아무도 못 맞히면 힌트 없음.
- 웃음은 필수: "사무실에서 웃음 참으면서 하는 게임 느낌". 원칙 "화면은 진지하게, 글은 웃기게".
- 이전 초안의 "비동기 턴제"는 실시간 방 초대 확정과 충돌하여 "끊겨도 방이 유지되는 재접속"으로 낮췄다.

## 1. 리스크 우선순위

### 치명

**C1. 두 사람이 같은 시간에 같은 방에 들어와야 시작됨**
- 근거: R1 지적 2번.
- 대안: 방 번호(4~5자리, 말로 전달 가능)만으로 입장, 가입 없음, 닉네임 자동 부여. 방장은 대기 중 **배 숨기기를 먼저 끝낸다**(대기를 준비 시간으로). 방 30분 유지 + 끊김 후 같은 번호로 복귀(상태는 Supabase 저장). 턴 제한시간 기본 없음. 2명 차면 잠금, 입장 시도 횟수 제한, 만료.

**C2. 회사망 접속 불가 + vercel.app 공유 도메인 연좌**
- 근거: R1 지적 4번. 차단율 미확인. 팀 메모리상 vercel.app은 AdSense도 불가.
- 대안: 출시 전 서로 다른 회사 지인 3~5명에게 URL 열림 확인(5분). 3명 중 2명 이상 불가면 자체 도메인 먼저. 이 게임만 별도 도메인이면 기존 앱 파급 차단. 모바일 개인폰 경로 지원(H5). 웹소켓 접속 로그는 못 숨기므로 "안 걸린다" 보장 금지(H3).

**C3. 해전 본체의 재미(판 길이, 선공 유리, 힌트 균형)**
- 대안: 8x8, 배 3척, 목표 5~8분. 개발 전에 봇 대 봇 시뮬(개발 도구로만)로 길이와 선공 승률 측정. 선공 승률 55% 초과 시 후공 동점 라운드. 힌트는 2번에서.

**C4. 배 위치/퀴즈 정답이 클라이언트에 노출되는 구조**
- 근거: 상대 배 위치나 정답이 브라우저에 있으면 DevTools로 승패가 무의미. 동료와 노는 게임이라 위협은 낮아도, "상대가 DevTools를 열었다"는 한 번이 입소문을 끊는다.
- 대안: 판정, 힌트 계산, **퀴즈 정답 검증과 선착 순서 판정은 서버에서만**. 클라이언트에는 결과(적중/빗나감/힌트 숫자)만. /pae 방 구조 재사용 시 이 부분만 새로 설계.

**C5. [신규] 웃음이 곧 위장 노출 경로**
- 근거: PM이 "웃음 참는 게임"을 정체성으로 확정했고, R1 지적 4번(동료 둘이 동시에 웃음)과 정면으로 겹친다. 글이 웃길수록 옆사람이 화면을 쳐다볼 확률이 올라간다. 즉 이 게임은 설계상 "웃기려면 눈에 띄고, 눈에 띄면 위장이 깨지는" 모순을 안고 있다.
- 대안: 4번의 "웃음 선 긋기"에서 구체화. 핵심은 **제3자가 문장만 읽어도 업무 문서로 통하는 이중 의미 문장**을 최우선으로 쓰고, 웃긴 글을 크고 눈에 띄는 곳에 두지 않는 것.

### 높음

**H1. 위장이 티 남(소리, 반응, 동작)**
- 대안: 효과음 기능 자체 없음. 셀 동작은 화살표 이동·클릭 선택 테두리·수식줄·시트탭만 정확히, 리본은 장식("5초 곁눈질 통과" 기준). ESC 전환 시 프레임 유지, 셀 내용만 교체, 100ms 이내. 창 포커스 이탈 시 자동 위장. 새 이벤트 알림은 탭 옆 작은 점 하나(소리·진동 없음).
- **변경**: 이전에 제안한 "자유 입력 40자 셀 메모"는 철회. 이유는 4번(괴롭힘 위험): 실제 동료끼리 쓰는 채널에 자유 텍스트를 열면 모더레이션 비용과 괴롭힘 위험이 생긴다. **프리셋 문구 선택형 메모**(예: "검토 요청", "반려", "보류", "확인 부탁드립니다^^")로 대체하면 웃음 품질도 통제된다.

**H2. 업종 × 콘텐츠 제작비**
- 근거: 업종마다 필요한 것이 시트 데이터에 더해 **머리글, 배 이름, 적중/격침/빗나감 메모, 도발 문구, 퀴즈 라벨, 결과 문서**까지 늘었다.
- 대안: **엔진 1개 + 업종 데이터(JSON) N개**, 출시는 **3업종**(회계 / 영업·유통 / 총무·인사). 어느 회사에나 있는 보편 양식이라 양식 불일치로 들킬 위험이 낮고, PM의 "업종 고르기"를 충족하는 최소치. 문구량 추정: 업종당 40~60줄 + 공통 풀 → 총 150줄 안팎(추정). AI 초안 후 PM이 선별. 업종은 각자 자기 화면에서 고르며 상대와 달라도 된다(공유되는 것은 좌표/판정/퀴즈 숫자뿐).
- 품질 기준: 시트 합계가 실제로 맞을 것 / 스크롤 가능한 행 30+ / 가상 이름·가상 회사만 / 열 너비를 넘치는 단어 금지(넘치면 즉시 티).

**H3. 약속 과장과 평판**
- 대안: "안 걸린다/상사 몰래/보안 우회" 금지, "옆에서 보면 그냥 시트" 정도의 연출 묘사. 랜딩은 위장하지 않고 게임임을 분명히. 푸터에 "회사 규정 확인은 본인". 모니터링 우회 불가를 FAQ에 명시. 결재 경보(3-5)도 "실제 상사를 감지한다"는 인상을 주지 않게.

**H4. 상표/외관(법률 확인 필요, 8번)**
- 이름·아이콘·카피에 "Battleship" 금지. Microsoft Excel 이름·로고·녹색 X·고유 리본 형태 미사용, 격자·열머리·행번호·수식줄·시트탭 같은 범용 요소만. 파비콘은 중립 격자. 탭 제목은 앱 이름 없이 파일명 형태. 위장 수준을 "구별 불가"가 아니라 "5초 곁눈질 통과"로.

**H6. [신규] 웃음 문구의 괴롭힘/비하 오해** — 4번.

### 중간

- **M1. 힌트 수식이 수식줄에서 들킴**: 수식은 실제 엑셀 문법 형태로, 게임 용어 금지. 자동완성 선택 입력. 사용 후 수식줄 비움.
- **M2. 재방문 동기**: 재대결 버튼, 최근 공동 작업자. 웃음 문구는 반복되면 감쇠하므로 비복원 추출(한 판 안에서 같은 문구 재사용 금지, 가능하면 최근 3판 내 중복 회피). 랭킹/시즌은 게이트 통과 전 금지.

## 2. 힌트 제도(퀴즈형) 평가와 최종 규칙안

### 2-1. 진행자 안에 대한 판단
진행자 안(5턴마다 같은 업무 계산 퀴즈, 선착 정답자가 힌트 1개)은 **채택 권고**. 이유:
- "작은 표의 합계 구하기"는 옆에서 보면 실제 계산 업무로 보인다. 위장을 깨는 장치가 아니라 **강화하는 장치**. 수식줄 노출 우려(M1)도 줄어든다.
- 산술 퀴즈는 콘텐츠가 소모되지 않는다(숫자 랜덤 생성). 상식 퀴즈 비추천 판단에 동의(검색 가능, 콘텐츠 소모, 업종·연령 유불리).

### 2-2. PM 수정 규칙(3초 잠금 + 10초 만료) 평가
**좋은 점**: "한 번 틀리면 상대 승리"는 불합리하다는 PM 지적에 동의. 단순 오타 한 번이 승패를 가르는 형벌은 짜증 요소다. #VALUE!는 실제 엑셀의 오류 표시라 **옆에서 봐도 완전히 자연스럽고 그 자체로 웃음 요소**다(위장+유머 동시 해결).

**새로 생기는 위험과 보정**
1. **무작위 찍기 허용 가능성**: 실격이 사라졌으므로 재도전이 연속 가능. 10초 창 안에서 한 사람이 최대 약 3회(3초 잠금 포함)이므로 다자리 합계를 찍어 맞힐 확률은 낮다. 그래도 방어로 **잠금 단계 상승**(1회 오답 3초, 2회 오답 5초)을 권고. 구현 비용 작음.
2. **10초는 짧아서 "화면을 보고 있던 사람"에게 유리**: 위장 화면(ESC) 중인 쪽이 퀴즈를 통째로 놓친다. 그러면 시스템이 **위장을 사용한 사람을 벌주는** 구조가 되어 게임의 핵심 약속과 충돌한다. 보정: **퀴즈는 두 사람 모두 게임 화면일 때만 출제**, 한쪽이 위장 중이면 해제 후 다음 사격 턴으로 연기. 10초 타이머는 출제 시점이 아니라 두 화면 모두 렌더된 시점부터. 서버는 출제 시각 기록.
3. **10초에 맞춘 난이도**: 계산기 없이 5~8초에 풀리는 수준. 세 개 이하 1~2자리 숫자의 합/평균/개수/최대. 모바일 숫자패드 입력 시간도 고려. 플레이테스트 목표: 출제된 퀴즈의 50~70%가 창 안에 풀림. 30% 미만이면 창을 15초로 완화.
4. **"아무도 못 맞히면 힌트 없음"은 올바른 선택**: 힌트가 공짜로 풀리지 않아 정보 인플레를 막는다. 한 판에 힌트 0개로 끝나도 기본 게임이 성립해야 한다(C3 시뮬에 "힌트 0개" 케이스 포함).
5. **스노볼(빠른 계산자 독점)**: 유지해야 할 보정. 한 사람 최대 2개(시뮬 결과에 따라 3). **격차 상한**: 힌트 보유 차이가 1이면 앞선 쪽 정답은 인정하되 힌트 미지급. 서버 도착 순서 차이가 200ms 이내면 동시 정답으로 보고 둘 다 지급(드묾).
6. **오답 상황을 상대에게 알릴지**: 알리지 않는다. 노출하면 상대 정답 정보가 누출되고, 별도 놀림 소재가 되어 괴롭힘 오해 위험이 생긴다.
7. **업종 유불리 제거**: 퀴즈는 산술만, 업종어는 라벨(장식). 급여·실제 인사 정보를 닮은 숫자는 쓰지 않는다(직급 비교 연상 방지). 라벨은 정답에 영향을 주지 않을 것(애매한 단위·모호 표현 금지).
8. **힌트 종류 정보량 서열**: 행/열 COUNTIF < 3x3 스캔. 3x3은 **개수만** 반환(위치 비공개, 노란 칠은 스캔 범위 표시용), 2번째 힌트 이후에만 해금하거나 별도 비용. 조회한 범위는 상대 화면의 수정 이력에 남겨 정보 교환 균형.
9. **힌트 사용은 턴을 소모하지 않는다**(퀴즈가 이미 비용). 한 판 최대 개수는 시뮬 + 플레이테스트 전에는 확정하지 않는다. 첫 퀴즈는 3~5턴째 조정 여지.

### 2-3. 컴퓨터 대전 포함 여부(방 초대가 주 경로라는 전제)
**판단: 첫 출시에서 포함하지 않는다. 대신 AI 없는 스크립트 튜토리얼 판 1회.**
- 방 초대 흐름의 병목은 "상대가 오느냐"인데 봇은 이를 풀지 못한다.
- 퀴즈/힌트/결재 경보가 추가되어 봇이 이를 모사해야 하므로 범위가 커지고, 어설픈 봇은 학습 경험을 왜곡한다.
- 규칙 학습은 정해진 배치와 정해진 몇 수로 구성한 튜토리얼로 충분하다. 튜토리얼 문구도 웃음 톤을 시험하는 장소가 된다.
- 봇 판은 지표 오염도 없앤다.
- 재검토 조건: 입장 후 첫 수를 두는 비율이 70% 미만이거나 방장 대기 이탈이 많으면 "연습 모드"(난이도 1단계, 지표 제외)로 추가. 봇 대 봇 시뮬레이터는 밸런스 측정 도구로만 제작.

## 3. 웃음 장치 리스크 평가와 선 긋기

### 3-1. 전제와 목표
"화면은 진지하게, 글은 웃기게"는 올바른 원칙이다. 소리·큰 애니메이션 없이 웃기겠다는 것은 위장과 양립하는 유일한 방식. 다만 C5처럼 웃음 자체가 노출 경로이므로 **웃음 강도를 "속웃음(피식)" 수준에 맞추고, 문장은 짧게 설계**한다. 터지는 웃음은 막을 수 없으니 막으려 하지 않고, 사전에 FAQ/랜딩에서 "웃음 조심" 정도의 유머로 소화한다.

### 3-3. 웃음 문구 선(가이드라인, 제안)

허용
- 문서·결재·반려·회의·야근·메신저 말투 같은 **제도와 관습** 풍자
- 과장된 공손함, 서식·숫자 말장난
- 플레이어 자기 자신을 낮추는 농담(승자·패자 모두 같은 톤)
- 권위 풍자는 "부장님이라는 역할의 관습(결재 대기, 법카 정산)" 수준까지

금지
- 성별·나이·외모·출신·지역·장애·고용형태(인턴, 계약직 등) 비하
- 특정 직군을 고정관념으로 능멸("영업은 술만", "회계는 쪼잔" 류)
- 실존 기업·인물·브랜드·사건
- 성적 암시, 폭력, 갑질/괴롭힘을 정당화하거나 미화하는 톤
- **상대 플레이어를 직접 지목하는 모욕, 패배자 조롱**(상대 이름 삽입 금지, 2인칭 비난 금지)
- 자유 텍스트 입력(괴롭힘 채널화 방지, 프리셋만)

검수 규칙(출시 전)
1. 제3자 테스트: 문장 단독을 보여줬을 때 "업무 문서 한 줄"로 읽히는가(이중 의미 문장 비율을 높게 유지).
2. 괴롭힘 시나리오 테스트: 이 문장이 실제 상사→부하 또는 갑을 관계의 두 사람이 쓸 때 압박/조롱으로 읽히는가. 하나라도 걸리면 삭제.
3. 반복 감쇠 테스트: 같은 문구가 3판 안에 재등장하지 않는지.
4. 웃음 품질: 문구 40개를 5명에게 보여주고 "피식" 체크, 과반이 못 웃는 문구 삭제.

### 3-4. 웃음이 위장을 깨는 경우의 설계 방어
- 웃긴 글은 짧게(셀 한 칸 안), 굵게·빨갛게·깜빡임 금지.
- 가장 웃긴 문구는 사격 결과 메모 영역(작은 폰트), 크게 보이는 머리글은 업무 정석으로 유지.
- 승/패 순간에 화면 전체 연출 금지(결과 문서는 일반 시트처럼 열리고 ESC로 즉시 숨김 가능).
- 웃음 장치가 위장보다 우선하면 안 된다: 충돌 시 위장 우선. 이 우선순위를 개발 지침에 명시.

### 3-5. 결재 경보 상세 평가
원안: 랜덤으로 결재 경보가 울리고, 늦게 ESC를 누른 쪽이 한 턴 쉼.
- (a) **실력과 무관한 형벌**: 실시간 대전에서 랜덤 턴 상실은 승패에 직접 영향. 실력 게임(해전+퀴즈)에서 짜증 요소가 될 가능성이 크다.
- (b) **상대의 불로소득**: 한쪽이 쉬면 다른 쪽이 이득. 불공정 시비.
- (c) **ESC 반응 속도 게임으로 변질**: 위장 전환이 본 게임보다 중요해진다. 단, 이는 위장 연습이라는 장점이기도 하다.
- (d) **경보 표현**: 소리·화면 점멸 금지. 비강조 팝업 하나("결재 요청이 도착했습니다")여야 위장이 안 깨진다.
- (e) 경보가 실제 상사 감지를 암시하면 H3 위반.

**권고안**: 기본은 **보상형 경보**. 양측에 동시에 발동(판당 최대 1회, 5턴 이후, 퀴즈와 동시 출제 금지), 경보 후 N초 안에 ESC를 눌렀다 복귀하면 희귀 문구 해금/칭호 같은 **가벼운 보상**, 못 눌러도 **불이익 없음**. 벌칙형(한 턴 쉼)은 **양측이 합의한 "하드 모드"**에서만, 이는 후순위. 플레이테스트에서 경보 발생 판의 완주율이 미발생 판보다 10%p 이상 낮으면 경보를 제거한다.

## 4. 퍼지는 경로 단 하나
**방 번호(링크 포함)를 개인 DM 또는 구두로 한 명에게 전달하는 초대.**
- 이유: 게임이 1:1이므로 확산 단위가 쌍이다. 단톡/채널은 위장과 충돌, 커뮤니티 게시는 일회성. 방 번호는 짧아 미리보기 노출(R1 1번)이 적고 구두 전달도 된다(정책 위반 조장 평판과 표리이므로 H3 카피 규율 필수).
- 공유 이미지(시말서/품의서)는 **경로가 아니라 재방문·재초대 장치**. 확산은 여전히 "다음 동료에게 방 번호 전달"이어야 하며, 이미지는 그 동기 부여(웃음 자랑)로 보조한다.
- 설계: 종료 화면에 "다른 동료와도 한 판?" 새 방 번호 즉시 생성.
- 시딩은 확산 경로가 아닌 초기 점화: PM 주변 10~20명 + 직장인 커뮤니티 1곳 1회(게시 규정 미확인).

## 5. 인정할 점
- "B7" 셀 주소 = 좌표, 업종 고르기로 시작하는 첫 화면, #VALUE!를 오답 피드백으로 쓰는 점은 설명 없이 통하는 훅이다.
- 산술 업무 퀴즈는 위장과 게임성을 동시에 높인다. PM의 오답 규칙 수정은 게임을 더 건강하게 만든다.
- "화면은 진지하게, 글은 웃기게"는 위장 게임에 맞는 정확한 웃음 원칙이다.
- 서버 로직이 단순하고 개인정보 미수집, 업종 데이터는 /liar류 데이터 주도 제작과 같아 확장이 쉽다.
- 보스키는 40년 넘은 장르이므로 차별점은 "1:1 동료 대전 + 업무 말투 유머"에 있다.

## 6. 실패 사례 참고
- 보스키 장르가 오래됐다는 점(확인), Hasbro 클론 사례(본문 미확인), 사내 차단 소멸 사례(미확인).
- /pae의 방 생성 대비 2인 입장률 로그가 있으면 C1 사전 근거가 된다(이 보고서에서는 미확인).
- 이 팀의 /liar 경험: 직장 유머 문구 톤 가이드와 선별 방식이 이미 있다면 재사용(내용은 본 보고서에서 미확인).

## 7. 출시 전 반드시 확인 (게이트 0)
1. 회사망 접속 실측(지인 3~5명, 3명 중 2명 이상 불가면 자체 도메인).
2. 밸런스 시뮬: 봇 대 봇 1만 판. 중앙값 5~8분, 선공 승률 45~55%, 힌트 0개 케이스 포함, 힌트 더 많이 가진 쪽 승률 60% 이하.
3. 퀴즈 플레이테스트 5쌍 이상: 출제 퀴즈의 50~70%가 10초 안에 풀림, 퀴즈 선착 다수 쪽이 승리하는 비율 65% 이하, 3초 잠금이 짜증 요소인지 인터뷰.
4. 서버 판정 점검: 네트워크 탭에 상대 배 위치/퀴즈 정답이 보이지 않을 것.
5. 위장 눈테스트: 모르는 3명에게 10초, 2명 이상이 "업무 시트"로 답. ESC 전환 100ms 이내. 업종어가 열 너비를 넘치지 않을 것. **웃음 문구가 보이는 상태의 화면**으로도 같은 테스트 1회.
6. 웃음 문구 검수(3-3의 4개 검수 규칙) 통과.
7. 플레이 테스트 5쌍: 규칙 설명 없이 방 번호만 주고 완주.
8. 법률 체크리스트 1, 3번 PM 확인 전에는 공개 배포 금지(비공개 링크 유지).
9. 카피 검수(보장 표현 금지), noindex + 베타 띠로 시작.

## 8. PM이 확인할 것 (법률·정책, 비평팀은 단정하지 않음)
1. "Battleship" 상표 및 유사 표기, "해전" 일반어 사용 범위.
2. 게임 규칙 자체의 보호 여부(국가별 차이, 소송 사례 본문 미확인).
3. 스프레드시트 외관 유사성(trade dress/부정경쟁) 허용 수준, 폰트 라이선스.
4. "Microsoft와 무관" 고지의 필요성과 위치.
5. 탭 제목·파일명 위장이 기만적 표시로 해석될 가능성.
6. 회사 정책 위반 조장으로 읽히는 표현의 책임 범위와 면책 문구.
7. 닉네임/IP/방 로그 수집 시 개인정보처리방침(/privacy 재사용 가능 여부).
8. 시딩할 커뮤니티의 홍보 규정, 자체 도메인 구입 여부.
9. **[신규]** 시말서·품의서 같은 가짜 업무 서류 이미지가 실제 서류 사칭이나 장난 서류로 오용될 가능성, 그리고 웃음 문구가 실제 직장 내 괴롭힘 맥락에서 인용될 때의 책임 범위(자문 필요).

## 9. 출시 후 Go / 접기 (제안 수치, 근거 데이터 아님)
측정: 시딩 후 14일, 같은 기기 자기대전 제외.
- 방 생성 대비 2인 입장률 ≥ 50%
- 입장 후 완주율 ≥ 60%
- 재대결률(같은 쌍 24시간 내 2판째) ≥ 30%
- 전파율 K(완료 참여자 1명당 새 상대 초대 수) ≥ 0.5
- 볼륨: 14일 내 완료 매치 ≥ 150, 고유 플레이어 ≥ 200
- **[신규] 웃음 지표**: 종료 화면 1탭 "피식했나요?"(없음/약간/터짐) 응답 중 "약간 이상" ≥ 70%. 문구 단위 "별로예요" 누적으로 하위 문구 정리.
- **[신규] 불편 지표**: "불편한 문구" 신고 비율 ≤ 3%(신고 버튼 제공). 초과 시 해당 문구 즉시 삭제, 1% 초과만 되어도 문구 풀 점검.
- **[신규] 결재 경보**: 경보 발생 판의 완주율이 미발생 판보다 10%p 이상 낮으면 제거 또는 옵션화.
- 참고: 업무시간(평일 09~18) 시작 비중 ≥ 50%, 퀴즈 참여율, 위장 전환 사용률.
- **Go**: 입장률/완주율/재대결/K 중 3개 이상 + 볼륨 + 웃음 지표 충족. 이후 업종 추가, 자체 도메인, 하드 모드 순.
- **1회 조정**: 2~3개 충족이면 가설 하나만 수정해 7일 재측정.
- **접기**: 완료 매치 < 50, 또는 입장률 < 30%, 또는 재대결률 < 15%, 또는 웃음 "약간 이상" < 40%(웃기지 않으면 PM의 필수 요구가 충족 안 된 것). 접을 때 업종 시트 엔진, 격자 컴포넌트, 문구 풀은 다른 직장인 게임에 재사용.
- "회사에서 막힘" 언급이 20% 넘으면 C2로 별도 판정.

## 10. R3 기획팀장용 권고
1. 조건부 Go: 실시간 방 초대 + 재접속 유지 + 모바일 지원 + 서버 판정.
2. 퀴즈 힌트: 진행자 안 채택. 3초 잠금(단계 상승) + 10초 만료, **두 사람 모두 게임 화면일 때만 출제**, 격차 상한, 정보량 서열, 힌트 0개여도 성립. 최대 개수는 시뮬 후 확정.
3. 웃음: "업무 말투 이중 의미 문장"이 핵심. 프리셋 선택형만(자유 입력 없음), 금지 목록과 검수 4규칙 준수, 충돌 시 위장 우선. 결재 경보는 보상형으로 변경.
4. 업종 3종(회계, 영업·유통, 총무·인사), 엔진 1개 + 데이터 JSON, 문구는 AI 초안 + PM 선별.
5. 컴퓨터 대전: 첫 출시 제외, 정적 튜토리얼로 대체, 조건부 재검토.
6. 확산 경로는 방 번호 개인 초대 하나. 공유 이미지는 보조 장치.
7. 법률 9항목은 PM 확인, 확인 전 공개 배포 금지. 수익 0 전제의 확산 검증 실험.
