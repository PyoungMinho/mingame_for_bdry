## 결론 요약

이번 묶음의 목표는 두 가지다. 첫째, 술자리 테이블에서 **블라인드 검증 때와 같은 수준의 정보가 실제로 돌게** 한다. 둘째, **앱이 스스로 흘리던 누설 경로를 막는다.** 지금 앱은 검증 받은 판(플레이어 뷰 = 지도 포함, 카드 전문)보다 정보가 적게 돈다. 지도가 없고, 공개 단서는 한 번 읽히고 사라지며, 생각을 적어 둘 곳도 없다. 그 결과 토론이 인상과 연기로 흐른다. 반대로 앱이 먼저 흘리는 경로도 세 군데 있다. 자기소개 카드의 말투 예시, 범인만 받는 붉은 도장, 방장 낭독보다 먼저 범인을 띄우는 플레이어 진상 화면이다.
그래서 이렇게 정했다. **추리 장치 5개**(궁 배치도·인물록, 개인 추리 수첩, 공개 단서 인장 보드, 최종 변론 3칸 틀, 보너스 문항 정식 단계)와 **술자리 마찰·누설 해소 8개**(외칠 말 통일, 낭독 먼저·방장 조사 분리, 말투 예시 제거, 도장 실루엣 통일, 진상 2단 공개, 거짓말 규칙 상시 노출, 공용 단서 상시 열람, 문구 정정)를 넣는다. P0 11건은 하루 개발 1회에 끝낸다. P1 3건은 P0이 끝난 뒤 같은 회차의 남는 시간에 넣는다.
어떤 항목도 사건 정보를 새로 만들지 않는다. 정보량은 블라인드 검증 수준과 같거나(지도·공개 단서), 그보다 적다(누설 차단). 그래서 원고 난이도 게이트(6인 R2 ≤50%, R3 끝 80%+)를 다시 블라인드로 검증할 필요는 없다. 대신 실제 판에서 종이로 확신도를 실측한다(실행 계획 4단계).
질문 유도 장치(어명 질문권·질문 카드·질문 차례)와 자기소개 '그날 밤 한 줄'은 이번에 넣지 않는다. 역할 진술을 R1에 끌어당겨 검증 범위 밖의 정보를 늘리기 때문에, 실측 뒤에 다시 판단한다.

## 채택한 아이디어

각 항목은 **목적 / 화면 위치 / 동작 / 문구 / 데이터 출처 / 역할 중립 보장 / 수용 기준** 순으로 적는다. 문구는 그대로 구현한다(사극 톤 유지). 수용 기준은 모두 vitest(+RTL) 자동 테스트로 확인할 수 있게 적었다. 실기기 확인만 가능한 것은 따로 [실기기]로 표시했다.

### 공통 규칙(전 항목)
- 새 안내 문구(큐·프롬프트·변론 틀·수첩 범례·규칙 상자)에는 **사건 고유어를 넣지 않는다.** 금칙어: `꿀 석청 탕약 매듭 부자 생부자 노린 독이 든 서온돌 동온돌 연못 장부 노리개 회임 해시 자시`. 지도 라벨·장소 이름·카드 본문·보너스 문항 원문은 이 금칙어 검사에서 뺀다. 테스트: 새 문구 상수를 모은 `GUIDE_COPY` 배열에 금칙어가 0개여야 한다.
- 결과 공유 문구·OG URL·초대 링크에 **수첩 내용, 인장 번호, 카드 id, 범인 정보를 넣지 않는다**(불변 2). 테스트: `resultShareInput`·`resultPayload`·`ogResultUrl`의 출력에 `/\b[A-Z]{2,3}-\d/`와 4자리 인장이 없어야 한다.
- 역할 중립(불변 1): 방장 공용 무대(진행 탭)와 봉인 화면의 DOM은 방장 역할에 따라 달라지면 안 된다. 기존 `RoleNeutral.test.tsx`를 새 화면(인장 보드, 진상 대기, 수첩 탭 머리, 「?」 시트 지도·인물)까지 넓힌다.

### G1. 방장 '외칠 말' 통일 (P0·S)

- **목적**: 서버가 없으니 동기화는 목소리뿐이다. 그런데 지금 방장 화면에는 플레이어 게이트 캡션이 기다리는 신호 문구가 한 번도 뜨지 않는다(`HOST_CUE`는 다음 화면 안내문이다. `HostScreens.tsx:67`). 라운드가 바뀔 때마다 '너 아직 1라운드야?' 확인이 생기는 원인이다.
- **화면 위치**: 방장 진행 탭 ActionBar의 주 버튼 위 캡션. 6초 '넘어갔소' 토스트.
- **동작**: 신호표를 한 모듈(`src/app/gung/screens/signals.ts`)에 두고, 플레이어 `gate()` 캡션과 방장 캡션이 **같은 함수**에서 문구를 받는다. 방장 캡션은 그 단계의 전진 버튼에만 붙는다. 하위 단계 전진(장소 고르기→토론, 변론 다음 사람, 지목 입력)에는 붙이지 않는다.
- **문구**
  - 방장 캡션 문법: `누르고 외치시오: '{신호}'`
  - 전진 토스트: `넘어갔소 → {단계명} · 📣 '{신호}'`
  - 신호표(단일 출처)

    | 방장 단계(누르는 버튼) | 신호 |
    |---|---|
    | 대기실 `사건 시작 →` | 사건을 시작하겠소 |
    | 브리핑 `다 읽었소 → 패 확인` | 각자 자기 패를 몰래 보시오 |
    | 패 확인 `다 봤소 → 자기소개` | 1번부터 신분을 밝히시오 |
    | 자기소개 `첫째 조사 시작 →` | 첫째 조사를 시작하오 |
    | 조사1 토론 `둘째 조사 시작 →` | 둘째 조사를 시작하오 |
    | 조사2 토론 `셋째 조사 시작 →` | 셋째 조사를 시작하오 |
    | 조사3 토론 `최종 변론으로 →` | 최종 변론이오 |
    | 변론 마지막 사람 `지목하러 →` | 지목하겠소 |
    | 지목 집계 `진상 공개 →` | 그날 밤의 진상을 밝히겠소 |
    | 진상 범인 도장 비트(G5) | 범인이 밝혀졌소 |
  - 자기소개 건너뛰기 링크 아래: `건너뛰면 외치시오: '첫째 조사를 시작하오' — 모두 두 번 눌러야 하오`
- **데이터 출처**: 디자인 스펙 §2-C 구두 신호 지도(이미 정의돼 있으나 구현이 빠짐). 사건 정보 없음.
- **역할 중립**: 문구는 단계로만 정해진다.
- **수용 기준**
  1. 표의 모든 단계에서 `hostSignal(phase, sub)` 결과가 같은 단계 플레이어 게이트 캡션의 신호와 **글자 하나까지 같다**(표 기반 단위 테스트).
  2. 방장 진행 탭에서 위 단계마다 캡션 `누르고 외치시오: '…'`가 보인다. 내 패·단서함·수첩 탭에서는 보이지 않는다(기존 ActionBar 숨김 규칙을 그대로 따름).
  3. 전진 토스트에 신호가 들어 있다.

### G2. 낭독 먼저 → 고르기 타이머는 방장이 시작 + 방장 조사를 무대에서 단서함으로 (P0·S)

- **목적**: 라운드에 들어서는 순간 2분 고르기 타이머가 저절로 돈다(`game.ts:547, 563, 810`). 그래서 R3의 PB-3(587자) 낭독이 끝나기도 전에 종이 울린다. 또 공용 무대 맨 아래에 방장 본인의 봉인 카드가 있어(`HostScreens.tsx:367-389`), 공용 단서를 다시 보려고 몸을 숙인 사람이 꾹 누르면 방장 단서가 열린다.
- **화면 위치**: 방장 H5(장소 고르기), 방장 단서함 탭.
- **동작**
  1. 엔진: 조사 라운드에 들어설 때(intro→r1, 토론→다음 라운드, skipIntro, 진행 단계 맞추기 모두) `timer = null`로 둔다. 무대 순서는 공용 단서(낭독) → 타이머 시작 버튼 → 내 조사 버튼이다. 기존 `TimerSlot`이 null이면 시작 버튼을 그리므로 그 라벨만 바꾼다.
  2. 무대에서 `HostOwnClue`·`HostPlacePicker`를 뺀다. 그 자리에 단서함 탭으로 가는 버튼을 하나 둔다. 방장은 단서함의 `지금 고르기`(기존 CatchUpPicker)로 고른다. 고른 뒤에는 플레이어 흐름과 같은 6초 되돌리기 토스트를 띄운다(단서를 열기 전까지).
  3. PB-3 단락 넘기기는 이번에 넣지 않는다(타이머가 멈춰 있으면 급할 일이 없다).
- **문구**
  - 고르기 HostCue: `공용 단서를 먼저 읽고, 고르기 2분을 시작하시오. 장소는 한 군데만이오`
  - 타이머 시작 버튼(고르기·타이머 없음): `다 읽었소 → 고르기 2분 시작`
  - 공용 단서 아래 한 줄: `이 단서는 각자 폰 단서함에도 있소`
  - 무대 버튼: `🔒 내 조사(장소·단서)는 단서함에서 ›`
- **데이터 출처**: 없음(진행 순서만 바꿈).
- **역할 중립**: 무대에서 봉인 카드가 아예 없어진다. 방장 버튼 문구는 '골랐는지'조차 드러내지 않는 고정 문구다.
- **수용 기준**
  1. 세 가지 진입 경로 모두에서 `host.timer === null`, `roundSub === 'select'`이다.
  2. 시작 버튼을 누르면 `timer.kind === 'select'`, 남은 시간은 2:00이다.
  3. 방장 진행 탭 DOM에는 lobby~result 어느 단계에서도 `.gu-sealed` 요소가 0개다.
  4. 방장이 단서함에서 고르면 `pickPlace`가 기록되고 되돌리기 토스트가 뜬다. 단서를 열면 토스트가 거둬진다(기존 BUG-17 규칙).
  5. 이 변경으로 바뀌는 기존 테스트(qa-engine·game·round-lock·RoundLock.smoke·GungApp.qa)의 타이머 기대값을 갱신한다. 그 밖의 테스트는 수정 없이 통과한다.

### G3. 자기소개: 말투 예시 제거·큐 교체 (P0·S)

- **목적**: 자기소개 카드는 `sheet.speech.slice(0,2)`를 프로필과 함께 띄운다(`PlayerScreens.tsx:233`). 큐도 「사극 말투는 필수요」라서 말투 예시까지 소리 내어 읽히는데, 이 말투 예시는 블라인드 검증에 들어가지 않은 정보 경로다. 6인 판 세자빈 ①은 「그런 분이 내 꿀을… 잠깐, 내 꿀을?」로 반전 1·2를 조사 전에 가리킨다. 원고는 이 대사를 R2 DG-2 순간의 반응용으로 설계했다(원고 6-6). 조상궁 ①은 R2부터 잠근 봉함 매듭을 먼저 말한다. 자기소개가 '누가 더 웃기게 읽나' 대회가 되는 것도 PM이 싫어한 역할놀이 쪽이다.
- **화면 위치**: 플레이어 P4 자기소개 카드, 방장 H4 큐, 하는 법 시트 ③, 내 패 '말투' 섹션 머리.
- **동작**: 자기소개 카드에는 역할명과 공개 프로필만 보인다. 말투 예시는 내 패 '말투' 섹션에만 남기고, 섹션 맨 위에 모든 역할 공통 안내 한 줄을 둔다.
- **문구**
  - H4 큐: `1번부터 차례로 신분을 밝히시오. 패의 신분 글을 읽으면 되오. 말투는 자유요`
  - P4 안내: `방장이 내 번호를 부르면, 아래를 꾹 눌러 '신분'을 읽으시오`
  - 하는 법 ③: `③ 자기소개 — 패의 신분 글을 읽는다(말투는 자유)`

### R1. 거짓말 규칙 상시 노출 + 패 확인 '꼭 볼 3칸' (P0·S, 봤음 점은 P1)

  3. 지도의 장소 아이콘 키가 `places[].icon`과 일치한다.
  4. 인물 섹션: 자기소개 전에는 잠김 문구만 있다. 뒤에는 자리 수만큼 카드가 있다. 4·5인에서만 NPC 머리가 있고, 6인 DOM에는 `이 자리에 없으나`가 없다.
  5. 호칭표의 모든 별칭이 공개 텍스트(브리핑 문단 ∪ 공개 프로필 ∪ 공용·장소 카드 본문) 안에 실제로 있다(자동 검사. 공개 텍스트에 없는 호칭을 새로 만들지 못하게 막는다).
  6. 장소 고르기 화면에 `🗺 궁 배치도 보기` 링크가 있다.

### R3. 공용 단서 상시 열람 (P0·S)

- **목적**: 방장 무대의 PublicBoard는 '지금 라운드' 공용 카드만 보여 준다. 변론·지목 화면에는 공용 카드가 아예 없다. R3 토론과 변론에서 정작 필요한 것은 PB-1과 PB-2의 대조다. 플레이어는 단서함 탭 맨 아래에서만 공용 단서를 볼 수 있어 방장 폰을 집어 들게 되고, 내문 출입 타임라인은 방장 폰에만 있다.
- **화면 위치·동작**
  - 방장 H5·H6: 지금 라운드 공용 단서(펼침) 아래 `지난 공용 단서 (조사 1~{N-1}) ▸` 접힘 블록.
  - 방장 H7 변론·H8 지목 준비: `공용 단서 전체 ▸` 접힘 블록(+ R5 인장 보드 접힘).
  - 플레이어 P5·P6(조사 화면, 장소 고르기 전·후 모두): 맨 위 `📢 이번 조사 공용 단서 ▸` 접힘. 열면 그 라운드 PB와 추가 증언 본문이 나온다.
  - 플레이어 단서함 '공용 단서' 위: `GateTimelineBar`(방장과 같은 `gateTimeline(c, n, gateRoundsShown(state))`).
  - 공용 단서 목록 아래(방장·플레이어 공통): 시각 어림 한 줄. `timeTable(c)`에서 만들고 하드코딩하지 않는다.
- **문구**
  - `지난 공용 단서 (조사 1~{N-1}) ▸` / `공용 단서 전체 ▸` / `📢 이번 조사 공용 단서 ▸`
  - 시각 어림(생성 결과 예시): `시각 어림 — 술시 초 19시 · 해시 초 21시 · 자시 초 23시 · 축시 초 1시 · 정은 초에서 1시간 뒤 · 말은 1시간 반 넘어 · 반 시진 ≈ 1시간`
- **데이터 출처**: `getRoundBoard`·`publicBoardUpTo`·`gateTimeline`·`timeTable`(기존 함수, 기존 라운드 게이팅 그대로).
- **역할 중립**: 목록은 인원과 이 폰의 단계로만 정해진다.
- **수용 기준**
  1. r1·r2에 있는 폰의 DOM(방장·플레이어, 펼친 상태 포함)에 PB-3과 R3 추가 증언 본문이 없다.
  2. r2 플레이어 타임라인 표식은 PB-2 gateLog뿐이다.
  3. 변론·지목 준비 화면에서 PB-1~3이 접힘 안에 있다.
  4. 같은 인원·단계에서 역할만 바꿔도 DOM이 같다.
  5. 시각 어림 문자열이 `timeTable(c)`의 `parts`와 어긋나지 않는다(단위 테스트).
- 각 시각어를 탭하면 환산 말풍선이 뜨는 '시각 칩'은 넣지 않는다. 한 줄 어림이 같은 일을 더 싸게 한다.

### R4. 개인 추리 수첩 — 4번째 탭 (P0·M)

- **목적**: 카드 31장 중 한 사람이 직접 보는 것은 장소 카드 3장과 공용 카드 3장뿐이다. 나머지는 귀동냥이다. 술자리에서는 R1에 들은 것을 R3까지 기억하지 못하고, 기억이 끊기면 판정 근거가 말투와 연기로 바뀐다. PM이 열어 둔 '정리 도구' 범위 안에서 가장 기본인 기능이다.
- **화면 위치**: BottomTabs 4번째 탭 `수첩`(아이콘 `NotebookPen`). 방장·플레이어 모두, 대기실 이후 모든 단계. 변론(P7)·지목(P8) 화면에는 `📓 수첩` 바로가기.
- **동작**
  1. **용의자 표**: 행 = 이 판의 **착석 자리 중 내 자리를 뺀 모두**(NPC 행 없음). 행 머리는 `rolesVisible` 전 `{N}번`, 뒤 `{N}번 · {약칭}` + 역할 아이콘.
  2. 열 = `수단` `기회` `동기`. 칸을 탭할 때마다 `빈칸 → ○ → ✕ → 빈칸`으로 바뀐다. 터치 영역은 칸당 48px 이상. 앱은 어떤 칸도 미리 채우거나 바꾸지 않는다.
  3. 행마다 한 줄 메모(선택, 40자). 표 아래 자유 메모 1칸(선택, 300자).
  4. **자동 추론 없음**: 카드 열람·단계 진행·공개 여부 어느 것도 칸에 영향을 주지 않는다. 합계·순위·'의심 1위' 같은 계산 표시도 없다.
  5. **보너스 문항 관련 칸 금지**: '독이 든 음식'·'노린 사람' 같은 칸이나 보기 목록을 두지 않는다(보기 자체가 반전 1·2를 가리킨다).
  6. **노출 방지**: 수첩 탭에서 60초 동안 입력이 없으면 진행 탭으로 돌아간다(모든 기기 동일). 단계가 바뀔 때 진행 탭으로 가는 기존 규칙도 그대로다. 봉인(꾹 누르기)은 쓰지 않는다. 표를 탭해야 하므로 꾹 누르기와 함께 쓸 수 없고, 직전 PM 불만('다음 쪽')처럼 조작이 겹치면 안 된다.
  7. **저장**: 키 `gu:note:v1` 1개 = `{ v:1, code, seat, updatedAt, marks:{[seat]:{means?:'o'|'x', opp?:'o'|'x', motive?:'o'|'x'}}, lines:{[seat]:string}, free:string }`. 순수 파서·직렬화는 `src/lib/gung/notes.ts`에 둔다. 저장 규약은 `storage.ts`와 같다(try/catch, 메모리 폴백, 화이트리스트 복사, 12시간 TTL). 읽을 때 `code`나 `seat`가 지금 게임과 다르면 폐기한다. `처음으로`·새 방·자리 바꾸기 때 지운다.
  8. 진상 공개 뒤에도 그대로 볼 수 있다('내 추리 vs 진상' 비교 화면은 보류).
- **문구**
  - 머리: `내 추리 수첩 — 이 폰에만 적히오. 앱은 아무것도 대신 채우지 않소`
  - 범례: `○ 그럴 수 있었소 · ✕ 아니라는 물증이 있소 · 빈칸은 모름`
  - 열 도움말(ⓘ 탭): `수단 — 독을 손에 넣을 수 있었나` · `기회 — 그때 그곳에 손을 댈 수 있었나` · `동기 — 그럴 까닭이 있었나`
  - 자리표시자: `한 줄 메모` / `자유 메모`
  - 비우기: `수첩 비우기` → 확인 `수첩을 다 지우겠소?` / `지우겠소`
- **데이터 출처**: `publicSeats`(D16 공개 정보)와 인원. 사건 텍스트 없음.
- **역할 중립**: 행·열·문구 구조가 모든 역할에 같다(범인 수첩도 같은 모양). 탭 바는 모든 역할·인원에서 4개다.
- **수용 기준**
  1. 4·5·6인, 모든 자리에서 행 수 = n−1이고 내 자리 행이 없다.
  2. 모든 단서를 열고 공개하고 r3까지 진행해도 `marks`가 `{}`인 채로 남는다.
  3. 칸 탭 순환이 `빈칸→○→✕→빈칸`이다.
  4. 수첩 DOM에 `bonusQuestions`의 prompt·options 문자열이 없다.
  5. 다른 code·seat의 저장은 읽지 않고 지운다. TTL이 지나면 지운다. localStorage가 throw해도 앱이 죽지 않는다.
  6. fake timer 60초 무입력 → 진행 탭으로 돌아간다. 입력하면 타이머가 다시 시작한다.
  7. 결과 공유 payload·OG URL에 수첩 문자열이 없다.

### R5. 공개 단서 인장 보드 (P0·L)

- **목적**: 원고 공통 규칙 3은 '공개 = **방장 폰 공용 보드에 올림**'이다(원고 1-7). 지금 앱의 공개 표시는 「공개/비공개는 내 폰에만 남는 메모예요」(`PlayerScreens.tsx:306`)일 뿐이라, 취한 사람이 한 번 더듬어 읽고 끝난다. 그 사이 「외매듭·잿빛 티끌·연분홍 명주실」, 「外用 三錢」, 「나비매듭」 같은, 추리 경로를 잇는 낱말이 흐려진다. 추리는 문장끼리 대조하는 일인데, 전달이 귀동냥이 되면 역할놀이가 된다. 보드는 블라인드 탐정이 가졌던 '정확한 문장'을 테이블에 되돌린다.
- **화면 위치**
  - 플레이어(와 방장 본인): 공개한 단서 카드(진행 화면·단서함)에 인장 번호.
  - 방장 무대: H6 토론 공용 단서 아래 `공개 단서 보드`. 다음 라운드 H5와 H7·H8 준비에는 접힘으로.
- **동작**
  1. **인장 번호**: `clueSeal(c, n, roomCode, cardId)` → 4자리(1000~9999). 기존 `rng.ts` 해시로 `roomCode|cardId|salt`를 해시한다. 그 판 인원에 보이는 장소 카드 전체(id 정렬) 안에서 겹치면 salt를 올려 다시 뽑는다. 결정론이라 같은 방이면 어느 폰에서나 같은 번호가 나온다. 공용 카드(PB)와 추가 증언에는 인장이 없다(이미 보드에 있음).
  2. 카드가 `disclosure === 'public'`일 때만 인장을 그린다. 미정·비공개 상태의 DOM에는 숫자가 없다.
  3. **방장 입력**: `＋ 인장으로 올리기` → 숫자 키패드 시트(4자리). `clueBySeal(c, n, roomCode, seal, upToRound = reachedRound(방장 phase))`로 찾는다.
     - 맞으면 선택 단계로 `누가 밝혔소?` 자리 칩(여럿 고를 수 있음, 건너뛰기 가능) → 보드에 붙인다.
     - 틀린 번호와 아직 들어서지 않은 라운드의 번호는 **같은 문구**로 거절한다(어느 쪽인지 알려 주면 번호의 유효성을 캐내는 신탁이 된다).
     - 3회 연속 오답이면 10초 동안 입력을 막는다(로컬 UI 상태).
     - 이미 올린 카드면 `이미 올린 단서요`(새 자리만 덧붙인다).
  4. **상태**: `HostState.board: { id: string; round: RoundNo; seats: number[] }[]`. 본문은 저장하지 않고 언제나 사건 데이터에서 다시 계산한다. 액션 `postClue`·`unpostClue`는 되돌리기 스택에 기록한다(↶ 지원). `storage.ts`의 `parseHost` 화이트리스트에 넣는다. 검증: id 형식 `/^[A-Z]{2,3}-\d{1,2}[a-z]?$/`, round 1~3, seats ⊂ 1..n, 최대 21건, id 중복 제거.
  5. **보드 표시**: 라운드별 묶음. 최신 라운드는 펼치고 이전은 접는다. 항목 머리 `조사 {r} · {장소} · {표시 id} {제목}`, 본문 전문(낭독용 큰 글씨), 꼬리 `{N}번 공개` 칩. 표시 id는 기존 BUG-25 규칙(`HW-1b`→`HW-1`)을 따른다. 항목마다 `내리기`(확인 시트).
  6. **간편 모드 금지**: 방장이 인장 없이 장소·라운드를 골라 카드를 띄우는 경로는 만들지 않는다. 오탭 한 번이면 숨긴 카드가 전원에게 펼쳐져 범인 전략과 숨김 플레이가 무너진다.
  7. 말로 일부만 전하는 것은 여전히 자유다(규칙 3). 인장은 원하는 사람만 부른다.
  8. **플레이어 장소 고르기 보강**(게임 감사 3 일부): 타일에 내 지난 방문 꼬리표, 그리드 위에 고정 안내 한 줄. 다른 사람이 많이 간 곳 같은 집계는 띄우지 않는다.
- **문구**
  - 공개 카드 인장: `인장 {1234} — 방장에게 불러 주면 공용 보드에 그대로 올라가오`
  - 공개 토스트(기존 '공개로 표시했소' 3곳 교체): `공개했소 — 인장 {1234}를 방장에게 불러 주고, 소리 내어 읽으시오` (+ 되돌리기 5초)
  - 단서 아래 micro(306행 교체): `공개해도 다른 폰엔 저절로 가지 않소. 인장을 방장에게 불러 주시오`
  - 보드 제목: `공개 단서 보드 ({k}장)` / 빈 상태: `아직 올린 단서가 없소. 공개한 이에게 인장을 불러 달라 하시오`
  - 버튼: `＋ 인장으로 올리기` / 키패드 시트 제목: `인장 번호를 넣으시오`
  - 거절: `그런 인장은 없소` / 잠금: `10초 뒤에 다시 넣으시오` / 중복: `이미 올린 단서요`
  - 자리 선택: `누가 밝혔소? (건너뛰어도 되오)` / `건너뛰기`
  - 내리기 확인: `이 단서를 보드에서 내리겠소?` / `내리겠소`
  - 보드 꼬리 고정 문구: `보드엔 스스로 밝힌 단서만 오르오`
  - 장소 고르기 위: `같은 곳을 고르면 같은 단서요. 나눠 갈수록 많이 알게 되오`
  - 타일 꼬리표: `조사 {r}에 감`
- **데이터 출처**: 장소 카드 본문(원고 4장 = 플레이어 뷰 5장·부록 A). 인장은 번호일 뿐 텍스트가 아니다. 모든 카드 본문은 이미 클라이언트 번들에 있다. 인장은 보안 장치가 아니라 **오탭·훑어보기 방지 장치**다.
- **역할 중립**: 보드 내용은 입력된 인장 순서로만 정해진다. 방장 본인 카드도 같은 흐름(자기 단서함에서 인장을 보고 직접 입력)을 거친다. 숨김 표시는 어디에도 없다.
- **수용 기준**
  1. `clueSeal`은 결정론이다. 무작위 방 코드 500개 × n∈{4,5,6}에서 방 안 인장이 모두 다르고 4자리다.
  2. 플레이어 카드가 public일 때만 인장 숫자가 DOM에 있다.
  3. 방장 r2: R1·R2 장소 카드 인장은 받고, R3 카드 인장은 `그런 인장은 없소`로 거절한다(틀린 번호와 문구·DOM이 같다).
  4. 3회 연속 오답 → 10초 잠금(fake timer).
  5. 받은 뒤 보드에 제목·본문·조사·장소가 나온다. HW-1b는 `HW-1`로 표시된다.

### 감사가 짚은 개별 위험과 처리

- **지도에 동선을 그어 R3 정보를 R2로 당길 위험**(게임 1): 사람·화살표·시각·물건을 그리지 않는다. 라벨은 원문만 쓴다. 금지어 테스트로 막는다.
- **수첩이 정답을 대신 찾을 위험**(UX 3·게임 2): 자동 채움·교차 대조·합계·추천이 없다. 보너스 보기가 들어간 칸도 없다. '모든 단서 열고도 marks 빈 채' 테스트로 확인한다.
- **방장 수첩이 무대에 노출될 위험**(게임 2): 60초 무입력이면 진행 탭으로 돌아가고, 단계가 바뀌면 진행 탭으로 간다. 봉인 꾹 누르기는 쓰지 않는다(직전 '다음 쪽' 불만처럼 조작이 겹치는 것을 피함).
- **인장 오탭으로 숨긴 카드가 펼쳐질 위험**(게임 6·시뮬 5): 간편 모드 금지, 인장 필수, 3회 오답 잠금. 미래 라운드 번호와 틀린 번호를 같은 문구로 거절해 신탁을 막는다.
- **'숨김' 낙인으로 R2 쏠림이 커질 위험**(게임 3): 숨김 표시와 롤콜 격자는 이번에 넣지 않는다. 보드에는 '밝힌 것'만 오른다.
- **인물록이 R3 연결을 앞당길 위험**(게임 9): 엑스트라·비밀 관계·관계선을 뺀다. NPC 표기는 브리핑 문구와 같게 쓰고, 6인 판에는 그 개념 자체가 없다.
- **진상 칩 문구 누설**(게임 4): 이번엔 근거 칩을 넣지 않는다(보류).
- **변론 틀·질문 문구가 반전을 가리킬 위험**(게임 11·시뮬 6): 공통 금칙어 테스트로 막는다.
- **엔진 변경의 회귀 위험**(G2, R5): 바뀌는 테스트 목록을 수용 기준에 못 박았다. 그 밖의 기존 테스트는 고치지 않고 통과해야 한다.

| 항목(출처) | 판정 | 이유 | 재검토 조건 |
|---|---|---|---|
| 진상 비트 근거 카드 칩 + '모든 단서' 열람(게임 4, 시뮬 15①) | 보류(다음 묶음 1순위) | 안전하고 '풀 수 있었다' 체감을 주지만, 사건이 하나뿐이라 '다음 판 학습' 효과는 사건 2가 생겨야 산다. 비트별 근거 매핑(원고 2-3·6-2)은 손 검수가 필요하다 | 사건 2 기획 착수 시. `case-extras.ts`에 비트→카드 매핑을 두고, 범인 공개 비트 뒤에만 노출 |
| 지목 근거 카드 고르기 + '근거 적중'(게임 5) | 보류 | 지목 순간에 단계가 하나 늘어(취중 마찰) 판정 목록 관리가 필요하다. R6 변론 틀이 '근거를 말하라'를 무마찰로 먼저 시험한다 | 실측에서 '근거 없이 찍기'가 여전히 많을 때 |
| 어명 질문권(게임 7) | 보류 | 잠기지 않은 「물으면 사실대로」(내관의 꿀·매듭·해시 초에 본 것)가 R1에 열릴 확률이 오른다. 블라인드 검증엔 역할 진술이 없었다 | 실측 R2가 30% 미만으로 너무 어려울 때만, 하우스룰(기본 꺼짐)로 |
| 절차형 질문 카드(게임 12), '대화가 멈췄다면?' 팁(UX 8), 질문 차례 돌리기(시뮬 8) | 보류 | 질문 유도 계열이라 위와 같은 이유. 사건 고유어가 든 질문은 영구 제외 | 같은 조건. 도입 시 금칙어 테스트 필수 |
| 자기소개 '그날 밤 한 줄' + 토론 4박자(게임 10) | 보류 | 어의의 술시~자시 동선(물으면 사실대로, 잠금 없음) 같은 진술이 R0에 쏟아진다. 4박자 중 ①장소 보고·②공개 낭독은 R5 보드 운영으로 자연히 생긴다 | 실측 뒤 |
| 방장 장소 롤콜 격자·숨김 표시(게임 3, 시뮬 5 일부) | 보류 | '숨김' 낙인이 R2 쏠림을 키울 수 있다. 공개분은 R5 보드의 '누가 밝혔나'로 대체 | 실측에서 '누가 어디 갔나' 혼선이 크면 숨김 표시 없는 '장소만' 롤콜로 |
| 칭호(게임 14) | 보류 | 결과 재미 요소이고 추리 핵심 아님. 범인 칭호는 공유 금지 조건 관리가 필요하다 | 다음 묶음 |
| 추리 여정·의심 곡선·확신 거수(게임 15, 시뮬 15②) | 보류 | 앱 내 실측 장치는 M 공수다. 이번엔 종이 프로토콜(실행 계획 4)로 대신한다. 공개 거수는 쏠림 위험 | 실측을 반복해야 할 때 비공개 버전으로 |
| 원고 말투 예시 개정(시뮬 2③) | 보류 → 사건 작가 요청 | 원고 3장이 유일 원본이고 `case-data.ts`는 생성 파일이다. 세자빈 ①, 조상궁 ①③, 어의 ③, 중전 ③을 「R2부터」 태그로 잠그거나 사건 지식 없는 대사로 바꿀지 결정이 필요하다 | 원고 6판 개정 시. 정보 지연만 하므로 블라인드 재검증은 불필요 |
| 인물록 엑스트라(카드 연동)·관계선(게임 9 일부) | 보류 | 열람 카드를 추적하는 구조가 필요하다. 처음부터 나열하면 R3 연결이 당겨진다 | 근거 칩과 함께 |
| 토론 시간 라운드별 차등(R1 5분 등)·30초 경고음(시뮬 6·8) | 보류 | 시뮬 추정치다. 방장이 +30초·조기 전진으로 이미 조절할 수 있다 | 실측 시간표 뒤 |
| PB-3 단락 넘기기(시뮬 4) | 보류 | G2로 낭독 중 타이머 압박이 사라졌다 | 낭독 피로 민원 시 |
| 사건 2 예고·'해 본 기기' 경고(게임 13 일부) | 보류 | 사건 2 콘텐츠가 없는 예고는 공수표다. 같은 밤 재플레이는 M1 문구로 막는다 | 사건 2 기획 확정 시 |
| 패 확인 타이머 4분(시뮬 12) | 보류 | +30초 버튼이 있다. '꼭 볼 3칸'으로 먼저 본다 | 실측 |
| 단서함 봉인 앞면 상태 배지(UX 5) | 제외 | 공개 카드는 이미 개봉돼 구분된다. 탭 뱃지가 미정 수를 보여 준다. 옆자리에 '비공개' 표시가 보이는 부작용이 있다 | — |
| '크게 보여주기' 모드(시뮬 14) | 제외 | R5 보드가 '폰 넘기기' 자체를 줄인다. 넘긴 폰의 탭 이동 위험은 보드로 대체한다 | 보드 도입 뒤에도 폰 넘기기가 잦으면 |
| 시각어 탭 칩(게임 8 일부, UX 9) | 제외(대체) | R3 '시각 어림 한 줄'이 같은 일을 더 싸게 한다 | — |
