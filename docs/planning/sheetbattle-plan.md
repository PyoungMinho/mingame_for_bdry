## 0. 최종 판정

**조건부 Go.** 빌드 전에 PM이 10분짜리 확인 두 가지만 해 주면 된다. Supabase를 다시 켜는 것, 그리고 다른 회사에 다니는 지인에게 접속이 되는지 확인하는 것이다. 그 뒤 바로 팀장 회의로 넘어간다. 첫 공개는 검색에 안 뜨는 베타(noindex: 검색엔진에 노출하지 말라는 표시)로 PM 지인에게만 한다. 커뮤니티 공개는 PM이 이름·외관 선(§6)을 확인한 뒤에 한다.

승부처는 세 가지다. ① **상대가 와 주느냐**(1대1이라 혼자는 못 함) ② **웃기느냐**(PM 필수 요구) ③ **옆에서 봐도 일하는 것처럼 보이느냐**. 셋 다 기능을 더해서가 아니라 규칙과 글을 다듬어서 푸는 문제다. 그래서 범위는 작게 잡고 문구에 공을 들인다.

판정 이유 3줄:
1. **빈자리가 있다.** 엑셀 위장 게임은 40년 된 장르지만 대부분 혼자 하는 게임이다. "동료와 1대1 실시간 + 업무 말투 개그 + 계산 퀴즈 힌트" 조합은 양측 조사에서 찾지 못했다 [R2, 전수 조사는 아님].
2. **이미 가진 부품으로 만든다.** 실시간 방, 가입 없는 입장, "상대 패는 서버만 아는" 구조를 /pae에서 만들어 108개 테스트로 검증했다 [확인]. 배 위치도 손패와 같은 종류의 숨긴 정보다.
3. **판 길이가 맞는다.** 8×8, 3척, "먼저 2척 침몰" 규칙으로 봇끼리 4,000판을 돌리니 중앙값 18라운드, 선공·후공 승률 약 48:47이었다 [측정]. 배치와 퀴즈를 포함해 약 7분으로, 점심시간에 1~2판 하기 알맞다 [추정].

## 1. 제품 정의

**한 줄**: 옆에서 보면 둘이 같은 시트를 보는 것 같지만, 실제로는 셀 주소("B7")로 서로 숨긴 배를 찾아 쏘고, 공손한 업무 말투로 약을 올리며 웃음을 참는 6~8분짜리 1대1 게임.

**톤 원칙**: 화면은 진지하게, 글은 웃기게. 소리와 큰 움직임은 없다. 웃음은 모두 글자에서 나온다. **웃음과 위장이 부딪치면 위장을 우선한다.**

### 한 판의 흐름 (PM 확정 5단계 그대로)
| 단계 | 화면 |
|---|---|
| ① 업종 고르기 | "새 문서 → 양식 선택"에서 회계 월마감표 / 영업 실적표 / 인사·총무 연차현황 중 하나를 고른다. "내 화면에 띄울 문서"를 고르는 것이라 직군과 상관없이 고르면 되고, 상대와 달라도 된다 |
| ② 방 번호로 초대 | "공유"를 누르면 5자리 문서 번호와 링크가 나온다. 2명이 차면 잠기고, 끊겨도 30분 안에는 같은 번호로 돌아온다 |
| ③ 배 숨기기 | 길이 4·3·2짜리 배 3척을 90초 안에 놓는다("자동 배치" 있음). 방장은 친구를 기다리면서 먼저 놓을 수 있다 |
| ④ 턴제로 쏘기 | 상대 판 셀을 클릭하거나 이름 상자에 "B7"을 입력한다. 한 발 20초. 결과는 셀 메모에 업무 말투로 뜬다 |
| ⑤ 중간 힌트 | 4·8·12라운드에 "검산 요청" 표가 뜬다. 10초 안에 먼저 맞힌 사람이 수식 힌트를 받는다(`=COUNTIF(E1:E8,">0")` → 2) |
| 끝 | 진 사람은 **시말서**, 이긴 사람은 **포상 품의서**. "v8로 저장" = 재대결 |

### 게임 화면 (PM 질문 반영, Q1)
```
[이름 상자: B7] [수식 입력줄: =COUNTIF(E1:E8,">0")   → 2                     ]
┌ 내 판 (A~H × 1~8) ─────┐   ┌ 내가 쏜 기록 (A~H × 1~8) ──────┐
│ 내 배 = 연노랑 칸        │   │ 명중 = 연빨강, 빗나감 = 회색     │
│ 상대가 쏜 곳 표시        │   │ 침몰 = 진빨강 + 메모 표시(▲)    │
└────────────────────┘   └───────────────────────┘
[손익][월결산][비고]                  상태줄: 다른 사용자가 편집 중 · 자동 저장까지 00:14
```
- 게임판은 **가짜 업무 숫자가 없는 깨끗한 시트 격자**다. 화면의 열 A~H와 행 1~8이 그대로 좌표가 된다.
- 업종 느낌은 **글자로만** 낸다. 파일명(탭 제목), 시트 탭 이름, 배 이름, 명중 메모에 업종을 반영한다.
- 진짜 위장은 **ESC 시트**가 맡는다. ESC를 누르면 0.1초 안에 업종별 가짜 업무 시트로 바뀐다(30행, 합계가 실제로 맞고, 클릭과 입력이 됨). 창을 벗어나도 자동으로 바뀐다.
- **숨기기 키 (2026-11-07 PM 제안 반영, 확정 대기):** PM 원문 "ESC말고 tab이 누르기 더 쉬운거 아닌가 ??". 진행자 추천은 **Tab을 주 키로, ESC도 같이 동작**. Tab은 왼손 새끼손가락 자리라 안 보고 누를 수 있고, 스프레드시트에서 Tab은 "다음 칸" 키라 눌러도 자연스럽고, 실물 ESC 키가 없는 맥북(2016~2019 터치바 모델)도 있다. 대신 브라우저의 Tab 기본 동작(버튼 사이 이동)을 게임 화면에서 막아야 하고, Alt+Tab·Cmd+Tab처럼 보조키가 눌린 경우는 무시한다. 이 문서의 "ESC 시트"는 "숨기기 시트"로 읽는다.

## 2. 쟁점별 판결 (창의 vs 비평)

| 1 | 컴퓨터 대전 | P0에 "박대리" 봇 | 빼고 각본 튜토리얼 | **비평 구조 + 창의 캐릭터**: P0는 "박대리와 2분 연습"(정해진 각본대로 진행), 진짜 봇은 조건부 P1 | 병목은 "상대가 오느냐"이고 봇은 이걸 못 푼다(비평이 맞음). 그래도 "한 번 웃어 봐야 링크를 보낸다"(창의가 맞음). 각본 판 하나로 도발·퀴즈·경보·시말서를 2분 안에 다 보여 줄 수 있다. 진짜 봇은 서버 판정과 별도인 두 번째 게임 경로가 필요해 비싸다. 방장이 혼자 기다리다 나간 비율이 50%를 넘으면 그때 봇을 붙인다 |

## 6. 이름·외관·법률의 선

팀은 법률을 단정하지 않는다. 대신 **처음부터 만들지 않을 것**을 정해서 PM이 확인할 범위를 줄인다.

- 이름, 문구, 주소에 "Battleship"이나 "배틀십"을 쓰지 않는다. 배는 게임 안에서 업무 항목 이름("부장님 법카 내역")으로 부른다. 참고로 미국 저작권청은 게임의 아이디어, 이름, 진행 방법은 보호 대상이 아니라고 안내한다 [확인: FL-108 검색 요약]. 이 게임 방식은 1930년대 종이 게임에서 시작됐다는 기록도 있다 [검색 요약, 단일 출처]. 한국 법 기준은 [미확인].
- 스프레드시트 요소는 누구나 쓰는 것(격자, 열 문자, 행 번호, 수식 입력줄, 시트 탭, 상태줄)만 쓴다. **쓰지 않는 것**: Microsoft·Excel·Google의 이름과 로고, 엑셀 고유의 초록색과 초록 X 아이콘, 리본 메뉴 모양, Office 전용 글꼴 파일. 목표는 "구별할 수 없는 수준"이 아니라 "5초 곁눈질 통과"다.
- 탭 제목은 "월마감_최종_진짜최종_v7"처럼 파일명만 쓰고 프로그램 이름은 붙이지 않는다.
- 시말서·품의서에는 회사명과 실명을 넣지 않고(닉네임만), "게임 결과 연출" 표시를 붙인다.
- "안 걸린다", "상사 몰래", "보안 우회" 같은 약속은 하지 않는다. 랜딩과 FAQ에 "회사 규정 확인은 본인 몫", "회사의 화면 모니터링은 피할 수 없음"을 적는다.

**공개 두 단계**: ① 베타: noindex와 베타 표시를 단 채 PM 지인 10~20명에게만 공개한다. 이 선 안에서는 추가 확인 없이 진행한다. ② 공개: 커뮤니티 게시와 검색 노출은 Q4 확인 뒤에만 한다.

**PM이 해 줄 일 (결정 아님)**: G0-2 회사망 접속 확인, 지인 10~20명 시딩, 플레이테스트 3쌍 모집.

# 부록 (실행팀용)

## A-1. 구조
- 라우트: `src/app/monthly-close/`(랜딩, 업종 선택, 박대리 연습), `src/app/monthly-close/[code]/`(방). 로직은 `src/lib/monthly-close/`. API는 `src/app/api/monthly-close/rooms/[code]/{join,place,fire,quiz,hint,alarm,tick,rematch,leave}`.
- **공유 파일(`layout.tsx`, `providers.tsx`, `globals.css`)은 수정하지 않는다.** 스타일은 라우트 범위 CSS로 한다. Q2 결과에 따라 슬러그가 바뀌면 폴더 이름만 바꾼다.
- 패턴은 /pae를 그대로 따른다. 익명 로그인(`signInAnonymously`), 모든 쓰기는 service_role 키를 쓰는 API 라우트에서만, 숨긴 정보는 RLS(행 단위 접근 규칙: 본인 행만 읽게 하는 DB 규칙)로 보호한다. `src/lib/pae/{supabase,supabase-admin,auth}.ts`는 **수정하지 말고 가져다 쓴다**(같은 프로젝트, 같은 익명 세션).
- 환경변수: 새 키 없음. `NEXT_PUBLIC_SUPABASE_URL`은 라이브 번들에 들어 있음 [확인]. `NEXT_PUBLIC_SUPABASE_ANON_KEY`와 `SUPABASE_SERVICE_ROLE_KEY`도 /pae가 쓰므로 등록돼 있을 것으로 본다 [추정]. 따라서 deploy.yaml의 env 드리프트 체크는 통과할 것으로 예상한다.
- 판정 엔진은 순수 TS(`engine.ts`)로 만들고 브라우저와 서버가 함께 쓴다. 단, 상대 배치는 서버에만 있다.

## A-2. 테이블 (`supabase/monthly-close-schema.sql`, 여러 번 실행해도 안전하게, 기존 테이블은 건드리지 않음)

| `mc_players` | room_code, uid, nickname(8자, 금칙어), seat, industry, last_seen, view_state(`game`/`disguise`) | 누구나 |
| `mc_boards` | room_code, uid, ships | **본인만** |
| `mc_secrets` | room_code, 퀴즈 정답, 경보 예정 라운드 | 없음(서버만) |
| `mc_matches` | id, room_code, players, started/ended_at, result, rounds, hints, alarm_on, alarm_outcome, rematch_of | 없음(서버만, 측정용) |

- 입장 시도는 방 번호 대입을 막기 위해 IP·uid당 횟수를 제한한다.

## A-3. 상태와 판정 세부
- 상태 갱신은 /pae `useRoom.ts` 구조를 그대로 쓴다. 액션 응답에 최신 공개 상태를 담아 즉시 반영하고, 2~3초마다 tick(접속 신호 + 기한 처리: 시간 초과, 퀴즈 마감, 경보 판정)을 보낸다. Realtime 신호를 놓칠 때를 대비해 1초 폴링을 둔다. 기한 처리를 tick이 맡으므로 cron은 필요 없다.
- 중복 발사 방지: (방, 라운드, 자리) 조합으로 유일성을 걸고, 상태 버전 번호를 비교한 뒤 저장한다.
- 시계: 서버 시각 기준. 차례인 사람의 view_state가 `disguise`이면 그 사람의 기한을 멈추고, 판당 누적 120초까지만 허용한다.
- 퀴즈: 4·8·12라운드 시작 시점에 두 사람 모두 view_state=`game`이고 last_seen이 3초 이내면 낸다. 조건이 안 맞으면 다음 라운드로 미룬다. 마감 시각은 두 브라우저의 "표시됨" 응답을 받은 시점 + 10초다. 2초 안에 응답이 없으면 서버가 낸 시각 + 1초를 기준으로 삼는다. 정답은 공개 상태에 넣지 않는다. 오답 잠금 정보는 본인에게 가는 응답에만 담는다. 먼저 맞힌 사람은 서버 수신 시각으로 정하고, 0.2초 이내면 둘 다 지급한다.
- 힌트 값: 범위 안의 배 칸 수(이미 맞힌 칸 포함). 수식 문자열에는 게임 용어를 쓰지 않는다(`"배"` 대신 `">0"`). 사용 후 수식 입력줄은 비운다.
- 결재 경보: 6~15라운드 중 서버가 무작위로 1회 정한다. 조건은 퀴즈와 같고, 퀴즈가 진행 중일 때는 띄우지 않는다. 각 브라우저는 "배너가 뜬 시각 → 위장으로 전환한 시각"(ms)을 보내고, 서버는 3초 이내인지만 판단한다. 경보 당시 접속이 끊겨 있던 사람(last_seen > 3초)은 벌칙에서 뺀다. 실패하면 다음 발사 1회를 넘기고, 시말서 변형 문구에 반영한다.
- 부재: 3번 연속 시간을 넘기면 상대에게 "부재 처리(기권승)" 버튼이 생긴다.
- 휴대폰: ESC 대신 "숨기기" 버튼을 둔다. 경보 판정도 같은 기준이다.

## A-4. 박대리와 2분 연습 (각본)
- 서버를 쓰지 않는다. 지표에서도 빠진다. 같은 엔진을 쓰되 박대리의 배치와 발사 순서는 고정한다.
- 1척이 이미 침몰한 상태에서 시작해 최대 8라운드 안에 끝낸다. 2라운드에 퀴즈 1회, 4라운드에 결재 경보 1회(연습이라 벌칙은 없고 안내만), 박대리의 도발 2회. 끝나면 결과와 상관없이 "연습 결산" 문서와 시말서·품의서 미리보기를 보여 준다.
- 마지막 화면에는 "동료 초대(방 만들기)" 버튼을 둔다.

## A-5. 화면 지침 (디자인팀용)
- 칸 모양: 데스크톱은 시트처럼 가로로 긴 칸(약 64×24px 안팎), 휴대폰은 터치하기 좋은 정사각형에 가까운 칸.
- 판 바깥에도 빈 셀이 이어지게 하고, 머리행 고정과 상태줄("준비" / "계산 중..." / "다른 사용자가 편집 중")을 둔다. 서버를 기다리는 동안 "계산 중..."을 보여 주면 대기 시간도 위장이 된다.
- 100ms 이상의 움직임, 깜빡임, 흔들림, 굵고 큰 빨간 글씨는 금지. 배 이름은 배치 패널에서만 길게 쓰고, 판 위에는 2~3자 약어만 쓴다. 승패가 나는 순간 화면 전체를 쓰는 연출도 금지.
- 웃음 문구는 셀 메모(마우스를 올리면 보임)와 상태줄에만 둔다. ESC 시트에는 웃음 문구를 하나도 넣지 않는다.
- 탭 제목은 업종별 파일명으로 고정. 파비콘은 중립적인 격자 모양. 링크 미리보기 이미지는 파일명 + "공유된 문서입니다".
- ESC 시트: 30행×10열, 소계와 합계가 실제로 맞을 것, 막대 차트 1개. 클릭, 방향키, 입력, SUM 재계산이 동작하고, Ctrl+S를 누르면 "저장됨" 토스트가 1~2초 뜬다. 움직이는 칸은 원래 움직이는 것(현재 시각, 마지막 저장 시각)뿐이다.
- 업종 단어가 열 너비를 넘치면 바로 티가 나므로 넘치지 않게 한다.
- 결재 경보 배너는 평범한 알림 토스트 모양에 "[ESC]" 단축키 표시를 붙인다. 소리나 깜빡임은 없다.

## A-6. 문구 묶음 (업종 JSON 1개)
- 들어갈 것: 파일명, 시트 탭 이름, 배 이름 후보(길이별 3개), 명중·빗나감·침몰 메모, 퀴즈 라벨 20개 이상, 결과 문서 변형, 도발 문구, ESC 시트 데이터 생성 규칙.
- 출발점은 창의 R2 §8의 초안. 지켜야 할 기준은 비평 R2 §3-3의 금지 목록(성별·나이·외모·지역·고용형태 비하, 직군 고정관념, 실존 기업·인물, 상대 지목 모욕 금지)과 검수 4규칙.
- 한 판 안에서는 같은 문구를 다시 쓰지 않고, 최근 3판 안에서도 가능하면 피한다(브라우저에 기록).
- 도발 문구에는 상대 이름을 넣지 않고, "당신은~" 식의 2인칭 비난을 쓰지 않는다.
- 퀴즈 숫자는 급여나 인사 정보처럼 보이지 않게 한다. 라벨이 정답을 헷갈리게 해서는 안 된다.

## A-7. 테스트 기준 (QA)
- 엔진 단위 테스트: 배치 검증, 판정, 라운드·무승부·상한, 힌트 계산, 퀴즈 생성과 채점, 경보 판정, 시계 정지 누적.
- 시뮬: 1만 판, G0-3 기준. 힌트 0개인 판과 힌트 효과도 포함.
- 보안: 상대 배치와 퀴즈 정답이 네트워크 응답, Realtime 메시지, HTML 어디에도 나오지 않을 것.

- **배포 후 검증**: 페이지가 200으로 열리는지에 더해 **방 만들기 API를 실제로 호출해 성공하는지** 확인한다. 같은 Supabase를 쓰는 /pae와 /dongne에도 같은 확인을 붙일 것을 배포엔지니어에게 권고한다(별건 참고).
