## 0. PM용 요약

### 0-1. 결론

**Go. 바로 디자인 단계로 넘어가도 된다.** 세 팀장 모두 "만들 수 있다"고 판단했다. PM이 정한 것(이름 "월마감", 8×8·3척·2척 침몰 승리, Tab 숨기기, 결재 경보 벌칙, 검산 퀴즈 규칙, 업종 3종, 무료 Supabase)은 하나도 바꾸지 않았다. Supabase도 다시 켜졌다(싱가포르, 정상). 그래서 새 프로젝트를 만들 필요가 없고, /pae·/dongne와 같은 프로젝트를 그대로 쓴다.

이번 회의에서는 "어떻게 만들지"를 정했다. 큰 결정은 세 가지다.

1. **숨기기는 한 방향이다.** Tab(또는 ESC)은 몇 번을 눌러도 숨기만 한다. 게임으로 돌아올 때는 화면 아래 시트 탭을 클릭한다. 허둥대며 Tab을 두 번 눌렀을 때 게임이 다시 튀어나오는 사고를 막기 위해서다.
2. **판 두 개는 "창 나누기" 모양으로 둔다.** 왼쪽 창이 내 시트, 오른쪽 창이 상대 시트다. 창마다 A, B, C… 머리글이 따로 있어서 두 판 모두 "B7"로 부를 수 있다.
3. **게임은 우리 서버(Vercel) 하나만 거친다.** 판정과 기록은 전부 Vercel 쪽 서버가 맡는다. Supabase는 보관함과 "바뀌었어요" 알림만 맡는다. 그래서 회사망에서 supabase.co가 막혀도 vercel.app만 열리면 게임이 된다.

## 1. 지정 쟁점 결정

### 1-0. 결정 표

| # | 쟁점 | 팀장 의견 | **결정** | 이유 |
|---|---|---|---|---|
| 1 | 판 두 개의 좌표 머리글 | 디자인: 분할 창 2개, 창마다 A1:H8 / 프론트: (가) 판마다 A~H 머리글을 단 두 칸 화면(추천), (나) 큰 판 + 작은 참조 창 | **분할 창 2개.** 왼쪽은 "내 시트", 오른쪽은 "상대 시트"다. 창마다 열 머리글(A, B, C…)과 행 번호(1, 2, 3…)를 따로 둔다. 판은 각 창의 A1:H8이고, 판 바깥의 빈 셀은 오른쪽(I열부터)과 아래(9행부터)로만 이어진다. (나)는 채택하지 않는다 | 디자인안과 프론트 (가)는 같은 안이다. 실제 시트 앱의 "창 나누기"와 모양이 같아서 위장에도 맞다. (나)를 쓰면 내 판이 작아져 상대가 쏜 곳을 읽기 어렵고 좌우 대칭이 깨진다 |
| 2 | 숨기기 복귀 방식 | 디자인·프론트 모두 "한 방향 + 시트 탭 클릭으로만 복귀" | **채택.** Shift+Tab도 숨긴다. 숨기기 시트 안에서 Tab은 다음 칸, ESC는 편집 취소다. 홈(랜딩)에는 숨기기를 적용하지 않는다. 세부는 §5-4 | 토글 방식이면 허둥대며 두 번 눌렀을 때 게임이 다시 뜬다. 숨기기 시트에서 Tab이 "다음 칸"으로 동작해야 진짜 시트처럼 보인다 |
| 3a | 힌트 보유형 | 디자인: 보유형, 내 차례에 [Σ]로 사용, 턴은 쓰지 않고 시계는 계속 흐름 | **보유형 채택, 쓸 수 있는 때는 넓힌다.** 대전 중 언제든 쓸 수 있다(상대 차례 포함). 단 검산 진행 중, 결재 경보 중, 숨기기 중에는 못 쓴다. 쓰면 발사 턴이 줄지 않고 시계도 멈추지 않는다. 기획서의 "1인 최대 2개"는 **판당 받은 개수**(이미 쓴 것 포함)로 센다 | 내 차례에만 쓰게 하면 20초 안에 범위를 고르고 쏘기까지 해야 해서 쫓긴다. 상대 차례에 쓰게 해도 얻는 정보는 같다. 지금 "가지고 있는 개수"로 세면 쓰고 또 받는 식으로 한도가 의미를 잃는다 |

## 3. 게임 규칙 보완과 공용 상수

기획서 §3·§4 규칙에 아래를 더한다(§1·§2 결정 반영).

**한 라운드의 순서**: 라운드 시작 → (4·8·12라운드이고 출제 조건을 충족하면) 검산 → 검산 확정 → 선공 발사(20초) → 후공 발사(20초) → 승패 판정 → 다음 라운드. 결재 경보는 6~15라운드 중 한 번, 검산이 열려 있지 않은 때에 낸다.

- **출제 조건**(검산·경보 공통): 두 사람 모두 `view_state = game`이고 `last_seen`이 6초 이내. 조건이 안 맞으면 다음 라운드로 미룬다.
- **숨기기와 시계**: 차례인 사람이 숨어 있는 동안 발사 시계가 멈추고, 판당 누적 120초까지 허용한다. 경보 때문에 숨은 시간도 여기에 포함된다.
- **경보 판정**: 브라우저가 "토스트 표시 → 위장 전환"까지 걸린 ms를 보고하고, 서버는 3,000ms 이하인지만 본다. 경보 직전에 이미 숨어 있었다면 0ms로 통과다. 토스트 클릭도 숨기기로 인정한다. 실패하면 다음 발사를 1회 자동으로 넘긴다.
- **도발**: 내가 도발을 보낸 라운드 + 3라운드부터 다시 보낼 수 있다. 서버가 강제한다.
- **부재·나가기**: 3번 연속 시간을 넘기면 상대에게 "부재 처리" 버튼이 생긴다(완주로 세지 않음). 대전 중 "나가기"는 확인 창을 띄운 뒤 기권 처리한다.
- **판 종료**: 상대 배치를 공개하고, 결과 탭(시말서·포상 품의서·공동 경위서)을 연다. 재대결은 두 사람이 2분 안에 모두 [v8로 저장]을 누르면 같은 방에서 판 순번을 1 올린다.

## 4. 확정 아키텍처

### 4-1. 구조도

```
 [브라우저 A]                                       [브라우저 B]
   localStorage: mc:key(비밀키), mc:test(테스트 표시), 업종·닉네임·최근 문서
   │                                                     │
   ├─ HTTPS ─► Vercel 함수 /api/monthly-close/* (sin1) ◄─ HTTPS ─┤   ← 핵심 경로: vercel.app 하나만 열리면 동작
   │           판정·상태 전이·시계·검증·투영(보는 사람별 화면 데이터)  │
   │                 │ service key            │ httpSend {v}       │
   │                 ▼                        ▼                    │
   │       Supabase Postgres (싱가포르)   Supabase Realtime Broadcast│
   │       mc_rooms / mc_players          주제 "mc:<방 UUID>"       │
   │       mc_matches / mc_events               │                  │
   │       (RLS 켜짐 + 정책 0 + 권한 회수)       │                  │
   └────── WebSocket(선택, anon key) ◄──────────┴──► WebSocket(선택) ┘

 [박대리 연습]  브라우저 안에서 engine만 실행. 서버·DB를 쓰지 않고 지표에서도 빠진다.
```

- **지역**: Vercel 함수는 `sin1`[확인: `vercel.json`], Supabase는 Southeast Asia (Singapore)[확인: 진행자]다. 액션 1회는 약 120~180ms로 본다[추정: 백엔드 §3]. 백엔드가 서울 지역에 대비해 준비한 RPC 최적화는 필요 없다.
- **책임**: Vercel API는 모든 상태 전이, 기한 처리, 투영, 지표 기록을 맡는다. Supabase는 단일 원본 저장, 버전 비교 저장, 초인종을 맡는다(게임 규칙을 plpgsql로 넣지 않음). 브라우저는 그리기, 입력, 위장 전환(서버를 기다리지 않음), 경보 반응 ms 측정(신뢰함), 카운트다운 표시를 맡는다.

### 4-2. 상태·동시성·시계 (백엔드 §4를 그대로 따름, 요점)

- `mc_rooms.state`(JSON) 한 덩어리에 공개 부분과 비밀 부분(`secret.boards`, `secret.quiz`, `secret.alarmRound`)을 함께 둔다. 브라우저는 이 행을 직접 읽지 못한다.
- 저장은 `version` 비교 후 UPDATE하고, 실패하면 최대 3회 다시 시도한다. 액션마다 `actionId`를 붙여 중복을 없앤다. 접속 신호(`last_seen`, `view_state`)는 `mc_players`에 따로 둔다.
- **서버 시각 하나**를 기준으로 하고, 기한은 절대 시각(ms)으로 저장한다. 모든 응답에 `serverNow`를 넣는다. 브라우저는 시각 차이를 보정해 카운트다운에만 쓴다.
- 기한 처리에 cron은 쓰지 않는다. 요청이 들어오면 지난 기한부터 처리하되, 한 요청에서 시간 초과는 최대 1회만 처리한다. 누구의 요청이든 처리하고, 버전 비교로 중복을 막는다.
- 투영 함수 `viewFor(state, seat)`는 **허용 목록 방식으로 새 객체를 만든다**(원본을 복사한 뒤 비밀을 지우는 방식은 금지). 방 페이지는 상태를 서버에서 미리 그리지 않는다(SSR 금지).

### 4-3. API (라우트 파일 6개, `src/app/api/monthly-close/`, 모두 nodejs 런타임·캐시 금지)

| # | 경로 | 하는 일 |
|---|---|---|
| 1 | `POST rooms` | 방 만들기(닉네임, 업종 번호 0~2, 경보 켬 여부). 만료된 방 정리도 여기서 함께 한다 |
| 2 | `POST rooms/[code]/join` | 입장과 재입장(같은 비밀키면 원래 자리) |
| 3 | `POST rooms/[code]/sync` | 접속 신호, `view_state` 보고, 경보 반응 ms, 지난 기한 처리. 바뀐 게 없으면 `{version, serverNow}`만 돌려준다 |
| 4 | `POST rooms/[code]/action` | `type` = `place` / `fire` / `answer` / `hint` / `taunt` / `rematch` / `resign` / `claimAbsent` / `leave` |
| 5 | `POST feedback` | 피식 응답, 문구 신고, `lines_shown`, `share_copied`, `transport` |
| 6 | `GET health` | `{db: "ok" \| "down"}`(비밀 없음) |

- **숨기기·복귀 보고는 즉시 `sync`로 보낸다**(`fetch keepalive`). 화면 전환은 이 요청을 기다리지 않는다.
- **오류 코드**: `ROOM_NOT_FOUND`, `ROOM_FULL`, `NOT_YOUR_TURN`, `WRONG_PHASE`, `LOCKED`, `INVALID`, `CONFLICT`(3회 재시도 후에도 실패), `RATE_LIMITED`, `SERVICE_DOWN`(503). 자리가 있는 사람에게는 거부 응답에도 최신 화면 데이터를 함께 담는다. 서버는 한국어 문장을 보내지 않고 코드와 숫자만 보낸다.

### 4-4. 화면 데이터 계약 (`protocol.ts`, D0 동결)

백엔드 §5의 "화면 데이터 초안"을 바탕으로, 아래를 더하거나 고친다.

- `room`: 방 번호, 상태(`waiting` / `placing` / `playing` / `ended`), `version`, 경보 설정, 판 순번(v7, v8…), **이 문서의 전적**(자리별 승 수·무승부 수), `serverNow`, **초인종 주제**(참가자에게만)
- `me`: 자리, 닉네임, 업종 번호, 내 배, 배치 완료 여부, 숨기기 남은 예산, **받은 힌트 수·쓸 수 있는 힌트 수**, 내가 쓴 힌트(종류·범위·값), 검산 잠금 해제 시각, 다음 발사 쉼 여부, **다음 도발 가능 라운드**
- `opp`: 자리, 닉네임, 업종 번호, 접속 여부, 숨기기 중인지(시계가 멈춘 이유 표시용), 배치 완료 여부
- `game`: 라운드, 단계(`quiz` / `fire`), 차례, 기한, 내가 쏜 칸 결과, 상대가 쏜 칸 결과, 침몰 목록(**길이 슬롯과 칸만**, 배 이름은 보내지 않음), 마지막 사건 코드, 변경 내역(힌트 범위, 도발 문구 id), 검산(id, **종류**, 숫자, `labelSeed`, 내 마감, 상태, `settleAt`, 받은 자리), 경보(진행 중 여부, 출제 시각), 결과(승자/무승부, 끝난 이유), **종료 후 공개(`ended`일 때만 상대 배치)**, 재대결 신청 현황
- **절대 넣지 않는 것**: 대전 중 상대 배 위치, 검산 정답, 경보 예정 라운드, 상대 힌트 값, 상대 오답·잠금, 비밀키와 그 해시

### 4-5. DB (`supabase/monthly-close-schema.sql`)

백엔드 §6을 그대로 따른다. 테이블은 `mc_rooms` / `mc_players` / `mc_matches` / `mc_events` 4개이고, 원칙은 다음과 같다.
- `create … if not exists`만 쓰고 전체를 한 트랜잭션으로 묶는다. `drop`은 넣지 않는다(지우기는 별도 `monthly-close-teardown.sql`).
- RLS를 켜고 정책은 0개, `anon`·`authenticated` 권한은 회수한다. Realtime 발행 목록에 테이블을 넣지 않는다.
- 스크립트 끝에 PM이 눈으로 확인할 SELECT 1개를 둔다. 게이트 판정용 쿼리는 `monthly-close-gate.sql`(SELECT만)로 따로 둔다.
- 정리는 방을 만들 때마다 한다(만료 방 최대 50개, 90일 지난 매치·이벤트 최대 500행). IP·User-Agent·닉네임은 매치·이벤트 기록에 남기지 않는다.

### 4-6. 저장소와 환경

- `RoomStore` 인터페이스 하나에 구현을 두 벌 둔다. `SupabaseStore`는 운영용, `MemoryStore`는 로컬 개발·테스트·프리뷰 스크린샷용이다(조건 4). `.env.local`에는 Supabase 키가 없다[확인: 키 이름만 확인].
- 환경변수는 기존 `NEXT_PUBLIC_SUPABASE_URL`, `NEXT_PUBLIC_SUPABASE_ANON_KEY`(초인종 구독용), `SUPABASE_SERVICE_ROLE_KEY`(서버 전용)와 Vercel이 자동으로 넣는 `VERCEL_ENV`만 쓴다. **새 키는 0개다.** `SUPABASE_SERVICE_ROLE_KEY`는 `server/` 안에서만 읽는다.
- Supabase가 멈추면 health가 `down`이 되고, 홈에 "공유 서버에 연결할 수 없습니다. 연습은 가능합니다"를 띄운다. 연습은 서버 없이 늘 동작한다. /pae처럼 몰래 봇 데모로 바꾸지는 않는다.

### 4-7. 클라이언트 (프론트 §2~§4를 따르되 아래로 확정)

- `useMcRoom`은 /pae `useRoom.ts`의 패턴만 본뜬다(파일은 import하지 않음). 액션 응답의 화면 데이터를 바로 반영하고, `version`이 더 클 때만 setState한다. 화면이 사라질 때 자동으로 나가는 처리는 없다. 탭이 다시 보이면 즉시 sync한다.
- `RoomController` 인터페이스 하나를 실전(`useMcRoom`)과 연습(`usePracticeRoom`)이 같이 쓴다. 화면 코드는 한 벌만 짠다.
- 숨기기는 `viewStore`(외부 저장소)와 `.mc-shell[data-view]` 속성을 바로 바꾸는 방식으로 처리하고, React 렌더링을 기다리지 않는다. 게임 레이어와 숨기기 레이어를 둘 다 미리 마운트해 둔다. 위장 숫자는 방·사용자별 seed로 한 번만 만든다.
- 숨기기 전환 시간은 `performance.measure('mc-hide')`로 남긴다. 목표는 p95 50ms 이하, 기준은 100ms다.
- 의존성은 새로 추가하지 않는다(Next 14.2.3, React 18, supabase-js 2.109.0, zod, fast-check, Testing Library 모두 설치되어 있음 [확인: `package.json`]). React Query는 쓰지 않는다.

### 5-3. 단계별 상태

`lead-design.md` §1-4 표를 그대로 채택하고, 다음만 고친다.
- 검산 요청: 오른쪽 창 10~14행에 뜨는 동안 발사 시계가 멈췄다는 것을 상태줄에 보인다("계산 중..."은 서버 대기 전용이므로 쓰지 않고, "검산 요청 1건 · 00:07"로 쓴다). 확정은 **Enter만** 받는다.
- 힌트 사용: [Σ] 또는 상태줄 안내로 연다. 대전 중이면 내 차례가 아니어도 열 수 있고, 검산·경보·숨기기 중에는 비활성이다.
- 끝: 결과 탭이 추가되면서 상대 시트의 판에 공개된 항목이 회색 빗금으로 남는다.

### 5-4. 숨기기 동작 표 (확정)

| 화면 | Tab / Shift+Tab | ESC | 창 이탈(`blur`·`visibilitychange` hidden·`pagehide`) | 복귀 |
|---|---|---|---|---|
| 홈 | 표준(포커스 이동) | 동작 없음 | 동작 없음 | — |
| 입장 대화상자 | 표준(입력 칸 이동) | 숨기기 | 숨기기 | 게임 시트 탭 클릭 |
| 시트(대기·배치·대전·결과)·연습 | **숨기기**(이름 상자, 검산 칸, 드롭다운, 한글 조합 중에도 무조건) | 숨기기 | 숨기기 | 게임 시트 탭 클릭 |
| 숨기기 시트 | 다음 칸 / 이전 칸 | 편집 취소 | 그대로 숨김 | 게임 시트 탭 클릭 |

- Ctrl·Alt·Cmd가 함께 눌린 Tab과 ESC는 무시한다. 창을 벗어나면 자동으로 숨는다. **돌아와도 숨긴 상태를 유지한다**(PM 확인 1의 추천안).
- 경보 토스트 클릭과 숨기기·장식 시트 탭 클릭도 숨기기다(경보 판정에 인정).
- Ctrl/Cmd+S는 두 화면 모두에서 가로채 "저장됨" 토스트를 1~2초 띄운다.
- 우리가 직접 연 공유 시트(`navigator.share`) 때문에 창을 벗어나는 경우는 한 번 예외로 둔다.
- 숨는 순간 같은 프레임에 지울 것은 `lead-design.md` §3-6 목록을 따른다. 탭 제목과 상단바는 그대로 둔다.
- 이름 상자는 두벌식 자모를 A~H로 바꿔 받는다(ㅁ ㅠ ㅊ ㅇ ㄷ ㄹ ㅎ ㅗ). 소문자도 받는다. 검산 칸은 `inputMode="numeric"`이다.
- 게임 화면에서는 Tab으로 포커스를 옮길 수 없으므로, 방향키·Enter·마우스로 모든 조작이 가능해야 한다. 셀에는 `aria-label`을 단다. 이는 MVP에서 받아들이는 접근성 제약이고, 홈에 고지한다.

### 5-5. 휴대폰

`lead-design.md` §5 표를 기본으로 하고 §2-A·H·I 결정을 반영한다. 정리하면 이렇다.
- 1024px 미만이면 창 1개 + 시트 탭 전환([내 시트] [상대 시트] │ [숨기기 탭])이다. 내 차례가 오면 [상대 시트]로만 자동 전환한다.
- 메모는 시트 탭 위 "메모 줄"에 띄운다. 숨기기는 숨기기 탭을 탭하거나 경보 토스트를 탭하면 되고, 앱을 전환하거나 화면을 잠가도 자동으로 숨는다. 배치에서 끌어다 놓기는 만들지 않고 "자동 배치"를 크게 둔다.
- 목표는 "공유받은 링크를 폰으로 열었을 때 막히지 않는 수준"이다.

### 5-6. 화면 용어

`lead-design.md` §1-6 용어 사전을 그대로 채택한다(방 → 문서, 배 → 항목, 쏘기 → 검토·반영, 명중/빗나감/침몰 → 반려/해당 없음/종결, 퀴즈/힌트 → 검산 요청/검토 의견, 도발 → 의견 남기기, 숨기기 → 시트 전환, 재대결 → v8로 저장). 게임 화면에는 게임 용어를 쓰지 않는다. 홈 안내와 연습 코치만 예외다.

**개발 완료 기준 (D3)**
1. `npm run type-check`, 클린 `npm run build`(`.next` 삭제 후), `npm run test`가 모두 통과한다.
2. 로컬 `MemoryStore`로 두 브라우저(일반 창 + 시크릿 창) 한 판을 끝까지 둔다. 배치 → 대전 → 검산(오답 잠금 포함) → 힌트 3종 → 경보(통과·실패) → 결과·상대 배 공개 → v8 재대결, 그리고 새로고침 복원까지.
3. 박대리 연습이 서버 없이 끝까지 돌고, 마지막 화면에 "동료 초대" 버튼이 있다.
4. 1만 판 시뮬이 G0-3 기준을 통과한다(힌트 없는 판과 힌트 효과 포함).
5. 숨기기 전환이 로컬 Chrome에서 p95 50ms 이하로 측정된다.
6. 투영 속성 테스트(무작위 판 1,000개)에서 유출이 0건이다.
7. §8-2 누수 표를 자체 점검했고, 공유 파일 diff가 0이다.

**배포 순서와 완료 기준 (STEP 7, `teams/workflows/deploy.yaml` + 아래)**
1. 사전 확인: 슬러그 `monthly-close`가 예약어가 아니고 기존 경로와 겹치지 않는다 [확인]. 인덱스에 staged된 flight 45개를 섞지 않도록, 커밋할 내용만 꺼낸 **git worktree**에서 게이트를 돌린다.
2. 로컬 게이트: `node -v`가 `.nvmrc`(22)와 같은지, `npm ci`, type-check, 클린 빌드, 테스트.
